# BThwani Unified Surface UI

## Overview

### Creative North Star

The product reads as a calm operational control room: warm neutral work surfaces carry dense information, navy establishes trusted structure, and orange marks the next governed action. The same vocabulary serves customer, partner, captain, field, and operator views while each surface keeps its own information density.

### Product context and register

- **Audience and primary job:** Customers discover and purchase; partners operate stores and orders; captains execute delivery; field workers complete onboarding and readiness; operators govern the platform. These surfaces are defined by `governance/product/PRD.md`.
- **Target market(s) and evidence:** Arabic-first Yemen-facing product evidence is in `governance/product/PRD.md`; English remains a supported technical and mixed-script presentation lane.
- **Locale(s) and language policy:** Arabic and English are supported. The web control panel defaults to Arabic/RTL and marks Latin identifiers, codes, and technical values with the Latin font lane. Shared locale and direction primitives are in `shared/ui-kit/src/locale` and `shared/ui-kit/src/foundation.ts`.
- **Usage scene:** Frequent mobile and web workflows with high operational urgency, dense data, weak-network recovery, and mixed Arabic/numeric identifiers.
- **Register:** Product UI on mobile and web application surfaces; focused control-room UI for operators.
- **Memorable signature:** Warm surface layers, navy structural chrome, and orange action emphasis.
- **Restraint:** Familiar controls, native keyboard behavior where explicitly accepted, truthful state panels, and no decorative state that could be mistaken for backend truth.
- **Anti-references:** No generic dark dashboard, neon-only palette, fake live indicators, local financial truth, or decorative gradients that compete with action hierarchy.
- **Token ownership/runtime mapping:** `shared/ui-kit/src/tokens` and `shared/ui-kit/src/foundation.ts` are the cross-surface runtime token owners. `apps/control-panel/runtime/src/styles/cp-css-vars.ts` is a control-panel chrome composition layer derived from those values, not a second foundation. Drift is checked by `pnpm guard:ui-kit-boundary` and `pnpm visual:ui-kit:contract`.

## Colors

The shared semantic palette uses `#0A2F5C` for trusted structure and primary text, `#FF500D` for governed actions, and warm surfaces from `#FFFCF8` to `#FFFFFF`. Semantic success, warning, danger, info, border, and focus roles come from `shared/ui-kit/src/tokens/colors.ts`. Light, dark, and high-contrast theme outputs are generated by `shared/ui-kit/src/foundation.ts`; surface-local aliases must be derived from that output.

## Typography

Arabic is the default reading lane and uses the Cairo font loaded by the control-panel runtime, with system fallbacks. Latin identifiers and technical values use the Inter lane on the web control panel and the shared system/mono roles elsewhere. Typography roles, weights, line heights, and code sizing are owned by `shared/ui-kit/src/tokens/typography.ts`. Text remains sentence case in Arabic and does not force uppercase on user content.

## Layout

The shared spacing scale is based on 4px steps. Web pages use responsive content widths up to 1120px; control-panel chrome uses an explicit top bar, navigation rail, main work surface, optional inspector, and status bar. Mobile surfaces use safe-area-aware scroll containers and bounded action regions. RTL is expressed with logical properties and direction context rather than mirrored coordinate literals.

## Elevation & Depth

Hierarchy comes first from surface tone and borders, then restrained shadows. The control panel may use appearance-driven glass for top chrome when the selected appearance mode requires it. Blur is not used for essential content readability, and financial or operational truth is never represented by elevation alone.

## Shapes

Cards and fields use the shared 8/12/16px radius roles; pills use the round role. Dividers are semantic border tokens. Icon containers remain compact and optically aligned; text labels remain present when an icon alone would be ambiguous.

## Components

### Foundational visual states

Every interactive control has default, hover where applicable, visible keyboard focus, active/pressed, selected, disabled, busy, and error behavior. Loading, empty, offline, forbidden, partial, and recovery states are rendered through the shared `StateView`/surface state owners or the surface's documented adapter. Reduced motion is a root-level accessibility contract.

### Buttons and actions

`shared/ui-kit/src/components/Button` owns mobile/native button behavior and web consumers use the web action owners. Primary action uses orange, structural navigation uses navy, destructive action uses danger, and busy state preserves geometry while preventing duplicate submission. Icon-only actions require an accessible label.

### Navigation and data display

Navigation labels remain visible in expanded rails and receive an accessible current marker. Tables and grids use the shared data-table owner; selection scope and pagination are explicit. Dense control-panel tabs may scroll horizontally, but the scroll surface has a keyboard-visible focus path and does not suppress the global scrollbar baseline.

### Forms and overlays

Application forms declare their validation owner with `noValidate` and implement the canonical controller/schema contract. Native select and date/time controls are accepted for web control-panel fields because they preserve keyboard and platform semantics; they are not silently mixed with an authored combobox. Textareas have bounded, intentional resize behavior. Dialogs and sheets use the shared owners and keep focus/recovery semantics explicit.

### Iconography

The shared icon owner is Ionicons through `shared/ui-kit/src/components/Icon`. Icons use the outline/filled state appropriate to inactive/active navigation, inherit semantic tone, and never replace a required text label. The icon contract is verified by `pnpm guard:icon-contract`.

### Motion

Motion uses the shared 120/180/240/320ms duration roles and standard/enter/exit easing. It communicates state changes, not routine decoration. The root stylesheet reduces animation and transition duration when `prefers-reduced-motion: reduce` is active.

### Content and data visualization

Copy is Arabic-first, explicit about service/data state, and avoids claiming health or success without runtime evidence. Numeric and technical values retain readable Latin formatting where required. Analytics identify freshness and source ownership; financial figures are readbacks of WLT-owned truth or an explicitly governed projection.

## Do's and Don'ts

- **Do:** Derive cross-surface color, spacing, typography, motion, direction, and component states from `shared/ui-kit`.
- **Do:** Keep UI truthful to the canonical Product Truth and show loading, empty, offline, forbidden, conflict, and error states explicitly.
- **Don't:** Reintroduce legacy CSS aliases, local token foundations, fake status signals, or surface-local business truth.
- **Don't:** Remove keyboard focus, hide meaningful scroll affordances, or use visual polish to bypass authorization, validation, or readback.

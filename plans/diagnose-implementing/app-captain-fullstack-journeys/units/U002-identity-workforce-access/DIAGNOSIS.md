# U002 — Identity, Workforce and access

The current Captain access path is already layered, but the closure evidence required by that layering is deeper than the previous package described. Native `App.tsx` configures SecureStore-backed Identity session storage and a device fingerprint provider, then requires an authenticated Captain session before entering Workforce and DSH. The current Identity policy authorizes a role-owned surface only when authentication is valid, `sessionSurface` equals `app-captain`, `surfaceAccess[app-captain]` is true, the role maps to that surface, and the identity actually contains role `captain`.

Refresh is also a governed concurrency problem now. `GovernedRefreshBoundary` delegates refresh rotation to the Identity repository/database layer; concurrent reuse of a token already rotated returns `REFRESH_ALREADY_ROTATED`, invalid/expired refresh returns `INVALID_REFRESH_TOKEN`, and service errors remain unavailable rather than silently extending a session. This must be verified together with client recovery so a racing refresh cannot create parallel valid state, leak another actor, or leave protected Captain data rendered under a stale session.

Workforce owns Captain provider readiness. The mobile provider flow directly reads `/workforce/me` and `/workforce/readiness/{actorId}` with the Identity bearer token, while DSH uses the service-authenticated internal `/internal/captains/{actorId}/readiness` boundary. The two transports must converge on the same Workforce person and readiness facts; the internal route must not become a human-bearer bypass. Missing profile, wrong workforce kind, suspended/terminated engagement, unavailable Workforce, actor mismatch and inconsistent readiness must all fail closed.

The root-cause risk is duplicated authorization/readiness semantics across Identity, app composition, Workforce and DSH. U002 therefore verifies ownership and convergence before editing. Any reproduced mismatch is fixed at the owner and all affected consumers are migrated. Cleanup includes removing any Captain-local readiness/session fallback or stale actor cache proven to bypass current truth. Physical-device restart/logout/relogin and actor-switch evidence remains required when native persistence/push behavior is changed or claimed closed.

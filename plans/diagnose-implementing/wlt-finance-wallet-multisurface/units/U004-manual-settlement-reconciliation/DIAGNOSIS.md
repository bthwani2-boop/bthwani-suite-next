# U004 Diagnosis — Official-Wallet Payout, Manual Settlement, Reconciliation and Close

Current BB already has useful payout/evidence/batch/close primitives, but key semantics remain wrong. `canonical_payout_destination.go` still defaults to bank and permits bank/mobile-money/manual; Product Truth requires verified official-wallet destinations and treats manual as execution method. `daily_close.go` totals legacy `wlt_ledger_entries` instead of canonical double-entry tables and explicitly proceeds after computing unverified evidence. Completion must require immutable approved payout snapshot + frozen batch row + manual execution evidence + authoritative external statement, with mismatch/duplicate/unknown states blocking through reconciliation. Sensitive official-wallet references must be versioned, encrypted/masked and operator-context scoped. Preserve legacy financial history read-only; do not restore automated cash-out or bank/IBAN semantics as a shortcut.

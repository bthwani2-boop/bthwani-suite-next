# U005 Diagnosis — Finance Control Center and Multi-Surface Binding

The current frontend is not empty; it is fragmented and partially aligned to obsolete backend semantics. The canonical control-panel route `/wlt/finance` exists and separate ledger, payment-session and COD inspectors exist. `services/dsh/frontend/control-panel/finance` contains the dashboard, payout, settlement, commission and reconciliation panels. `services/wlt/frontend/shared/dsh` already provides reusable actor-wallet, commission, field-finance, finance-boundary, finance and payment modules. This means the correct frontend strategy is reuse/merge around canonical WLT contracts, not a parallel redesign with local money calculations.

The finance dashboard must become one permission-aware operating workspace with clear sections for command center, internal wallets, Cash-In/payment sessions, captain COD, official-wallet destinations, payout requests, settlement batches/manual execution, reconciliation/exceptions, treasury, daily close, ledger/audit and provider health. Existing provider-payout actions such as “send to provider” must disappear from the current product flow. Policy administration must be separated from settlement execution, sensitive adjustments must use governed forms rather than browser prompts, and finance navigation/actions must reflect server permissions while never relying on UI hiding for security.

All five surfaces require canonical financial readback. Client gets funding/payment/wallet history; captain gets one-wallet balance, Cash-In, COD effect, earnings and eligible payout; partner/field get earnings/wallet, verified destination and payout history. No app should compute available/held/withdrawable truth locally or call a provider directly. DSH may compose operational context, but WLT remains the financial writer. Final verification must include mixed-version behavior, offline/reconnect, duplicate taps, stale reads, forbidden scope, runtime restart, unknown provider result and manual-settlement exception recovery, plus browser/mobile visual checks on the same candidate SHA.

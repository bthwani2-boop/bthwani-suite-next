# U002 diagnosis — discovery, catalog, store and special requests

The current repository already contains a canonical client catalog projection plus assortment/publication runtime truth, so the previous plan to create another projection is obsolete. The closure problem is convergence: store publication readiness, assortment membership, inventory/pricing availability, media/marketing visibility and policy must all produce one canonical client-visible set, and the app must read that set without local/demo category or product truth. Field/partner/control behavior enters only where it writes those publication facts.

Marketing/reels/media are in scope only as client-visible discovery inputs and destinations; every action target must resolve to a current canonical entity. Special requests remain a separate path but must use trusted identity, address/serviceability, idempotency and committed readback. No optimistic frontend success may create order-like truth. Verification must cover hidden/unpublished/unavailable content, concurrent publication changes, stale destinations and special-request duplicate/timeout paths. A mismatch is repaired at the earliest canonical owner, never by frontend filtering that masks backend divergence.

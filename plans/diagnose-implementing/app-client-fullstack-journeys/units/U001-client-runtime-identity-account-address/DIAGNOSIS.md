# U001 diagnosis — client runtime, Identity, account and address

Current source no longer supports the old assumption that refresh rotation is missing. Identity session storage now restores persisted state, validates it, serializes concurrent refresh attempts and handles already-rotated conflicts; app-client registers a pre-session-end hook that clears the persisted React Query cache and offline mutation queue. Those mechanisms are evidence to verify, not a second implementation to create. The current defects are at lifecycle/runtime boundaries. Actions evidence shows Identity readiness still expects `identity-021_actor_lifecycle_status.sql` while the governed migration set requires `identity-022_refresh_rotation_concurrency.sql`. DSH also fails `TestRequireActorRejectsSystemSurfaceForMobileRole` because the system-surface/mobile-role case returns 401 rather than required 403, leaving authentication versus authorization semantics inconsistent.

Implementation must converge Identity readiness on the active migration manifest, make mobile role/surface rejection deterministic without weakening authentication, and prove that logout, revoke, wrong role, wrong surface, actor change, restart and offline recovery cannot retain another actor's cached queries, queued mutations or push endpoint. Account/address work stays bounded to the customer's own profile, address, geofence and privacy truth. Address/serviceability remain server-owned; no local coordinate, cached eligibility or frontend fallback can authorize checkout. Native/LAN is development transport only and must not become product authorization or data truth.

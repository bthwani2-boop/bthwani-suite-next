# U001 diagnosis — runtime, Identity, account, profile, address and privacy

The independent re-audit found that U001 mixed valid enduring obligations with defects that were already superseded. On the current BB evidence SHA, the Identity backend/database job is green and the DSH `internal/http` package passes; therefore the earlier identity-021/022 readiness mismatch and the prior 401/403 test failure must not remain implementation instructions. The current DSH full-backend failure is a readiness mismatch whose latest migration is `dsh-999b_partner_evidence_lifecycle.sql`, so it is a project/shared-runtime blocker but not authority to import Partner evidence work into the client package.

The client account slice has a separate, currently visible defect that the old U001 missed. `MySpaceScreen` exposes the commercial-profile action through optional `onOpenProfile`, while `DshClientSurface` neither supplies that callback nor routes `MyProfileScreen`. The latter is not decorative: it owns client self-service preferences and consents with optimistic-concurrency versioning and also exposes data-copy and account-deletion affordances that are currently disabled. This means the package must explicitly own route reachability, profile OCC, consent persistence and authoritative disposition of privacy-right actions.

U001 therefore treats current session/auth behavior as a fresh regression obligation, preserves actor/cache/push isolation work, retains canonical address/service-area privacy work, and adds a fourth root-cause task for profile/consent/privacy-right reachability. It must not invent privacy policy, add a second session/profile truth, or fix unrelated Partner readiness. Every supported visible account action must lead to a governed implementation; unsupported actions must not masquerade as available functionality.

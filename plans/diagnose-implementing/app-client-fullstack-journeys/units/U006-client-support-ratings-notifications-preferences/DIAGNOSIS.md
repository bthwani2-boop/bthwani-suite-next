# U006 diagnosis — support, ratings, notifications and preferences

Support architecture changed materially since the prior package. The current shared client adapter targets the actor-generic `/dsh/support/tickets` API, a stronger shape because trusted session identity chooses the actor rather than a client path segment. The unit must forbid resurrection of retired `/dsh/client/support/...` aliases and verify owner scoping, internal-note redaction, mutation idempotency and support/rescue transitions. Other surfaces enter only when they write the same support/rescue/order state the client reads.

Ratings remain server-eligible and idempotent; rendering a prompt is never eligibility authority. Notifications are transport hints, not business truth: push registration/preferences must be actor-scoped and deep links must re-fetch/re-authorize their target. Session replacement must not retain another actor's endpoint or queued notification state. Preference writes must converge on canonical owner state across devices. Verification must force cross-actor ticket/rating access, duplicate support/rating mutation, stale notification, forbidden deep link, token replacement and logout/relogin as another actor.

# U007 diagnosis — benefits, loyalty, offers and subscriptions

The prior package omitted an entire client-facing commercial journey. `BenefitsHubScreen` is reachable from My Space and exposes loyalty points and tiers, offers/coupons, available subscription plans, active membership, purchase/activation/renewal and cancellation with financial compensation status. None of U002, U005 or U006 owned the combined lifecycle, so the plan could have reached its previous final closure unit while this real money-moving client feature remained unverified.

The omission is not merely categorization. Current shared subscription code creates mutation idempotency from `Date.now()` plus an in-process sequence for each invocation, while `useSubscriptionLifecycleController` stores `pendingPurchase` and `paymentSession` only in React state. That combination makes process death, navigation reset, timeout and retry a first-class risk: a relaunch can lose the original attempt identity and initiate another mutation unless DSH/WLT independently recover and deduplicate it. The package must therefore test and, if necessary, redesign durable attempt identity/readback rather than adding UI-level debounce.

DSH remains the owner of benefit/loyalty/offer/subscription entitlement and lifecycle state; WLT remains the owner of payment, ledger, refund and compensation. The governance product-contract directory has no obvious dedicated benefits/subscription truth file by name, so implementation must resolve commercial terms through existing Product Truth/PRD/contract authority and must not invent plan, eligibility, refund or loyalty policy from frontend behavior. U007 closes the read projection, purchase/renewal exactly-once path, and cancellation/compensation saga before final closure.

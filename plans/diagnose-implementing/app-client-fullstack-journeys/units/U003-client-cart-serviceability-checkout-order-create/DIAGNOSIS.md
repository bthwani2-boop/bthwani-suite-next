# U003 diagnosis — cart, serviceability, checkout and order creation

Current DSH already contains the stronger checkout snapshot owner: `ComputeCheckoutSnapshotTx` locks the cart and validates `expectedVersion`. The current HTTP checkout path still calls `ComputeCheckoutSnapshotForClientTx`, a compatibility wrapper explicitly intended for callers that do not carry expected version. This is a real optimistic-concurrency hole between a client-confirmed cart and the snapshot used to create an order. The correction is architectural, not a UI refresh: expected cart version must become part of checkout contract, generated type, controller and handler; stale versions must return canonical conflict/readback before order creation.

Cart pricing/financial components remain WLT-owned where delegated and serviceability remains DSH server truth. Checkout coordinates those owners but cannot cache a final local eligibility or financial truth. Order creation must remain exactly once under retry/concurrency and persist immutable snapshots. The versionless wrapper must be removed once its legitimate caller census reaches zero, or tightly bounded during migration without becoming an indefinite fallback. Verification must force stale-cart, simultaneous mutation/checkout, duplicate intent, timeout/retry and serviceability-change races.

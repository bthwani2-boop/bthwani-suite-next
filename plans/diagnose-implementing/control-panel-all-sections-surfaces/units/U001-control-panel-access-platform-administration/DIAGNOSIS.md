# Diagnosis — Access, Platform and Administration

This unit covers the cross-cutting entry and control plane that can silently invalidate every other Control Panel section. The runtime is composed through the shell and server/BFF layers, so route visibility is not enough: implementation must prove route authorization, object authorization and trusted scope independently. Login, session restore, logout, actor/permission changes, hidden routes and direct URL access must fail closed. Platform and Administration operations are especially sensitive because role assignment, actor state, policy/configuration, rollback and audit controls can alter the authority applied elsewhere.

The service-level Control Panel modules and runtime API/server boundary must converge on one server-authoritative identity and scope model. Search, pagination and bulk administration must never authorize by client-supplied identifiers alone. Sensitive changes require durable actor/target/scope/reason/request evidence and post-write readback. The unit must preserve DSH ownership and must not create local browser, BFF or UI truth for permission or platform state. Its completion is prerequisite for all later units because section-level correctness is meaningless if access, session or trusted context can be bypassed.

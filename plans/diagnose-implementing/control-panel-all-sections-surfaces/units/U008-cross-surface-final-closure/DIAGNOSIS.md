# Unit diagnosis — U008 / cross-surface-final-closure

## Inclusion reason

U008 is the only verification concern and depends on U001 through U007. Its coverage intentionally references common runtime layers, all sovereign owners, Product Truth groups, hidden/detail routes, direct mobile consequences, migration governance and the explicit unrelated-area exclusion boundary. COV-041 supplies the complete Control Panel section/state/manual-scenario registry so this unit can verify every current section without taking ownership away from the implementation units.

## Current behavior and observable defect

A package can pass compilation while still being operationally unsafe: a forbidden object can leak through search, a stale mutation can overwrite newer state, a response can be lost after commit and retried twice, a provider can be shown healthy because it is configured, an unknown financial result can be treated as failure and moved again, or an affected mobile surface can remain stale. Current Product Truth also requires runtime/visual/security/finance/approval evidence for protected capabilities. Therefore “all tests green” is not equivalent to final closure.

## Root cause

The structural cause of false closure is evidence fragmentation across commits, services and surfaces. If checks run against different SHAs, or a branch moves after verification, there is no single proven candidate. If derived registries are treated as truth, they can mask a canonical contract conflict. If unrelated areas are pulled in, the candidate becomes noisy and harder to prove. Final closure needs one immutable SHA, direct dependency scope and an evidence matrix tied to that SHA.

## Correct truth owner and target architecture

This unit owns no product truth. It verifies that Control Panel composition and each sovereign owner comply with their current canonical contracts on one candidate. It rejects parallel truth, stale generated clients/contracts, unsupported fallbacks, cross-scope access, missing failure/recovery states, financial boundary violations and unverified protected approvals. A branch movement triggers re-resolution and delta classification before the decision can remain valid.

## Exact affected paths and symbols

All paths listed by COV-019 through COV-046, plus the current Control Panel section routes represented by COV-041 and the implementation results from U001-U007. Verification reads but does not broaden into unrelated product areas covered by COV-044.

## Risks, compatibility, migration, and removal impact

The main risk is a false positive closure. Evidence must record exact candidate SHA, command/result and required manual/independent review. Runtime/visual checks cannot be substituted by static inspection. Financial and protected Administration/Platform approvals cannot be self-granted. Cleanup is required for obsolete duplicate implementations discovered during execution, but only after replacement paths and compatibility are proven.

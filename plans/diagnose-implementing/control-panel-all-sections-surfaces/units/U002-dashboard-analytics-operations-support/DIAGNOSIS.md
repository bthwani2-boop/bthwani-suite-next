# Diagnosis — Dashboard, Analytics, Operations and Support

This unit covers operational observation and intervention: dashboard, analytics, operations, support, cart diagnostics and map-assisted workflows. These areas are linked by live operational truth rather than by navigation. A dashboard/KPI that uses stale or differently scoped data can contradict the work queues used to change orders; a support rescue action can create downstream Partner/Captain/Client consequences; cart or map diagnostics can expose cross-tenant/object data if filtering and scope are not aligned with the mutation APIs.

Implementation must trace each read and write from the page/shared module through the Control Panel BFF/server boundary into DSH contracts, backend ownership and PostgreSQL invariants. Operator intervention must obey legal state transitions, conflict/version rules, idempotency where retries occur, and canonical readback after success or response loss. Search, filters, exports and bulk operations must preserve object isolation. Client, Partner and Captain are included only for direct consequences of operational decisions, not as independent application scopes. Error, forbidden, empty, no-result and dependency-degraded states must remain distinct so operators cannot mistake missing truth for valid zero-state data.

# U002 — Canonical Field provider, Identity, Workforce and activation

Current source proves a structural problem rather than a single missing button. Field providers are intended to be independent contractors with no shifts, yet the create UI has emitted employee semantics; the public contract, TypeScript input and Go implementation disagree about whether `actorId` already exists; a live direct create API coexists with `provisioning-cases`; those provisioning routes are disabled while frontend code still references them; and the visible create screen calls another controller that intentionally always fails. This must be removed as a competing architecture, not patched around.

Activation has a second contradiction: the service has `sovereignFieldsComplete`, the operational core has its own evaluator, and `GovernedActivationReadiness` extends it again. The final policy is one canonical server policy: name, phone, service zone, supervisor, verified identity and approved contract before activation. Guarantor/referral are not global blockers without active policy. The Control Panel also has duplicate provider-detail views and unwired media/save/supervisor/operational controls; one routed view must absorb the valid behavior and the duplicate/dead implementation must be deleted.

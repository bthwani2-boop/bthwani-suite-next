# 05 — REVERIFY, EXACT-HEAD CI, REDIAGNOSE, RE-COLLAPSE, AND REPEAT

## Purpose

After each coherent Closure Unit or fast-garbage checkpoint, verify exact results, push safely, refresh branch-wide truth, re-run semantic/container consolidation, and select the next structural root only from the refreshed model.

## Fast-garbage checkpoint flow

For `DELETE_NOW` discoveries:

```text
PROVE LOW-RISK GARBAGE
→ EVALUATE LINE→SYMBOL→FILE→DIRECTORY→PACKAGE
→ DELETE AT HIGHEST SAFE CANONICAL GRANULARITY
→ RE-EVALUATE PARENTS RECURSIVELY
→ SEARCH REFERENCES AGAIN
→ RUN AFFECTED VERIFICATION
→ CONFIRM NO PRODUCT/DATA/CONTRACT/RUNTIME/E2E AUTHORITY CHANGED
→ COMMIT COHERENT FAST-CLEANUP BATCH
→ PUSH g
→ VERIFY REMOTE SHA
→ RE-PIN
→ REFRESH AFFECTED CENSUS/LEDGER/FILE-CONTAINER VERDICTS
```

If deletion changes semantic authority, ownership, contract/data/runtime behavior, required consumers, vertical parity, or canonical container topology, stop the fast lane and return to the complete structural baseline.

## Commit / push / exact-head evidence

For structural roots:

`COMMIT ONE COHERENT CLOSURE UNIT → PUSH g → FETCH → VERIFY REMOTE HEAD → PIN EXACT PUSHED SHA → EVALUATE ON-DEMAND REMOTE CI NEED`.

CI remains evidence only. Remote runs are dispatched when required by security/control-plane/high-impact structural/final qualification needs; localized proven cleanup may rely on affected verification when appropriate.

## Evidence ingestion

For every material CI/test/scanner/runtime/UI result:

`INGEST → VERIFY HEAD/BASE/WORKFLOW PROVENANCE → DEDUPLICATE → CORRELATE TO CURRENT g/CANONICAL g/STRUCTURAL DELTA/E2E MATRIX/CANONICAL CONTAINER MAP → IDENTIFY CAUSAL PARENT → UPDATE EVIDENCE VALIDITY`.

`CI FAILURE != EXECUTION ROOT`.

## Mandatory branch-wide refresh after structural roots

After every structural root and before every next structural mutation:

```text
RE-PIN
→ FULL TRACKED-TREE RE-CENSUS
→ REFRESH ARTIFACT DISPOSITION LEDGER
→ REFRESH SEMANTIC AUTHORITY REGISTRY
→ REFRESH FILE VERDICTS
→ REFRESH DIRECTORY/PACKAGE VERDICTS
→ REFRESH CURRENT g
→ RECHECK CANONICAL g
→ REFRESH WINNER/LOSER MAP
→ REFRESH CANONICAL CONTAINER MAP
→ RE-RUN SAME-RESPONSIBILITY CLUSTERING INDEPENDENT OF NAMES/PATHS
→ REFRESH END-TO-END CAPABILITY/JOURNEY MATRIX
→ REFRESH STRUCTURAL + PARITY + FRAGMENTATION DELTA
→ RE-SYNTHESIZE/RANK ROOT GRAPH
```

After a fast-garbage-only checkpoint, refresh affected inventory and parent-container verdicts; a full rebuild is required if deletion exposes material structural, semantic, parity, or container changes.

Any newly introduced/exposed artifact starts `UNJUSTIFIED_UNTIL_PROVEN`.

No next structural root may execute while:

```text

```

## Next-root law

Do not return to Orchestrator AUTO/NEXT or historical order.

The next root comes only from:

`REFRESHED CURRENT g → CANONICAL g → STRUCTURAL + E2E + CONTAINER/FRAGMENTATION DELTA → DYNAMIC ROOT GRAPH`.

If new evidence proves a higher root that invalidates descendant treatment:

`STOP DESCENDANT WORK → PROMOTE HIGHER ROOT → REBUILD TARGET/AFFECTED CONE/VERTICAL SLICE/CANONICAL CONTAINER SET → EXECUTE ONLY AFTER GATES PASS`.

## Repeat condition

While a proven executable structural root remains:

`SELECT HIGHEST ROOT → RECONSTRUCT → CONSOLIDATE CONTAINERS → MIGRATE/CUTOVER → RESTORE E2E PARITY → DELETE LOSERS/GARBAGE → RECURSIVE PARENT PRUNE → FINISH FILES/DIRECTORIES/SCREENS → VERIFY → PUSH → RE-CENSUS → RE-RANK`.

When the root graph first becomes empty, transition to `06`; do not declare completion.

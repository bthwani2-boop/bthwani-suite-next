# H Verification, Re-Diagnosis and Fixed-Point Closure

Status: ACTIVE_CANONICAL_ORCHESTRATOR_OWNER
Owner: exact-candidate evidence, falsification, admission proof, re-census and final Level-4 qualification.

## 1. Verification proves claims; it does not define architecture

CI, tests, scanners, linters, builds, runtime probes and code review are evidence producers only.

```text
GREEN != CANONICAL
GREEN != ROOT_CLOSED
ZERO_EXIT != FINDINGS_DISPOSITIONED
UPLOADED_ARTIFACT != EVIDENCE_CONSUMED
```

Verification is selected from the claims invalidated by the actual root treatment, then widened at material risk and fixed point.

## 2. Exact-h evidence

Every closure claim records:

```text
EXACT_H_SHA
EVIDENCE_SOURCE
INPUT/BASE WHEN APPLICABLE
ENVIRONMENT
CLAIM COVERED
RESULT
LIMITATIONS
FINDINGS/DISPOSITIONS
```

Evidence tied to a changed claim, input, environment, authority or consumer cone is stale.

After every material push re-pin remote `h` before making a final claim.

## 3. Required closure evidence per root

As applicable to the root, prove:

```text
CANONICAL OWNER EXISTS
CANONICAL WRITE PATH EXISTS
REQUIRED DATA/CONTRACT MIGRATION COMPLETED
ALL MATERIAL CONSUMERS CUT OVER
OLD WRITES DISABLED
LOSING READERS/IMPORTS/ROUTES/CONFIG REFERENCES=0
LOSING AUTHORITY DELETED
OBSOLETE CONTAINERS PRUNED
DEPENDENCY RESIDUE REMOVED
GENERATED LINEAGE REPRODUCIBLE
RUNTIME READBACK CORRECT
SECURITY/FINANCIAL INVARIANTS HOLD
ADMISSION/PREVENTION HOLE CLOSED
```

Negative-space proof is mandatory for deletion/cutover claims.

## 4. Failure classification

A verification failure is classified before mutation:

```text
SAME_ACTIVE_ROOT_SYMPTOM
NEW_HIGHER_ROOT_EVIDENCE
INHERITED_INDEPENDENT_ROOT
TOOL/ENVIRONMENT_FAILURE
STALE_EVIDENCE
EXPECTED_TRANSITIONAL_FAILURE_INSIDE_OPEN_ROOT
```

Never automatically turn the first failed job into the next fix.

If evidence reveals a higher causal root than the active diagnosis, stop local patching and re-rank.

## 5. NOT_COVERED and UNKNOWN

Material claims may not silently disappear.

```text
PASS
FAIL
N/A_PROVEN
NOT_COVERED
BLOCKED_UNKNOWN
```

For a material claim, closure is forbidden while the state is `NOT_COVERED` or `BLOCKED_UNKNOWN`.

## 6. Falsification

For every major closure claim actively attempt to disprove it.

Examples:

```text
SEARCH FOR OLD AUTHORITY REFERENCES AFTER DELETION
SEARCH FOR SECOND WRITERS
SEARCH FOR DUPLICATE ENUM/DTO/POLICY DEFINITIONS
SEARCH FOR SHADOW CONFIG
SEARCH FOR MANUAL GENERATED MIRRORS
SEARCH FOR COMPATIBILITY ROUTES STILL REACHABLE
SEARCH FOR EMPTY/MEANINGLESS PARENT CONTAINERS
SEARCH FOR TESTS THAT ONLY VALIDATE RETIRED BEHAVIOR
SEARCH FOR CI SUPPRESSIONS THAT MASK THE ROOT
```

Absence claims require search/graph/runtime evidence appropriate to the surface.

## 7. Admission and prevention proof

Root closure must identify how the defect was admitted or allowed to survive.

A prevention mechanism should be the simplest durable authority that can falsify recurrence:

```text
TYPE SYSTEM
SCHEMA CONSTRAINT
CONTRACT GENERATION
COMPILER
LINT/STATIC RULE
UNIT/INTEGRATION/E2E TEST
RUNTIME ASSERTION/HEALTH PROBE
CI CHECK
SECURITY SCANNER
PROCESS/OWNERSHIP STRUCTURE ONLY WHEN EXECUTABLE MECHANISMS CANNOT EXPRESS THE CLAIM
```

Do not build governance automation merely to prove governance prose.

## 8. GitHub Actions policy on h

The campaign may use direct `workflow_dispatch`, push-triggered evidence, reusable workflows or temporary campaign workflows on `h` when technically justified.

Requirements:

```text

```

At fixed point, persistent workflows must re-earn existence as durable baseline assurance.

## 9. Re-diagnosis after each closed root

After closure:

```text
RE-PIN h
→ UPDATE CURRENT MODEL
→ RE-RUN MATERIAL CENSUS FOR AFFECTED SURFACES
→ INVALIDATE STALE EVIDENCE
→ INGEST NEW FINDINGS
→ REBUILD/REFRESH ROOT GRAPH
→ RE-RANK
```

Do not continue from a frozen objective list.

Then adversarially falsify the fixed-point claim.

```text

```

If new evidence appears, reopen the graph. Completion is evidence-bounded, never metaphysical certainty.

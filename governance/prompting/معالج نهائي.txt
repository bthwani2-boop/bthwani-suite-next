## أمر التشخيص والتخطيط الريموت قبل التنفيذ

1. **تثبيت المرجع الريموت:** قبل أي تنفيذ أو تعديل، اجلب أحدث حالة للفرع المحدد عبر GitHub Remote، وثبّت وسجّل أحدث `SHA` بوصفه خط الأساس الملزم للتشخيص والخطة.

2. **التشخيص الاستقصائي الشامل:** افحص ووثّق كل ملف ومكوّن واعتمادية واستخدام وتدفق وتكامل ذي صلة مباشرة أو غير مباشرة بالمهمة، بما يشمل العناصر القديمة والمكررة والمهجورة وغير الضرورية، ولا تفترض سلامة أي عنصر دون دليل ريموت قابل للتحقق.

3. **إنشاء الحزمة حصريًا بالأدوات المعتمدة:** أنشئ حزمة تشخيص وتخطيط ذاتية الاكتفاء داخل:

   * الريموت: `tools/diagnose-implementing/<TASK_NAME>/`
   * المحلي المقابل: `C:\bthwani-suite-next\tools\diagnose-implementing\<TASK_NAME>\`

   ويُمنع إنشاؤها يدويًا أو باستخدام بنية موازية؛ استخدم حصريًا القالب الدائم `_template/` والمولّد `new-package.mjs`.

4. **محتوى الحزمة الإلزامي:** يجب أن تتضمن الحزمة بصورة مترابطة وموثقة:

   * السلطة المرجعية، نطاق المهمة، الحدود والاستثناءات.
   * الجرد الكامل للملفات والاستخدامات والاعتماديات والتدفقات والأدلة.
   * الأسباب الجذرية، ملاك ومصادر الحقيقة، المخاطر، الفجوات والنقاط غير المثبتة.
   * تحليل العناصر المرشحة للحذف أو النقل أو الدمج أو إعادة التنظيم، مع إثبات أثر كل قرار قبل اعتماده.
   * التصميم والحالة المستهدفة.
   * خطة معالجة مرتبة حسب الاعتماديات والتسلسل التشغيلي الصحيح.
   * مهام ذرية تحدد بدقة: الملفات والمسارات والأسطر أو الرموز المستهدفة، التغييرات المطلوبة، أوامر التنفيذ، النتائج المتوقعة، معايير القبول، الفحوص، المخاطر وخطة التراجع.

5. **تقسيم المهام الواسعة:** إذا كانت المهمة واسعة أو معقدة، فقسّمها إلى مراحل مرقمة وشرائح عمودية مترابطة ذات ترتيب إلزامي، وحدد لكل مرحلة أو شريحة:

   * النطاق.
   * المدخلات والمخرجات.
   * الاعتماديات والمتطلبات السابقة.
   * المهام الذرية.
   * بوابات الفحص والقبول والإغلاق المستقلة.

6. **التتبّع المتقاطع:** امنح كل ادعاء ودليل وفجوة ومخاطرة وقرار ومهمة وفحص وبوابة معرفًا ثابتًا، واربط المعرفات ببعضها بحيث يمكن تتبّع كل مهمة إلى فجوتها وسببها الجذري ودليلها ومعيار قبولها ونتيجة فحصها.

7. **التحكم الصارم بالتنفيذ:** اسمح بمهمة تنفيذية واحدة فقط في كل مرة، وفق ترتيب الاعتماديات المعتمد، وامنع بدء المهمة التالية أو إغلاق المرحلة أو الحزمة ما دامت أي بوابة قابلة للمعالجة غير صفرية أو توجد فجوة مثبتة لم تُغلق أو نقطة قابلة للإثبات لم تُحسم.

8. **التحقق قبل الاعتماد:** شغّل `validate-package.mjs --strict`، وعالج جميع الإخفاقات حتى تصبح النتيجة ناجحة بالكامل قبل اعتماد الخطة أو السماح ببدء أي تنفيذ لاحق.

9. **حدود هذه المرحلة:** في هذه المرحلة اقتصر حصريًا على التشخيص وإنشاء حزمة الخطة وإجراء `Commit` و`Push` لها على الفرع الريموت؛ ويُمنع تعديل أو حذف أو نقل أو إعادة تسمية أي ملف من ملفات المشروع التشغيلية.

10. **طبيعة الحزمة:** اعتبر مجلد المهمة أداة دعم وتشخيص وتخطيط مؤقتة فقط، وليس مصدر حقيقة أو مكوّنًا تشغيليًا، ويُمنع ربطه بالتشغيل أو البناء أو الاختبارات أو `CI` أو الحوكمة أو استيراده واعتماد أي جزء من المشروع عليه.

11. **مرحلة التنفيذ اللاحقة:** عند تنفيذ الخطة لاحقًا، انقل كل نتيجة أو عقد أو توثيق أو اختبار أو قاعدة أو إعداد دائم إلى مالكه الحقيقي ومساره المركزي المعتمد، ولا تترك داخل حزمة المهمة أي سلطة دائمة أو مصدر حقيقة موازٍ.

12. **الإغلاق والتخلص:** بعد اكتمال التنفيذ وإغلاق جميع البوابات، شغّل `validate-package.mjs --strict --disposal`، وأثبت عدم وجود أي استيراد أو مرجع أو اعتماد تشغيلي أو بنائي أو اختباري أو حوكمي على مجلد المهمة، ثم احذف مجلد `<TASK_NAME>` وحده، مع الإبقاء دائمًا على `_template/` و`new-package.mjs` و`validate-package.mjs`.

13. **المخرجات الإلزامية:** لا تعتبر المهمة منجزة إلا بعد:

* تثبيت وتوثيق أحدث `SHA` ريموت.
* اكتمال الحزمة واجتياز التحقق الصارم.
* تنفيذ `Commit` و`Push` فعليين.
* إرجاع اسم الفرع، و`SHA` الأساسي، و`SHA` الالتزام الناتج، ومسار الحزمة، وملخص الجرد والفجوات والمراحل والبوابات.
* التأكيد الصريح أن ملفات المشروع لم تُعدّل في مرحلة التشخيص والتخطيط.











# أمر التنفيذ الهندسي الجذري الشامل لـ DSH وما يرتبط به في WLT

نفّذ على أحدث `SHA` للفرع المحدد معالجة هندسية جذرية وشاملة للمستودع، تخص جميع مكونات `DSH` وما يرتبط بها في `WLT`، في الواجهات والخلفيات ووفق معمارية **الفول ستاك الموحد متعدد الأسطح**، مع الالتزام الصارم بالنقاط التالية:

## 1. نطاق التشخيص الإلزامي

* افحص معماريًا وتقنيًا ومنطقيًا وتشغيليًا كل ملف ومجلد ووحدة وخدمة وعقد وقاعدة بيانات وسطح وتدفق وتكامل وإعداد واعتمادية واختبار وأداة وحوكمة ذات صلة مباشرة أو غير مباشرة.
* لا تتجاهل أي تطبيق أو سطح أو صفحة أو تبويب أو وظيفة أو عملية أو مسار أو حالة أو عقد أو تكامل أو مكوّن.
* لا تفترض سلامة أي عنصر لمجرد أنه لا يفشل حاليًا.
* افحص كذلك الملفات القديمة والمكررة والمهجورة والمشتتة وعديمة القيمة أو ذات الأسماء أو المواقع أو المسؤوليات غير الصحيحة.

## 2. تحديد الأسباب الجذرية

حدّد وأثبت الأسباب الحقيقية لكل:

* فجوة أو نقص أو مخالفة أو تناقض.
* تكرار أو ازدواجية أو ضجيج معماري.
* مصدر حقيقة موازٍ أو ملكية غير واضحة.
* اعتماد خاطئ أو دوري أو غير ضروري.
* عقد يدوي موازٍ للعقود المركزية.
* دين تقني أو تصميم ضعيف أو حدود خدمة منتهكة.
* وظيفة غير مربوطة أو غير مفعلة أو ناقصة.
* ملف قديم أو احتياطي أو مهجور داخل المسارات الحية.
* تسمية أو موقع أو مسؤولية لا تتوافق مع المعمارية الصحيحة.

## 3. منهجية المعالجة

* عالج كل مشكلة من مصدرها الحقيقي، لا من أعراضها.
* طبّق الحل الأكثر أمانًا وكفاءة وبساطة واستدامة وفق أفضل الممارسات الهندسية والمعمارية والأمنية.
* التزم بالتسلسل المنطقي والتشغيلي الصحيح، ولا تنفّذ تغييرات معزولة تكسر التدفقات العابرة للخدمات والأسطح.
* حافظ فقط على الوظائف الصحيحة والبيانات الضرورية والتوافقات المعتمدة والمثبتة.
* لا تستنزف الوقت في مطاردة أعطال متتابعة داخل مكوّن ثبت فساد أساسه؛ استبدله بتصميم صحيح ومبسّط.

## 4. صلاحيات التنفيذ

لديك صلاحية مدروسة لتنفيذ ما يلزم، بما يشمل:

* إعادة الهيكلة أو إعادة البناء.
* الحذف أو الإزالة.
* النقل أو الدمج أو التقسيم.
* إعادة التسمية أو الاستبدال.
* الإضافة أو التوحيد.
* إعادة تصميم الحدود والتدفقات والعقود والملكيات.

استخدم هذه الصلاحيات عندما يكون الإصلاح الجذري أكثر أمانًا وأقل تعقيدًا من إبقاء تصميم فاسد أو ملاحقة أخطائه.

## 5. المحظورات الصارمة

يُمنع:

* استخدام الترقيعات المؤقتة أو الحلول الالتفافية.
* مطاردة سلسلة أعطال دون معالجة أصلها.
تجاهل اي شاشة او زر او تبويب او واجهة او صفحه او اي شيء في الفرونت ايند 
* إنشاء طبقات توافق غير ضرورية.
* تكرار المنطق أو العقود أو الحالات أو النماذج.
* إنشاء مصادر حقيقة بديلة أو موازية.
* إبقاء ملفات قديمة أو نسخ احتياطية داخل المسارات الحية.
* تعطيل الاختبارات أو تخفيف القيود لإخفاء الأخطاء.
* إبقاء مسارات مهجورة أو واجهات زائفة أو وظائف غير مكتملة.
* الادعاء بإغلاق نقطة لا يوجد دليل قابل للتدقيق على إغلاقها.

## 6. ترتيب التنفيذ الإلزامي

نفّذ المعالجة تدريجيًا بهذا الترتيب:

1. حدود الثقة والسيادة وملكية المجالات.
2. الهوية والمصادقة والتفويض والأدوار والصلاحيات.
3. حقيقة البيانات وقواعد البيانات والمخططات والترحيلات.
4. العقود المركزية وواجهات `API` والأحداث والأنواع والعملاء المولدين.
5. الاعتماديات والحدود المعمارية واتجاهات الاتصال.
6. خدمات `DSH` وتكاملاتها المسموح بها مع `WLT`.
7. التدفقات التشغيلية العابرة للخدمات.
8. التطبيقات والأسطح والصفحات والوظائف وتجربة المستخدم.
9. الأدوات والإعدادات والتشغيل والمراقبة.
10. الاختبارات والحوكمة والوثائق وأدلة الإغلاق.

لا تنتقل إلى طبقة لاحقة قبل استقرار الأساس الذي تعتمد عليه.

## 7. ضوابط الحذف والاستبدال

* كن صارمًا واحذف كل عنصر غير صحيح أو غير مناسب أو غير مفيد أو متعارض مع المعمارية المستهدفة.
* لا تحذف أي عنصر قبل تحليل استخدامه واعتمادياته وتأثيره ومسار ترحيله أو استبداله.
* انقل المستهلكين أولًا إلى المصدر الصحيح، ثم احذف المصدر القديم وبقاياه.
* تأكد من إزالة الاستيرادات والمراجع والإعدادات والاختبارات والوثائق المرتبطة بالعناصر المحذوفة.
* لا تترك ملفات إعادة تصدير أو واجهات توافق أو أسماء قديمة ما لم تكن ضرورة مثبتة ومحددة زمنيًا.

## 8. شروط الإغلاق والتحقق

لا تعتبر المهمة مكتملة إلا بعد:

* إزالة الأسباب الجذرية وجميع البقايا والازدواجيات والمسارات المهجورة.
* توحيد الملكية ومصادر الحقيقة والعقود والمسميات والحدود والمسؤوليات.
* التأكد من ربط جميع الصفحات والوظائف والعمليات والتدفقات المتأثرة فعليًا.
* تشغيل الفحوصات الساكنة والتنسيق والتحقق من الأنواع.
* نجاح البناء لجميع الحزم والخدمات والتطبيقات المتأثرة.
* نجاح الاختبارات الوحدوية والتكاملية والتعاقدية والأمنية والسلبية.
* اختبار ترحيلات البيانات والتراجع عنها وسلامة البيانات.
* تنفيذ اختبارات التشغيل الفعلي و`smoke tests` لجميع الأسطح والتكاملات المتأثرة.
* التحقق من حالات النجاح والفشل والرفض وعدم الجاهزية والتدهور والاسترداد.
* التأكد من عدم ظهور مصادر حقيقة موازية أو اعتماديات غير مشروعة بعد التنفيذ.

## 9. أدلة التسليم الإلزامية

قدّم في النهاية أدلة قابلة للتدقيق تتضمن:

* أحدث `SHA` الذي بُني عليه التنفيذ.
* نطاق الملفات والمكونات التي شُخّصت.
* الأسباب الجذرية المكتشفة.
* ما تم حذفه أو نقله أو دمجه أو تقسيمه أو إعادة تسميته أو إعادة بنائه.
* العقود ومصادر الحقيقة والملكيات التي تم توحيدها.
* الاختبارات والفحوصات والأوامر التي نُفذت ونتائجها الفعلية.
* دليل تشغيل التدفقات المتأثرة على جميع الأسطح.
* قائمة صريحة بكل نقطة لم يمكن إثبات إغلاقها، وسبب ذلك، والخطوة اللازمة لإغلاقها.

# قاعدة الاكتشاف والتشخيص والإغلاق الشامل للسطح وجميع رحلاته

تُطبّق هذه القاعدة إلزاميًا على مرحلتي التشخيص والتخطيط داخل `tools/diagnose-implementing/<TASK_NAME>/` وعلى التنفيذ اللاحق كاملًا: اعتبر اسم أي سطح أو تطبيق أو قسم يرد في المهمة **نقطة بدء لاكتشاف النطاق فقط، وليس حدًا للنطاق**، ولا تبدأ الخطة أو التنفيذ اعتمادًا على الرحلات أو الملفات المذكورة صراحةً وحدها؛ بل ثبّت أحدث `SHA` ريموت للفرع أو المرجع المحدد، ثم نفّذ تشريحًا استقصائيًا عميقًا للمستودع كله ولكامل مصادره الحية والمشتركة والمولدة والقديمة والمكررة والمجزأة والمخفية خلف تسميات مختلفة، وافحص جميع التطبيقات والخدمات والحزم والمجلدات والملفات والرموز والاستيرادات والاستخدامات ونقاط الدخول والمسارات والتوجيه والتنقل والروابط العميقة والعقود والعملاء المولدين وواجهات `API` والمعالجات ومنطق المجال وآلات الحالات وقواعد البيانات والمخططات والترحيلات والقيود والفهارس والأحداث و`Outbox/Inbox` والمهام والطوابير والمزودات والوسائط والبحث والتخزين المؤقت والإعدادات وبيئات التشغيل و`Docker` و`CI` والحراس والاختبارات والحوكمة والوثائق والأدلة، بحيث يُصنَّف كل عنصر إلى مرتبط أو غير مرتبط بدليل، ويُمنع استبعاد أي عنصر لمجرد أن اسمه لا يذكر السطح أو أنه لا يظهر فيه مباشرة.

استخرج من الكود والعقود والبيانات والواجهات والتشغيل **جميع الرحلات المرتبطة بالسطح** سواء كانت موثقة أو غير موثقة، مسجلة أو غير مسجلة، صريحة أو ضمنية، كاملة أو مجزأة بين عدة ملفات وخدمات، مفتوحة أو ناقصة أو متوقفة أو مهجورة أو مكررة أو مغلقة شكليًا دون دليل، وسواء كان السطح فيها مدخلًا أو مخرجًا أو مالكًا أو مستهلكًا أو منفذًا أو مراقبًا أو مصدر أمر أو مستقبل قراءة راجعة أو طرفًا في أثر تشغيلي أو مالي أو أمني أو بياناتي؛ ثم وسّع شبكة النطاق تكراريًا لتشمل كل رحلة سابقة تمهد لها، وكل رحلة لاحقة تعتمد على نتائجها، وكل رحلة مشتركة أو عرضية تؤثر في صحتها، وجميع الاعتماديات والممثلين والخدمات والأسطح والأقسام المستهلكة لهذه النتائج، ولا تتوقف عملية التوسيع حتى لا يبقى ارتباط مباشر أو غير مباشر غير مصنف أو أثر غير متتبع.

لا تعتمد اكتمال حزمة الرحلات أو السجل أو الوثائق كدليل على اكتمال الواقع؛ بل قارنها ثنائيًا مع الكود والتشغيل: استخرج من كل رحلة مكتوبة جميع عناصرها الفعلية وتحقق من وجودها وربطها، واستخرج من الكود كل رحلة أو حالة أو فعل أو أثر فعلي وتحقق من تسجيله وتغطيته، وسجّل أي رحلة مفقودة أو متداخلة أو مكررة أو ذات مالك خاطئ أو تبعية ناقصة أو إغلاق زائف بوصفها فجوة واجبة المعالجة، مع إنشاء خريطة تغطية وتتبع كاملة تربط: `السطح ← الممثل ← الرحلة ← الشرائح ← نقطة الدخول ← الصفحة/الشاشة ← التحكم المرئي ← الأمر أو الاستعلام ← الصلاحية والنطاق الموثوق ← العقد والعميل المولد ← API ← المعالج ← منطق المجال وآلة الحالة ← المعاملة وقاعدة البيانات ← الحدث والمهام والتكاملات ← الأثر التشغيلي أو المالي ← القراءة الراجعة ← جميع الأسطح المستهلكة ← الاختبارات وأدلة التشغيل`.

افحص السطح نفسه عنصرًا عنصرًا دون أي استثناء، بما يشمل جميع المسارات والصفحات والشاشات والواجهات والتخطيطات والأقسام والتبويبات والقوائم والبطاقات والجداول والنوافذ والنماذج والحقول والأزرار والأيقونات والروابط والإيماءات والفلاتر والبحث والفرز والترقيم والتحديث والسحب والإشعارات والتنبيهات والتأكيدات والتنقل والعودة والروابط العميقة؛ وتحقق لكل عنصر من شرط ظهوره وإخفائه وتمكينه وتعطيله وصلاحيته ونطاقه والمدخلات والتحقق والأمر الحقيقي الذي ينفذه وحالات الضغط المتكرر والتحميل والنجاح والفشل والرفض والحظر وعدم الجاهزية والفراغ والبيانات الجزئية والتعارض والبيانات القديمة وفقد الاستجابة والنتيجة المجهولة وعدم الاتصال وإعادة المحاولة والاسترداد والعودة بعد إغلاق التطبيق، ومن صحة `RTL` والترجمة وإمكانية الوصول وترتيب التركيز وقارئ الشاشة وأحجام النص والتكيف مع الشاشات المختلفة واتساق تجربة المستخدم؛ ويُمنع اعتبار أي عنصر مكتمل إذا كان زخرفيًا أو عديم الأثر أو مربوطًا بـ`Mock` أو `Fixture` أو قيمة ثابتة أو حالة محلية أو عقد يدوي أو مسار قديم أو `Fallback` صامت أو إذا نجح بصريًا دون أثر محفوظ وقراءة راجعة مثبتة.

نفّذ لكل رحلة مكتشفة تشخيصًا وتنفيذًا كاملين لشرائح `SL-01..SL-24` وفق ترتيب التبعيات، وتتبع كل فعل من نية المستخدم ونقرته وحتى التحقق من الهوية والجلسة والجهاز والدور والصلاحية والنطاق الموثوق، ثم العقد والنقل والمعالج وقواعد الأعمال وآلة الحالات والمعاملة والقيود وسلامة البيانات والأحداث والتكاملات والأثر المالي عند الانطباق، وانتهاءً بالقراءة الراجعة الصحيحة والمتزامنة في السطح الأصلي وكل سطح أو قسم آخر يجب أن يرى النتيجة؛ وافحص حالات النجاح والفشل والرفض والتكرار والتزامن والسباقات و`Idempotency` والانقطاع في كل نقطة وفقد الاستجابة وإعادة الإرسال والعمل دون اتصال والتعارض والاسترداد والتراجع والتعويض والتدهور وعدم جاهزية الاعتماديات، إضافة إلى الأمن والخصوصية و`IDOR` وتسرب النطاقات والتدقيق والمراقبة والسجلات والأداء والموثوقية وسلامة البيانات وتجربة المستخدم اليدوية الفعلية.

عالج كل فجوة في مالك الحقيقة القانوني ومن مصدرها الجذري، وأكمل جميع الكتابات والقراءات والمستهلكين والترحيلات والاختبارات قبل إزالة المصدر القديم، ولا تترك واجهة أو وظيفة أو رحلة أو حالة أو مسارًا جزئيًا أو مؤجلًا أو غير مربوط، ولا تسمح ببقاء مصادر حقيقة موازية أو عقود مكررة أو حالات محلية حاكمة أو مسارات كتابة متعددة أو ملفات قديمة قابلة للوصول أو وظائف زائفة أو عناصر غير مصنفة؛ وكل عنصر مجهول أو غير مثبت أو لم يُفحص فعليًا يُعامل كفجوة مفتوحة، لا كعنصر سليم ولا كاستثناء ضمني.

لا يُعتبر السطح مكتملًا أو قابلًا للتشغيل ولا تُغلق حزمة التشخيص أو أي مرحلة أو رحلة لمجرد اكتمال الملفات أو نجاح `Lint` أو `Typecheck` أو البناء أو بعض الاختبارات، بل لا يصدر الإغلاق إلا بعد أن تصبح جميع الرحلات المرتبطة، الموثقة والمكتشفة من الكود، مغلقة فعليًا وفق تبعياتها، وتصبح جميع الملفات والمسارات والعمليات والعقود والجداول والأحداث والشاشات والتحكمات والحالات المرئية والآثار والقراءات الراجعة مصنفة ومربوطة ومختبرة، وتصل جميع العدادات والبوابات المنطبقة إلى الصفر، وتنجح الفحوص الساكنة والبناء والاختبارات الوحدوية والتكاملية والتعاقدية والأمنية والسلبية واختبارات الترحيل والتراجع و`Smoke/E2E` والتجريب اليدوي الكامل والتشغيل الحقيقي عبر جميع الأسطح المتأثرة، وتثبت النتائج والأدلة والقراءات الراجعة على `SHA` نهائي واحد؛ وأي رحلة أو عنصر أو حالة أو دليل لم يُثبت إغلاقه يجب التصريح به صراحةً بوصفه مانعًا للإغلاق، مع سببه وموقعه ومالكه وخطوة معالجته، ويُمنع الادعاء بأن السطح يعمل كاملًا ما دام أي خلل داخلي قابل للمعالجة أو أي ارتباط أو رحلة أو تحكم أو أثر غير محسوم.

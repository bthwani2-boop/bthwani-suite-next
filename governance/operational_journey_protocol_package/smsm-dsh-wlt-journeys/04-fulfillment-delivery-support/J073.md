## النتيجة التشغيلية النهائية

ينشئ المستخدم Ticket واحدة مرتبطة بالActor/Order/Category، وتُدار رسائلها وحالتها وSLA بترتيب/idempotency وصلاحيات صارمة. Notifications تسلم فقط، Media يخزن المرفقات، وDSH Support يملك الحقيقة. لا cross-ticket IDOR أو رسائل orphan أو إغلاق صامت.

## تشخيص الحالة الحالية

### الموجود
- support/governed support/message delivery handlers.
- Client/Captain support routers وControl Panel workspace.

### الناقص
- category/routing/priority taxonomy.
- ticket/message state machines.
- assignment/claim/SLA timers.
- message ordering/dedupe/offline send.
- attachment policy وredaction.
- close/reopen/escalation rules.

### الخاطئ أو الممنوع
- ticket IDs قابلة للتخمين أو cross-actor read.
- push payload هو message truth.
- optimistic sent message لا يصحح عند الفشل.
- attachment raw URL أو محتوى حساس في logs.
- Operator impersonation بلا governed support session.

### التصحيح المطلوب
- support aggregate وmessage sequence.
- object-level auth لكل read/write.
- idempotency client_message_id.
- claim/assignment/version/SLA.
- generated clients وcontroller موحد.
- إزالة legacy aliases/routes غير المحكومة.

### الإضافات المطلوبة
- typing/read receipt فقط إذا Product Truth.
- canned responses governed لا أسرار.
- audit transcript export/redaction.

## App Client

- ticket list/detail، create category/order، messages، attachment، retry، close/reopen.
- حالات sending/failed/retrying/waiting/resolved/closed.
- لا duplicate message بعد offline reconnect.

## App Captain

- in-task support entry مع order/assignment context محدود.
- emergency/safety escalation منفصل حسب policy.
- لا يكشف tickets غيره.

## Control Panel

- queues/filters/search، claim/assign، reply، internal note منفصل، request info، resolve/close/escalate.
- internal notes لا تظهر للعميل.
- SLA/priority/audit/attachment scan.

## العقود والبيانات

- ticket/message/participant/assignment schemas.
- message sequence وclient_message_id unique.
- internal/public visibility flag enforced server-side.
- attachment refs scoped.
- notification delivery audit منفصل.

## الاختبارات الآلية

- cross-ticket IDOR.
- message replay/out-of-order/offline.
- internal note leakage.
- close/reopen race.
- attachment abuse.
- claim race/SLA timers.
- notification failure/readback.

## التجريب اليدوي

1. أنشئ ticket من Client وCaptain.
2. أرسل رسائل offline ومتكررة.
3. اختبر attachments والملفات المحظورة.
4. طالب ticket من مشغلين.
5. اكتب internal note وتحقق من عدم ظهورها.
6. أغلق/أعد فتح بالتزامن.
7. عطّل notifications وقارن readback/audit.

## النتيجة التشغيلية النهائية

يمكن للعميل تقديم طلب خاص مرتبط بالطلب أو العنصر، يراجعه الشريك أو المشغل ضمن taxonomy وسياسة سلامة. المرفقات تمر Media، وأي quote أو فرق مالي يملكه WLT. كل خطوة ظاهرة ومؤرخة ولا توجد تعليمات خفية أو mutation مالية مباشرة.

## تشخيص الحالة الحالية

### الموجود
- special requests handlers/screens وmedia upload runtime.
- support/partner workbenches وWLT boundaries.

### الناقص
- request categories/schema/limits.
- moderation/safety policy وforbidden content.
- lifecycle والمالكون لكل transition.
- quote expiry/customer confirmation.
- attachment ownership/scan/retention.
- execution evidence/readback.

### الخاطئ أو الممنوع
- free-text غير محدود يدخل العمليات أو logs.
- upload عام أو URL خام.
- Partner يفرض مبلغًا أو يعدل Order بلا WLT.
- request accepted بصريًا دون state حقيقية.
- تنفيذ طلب غير آمن أو غير مدعوم.

### التصحيح المطلوب
- structured request command وvalidation.
- lifecycle `SUBMITTED | REVIEWING | NEEDS_INFO | ACCEPTED | REJECTED | QUOTED | CONFIRMED | EXECUTED | CANCELLED`.
- Media references فقط.
- WLT quote/adjustment reference.
- generated allowedActions وreason codes.

### الإضافات المطلوبة
- moderation flags ومسار escalation.
- customer/partner messaging مرتبط بالrequest.
- Control Panel queue وaudit/evidence.

## App Client

- entry من Cart/Checkout/Order وفق eligibility.
- category selector، description bounded، attachment add/remove، submit، cancel، confirm quote، reply.
- preview واضح للتأثير والقيود.
- حالات unsafe/rejected/needs info/quoted/expired/executed.
- double-submit/offline recovery.

## App Partner

- review queue، details masked، accept/reject/request info/propose quote/mark executed.
- لا raw customer PII زائد.
- quote fields تأتي من workflow لا input مالي حر غير محكوم.

## Control Panel

- queue حسب safety/SLA/status، review moderation، audit، media scan result، WLT refs.
- controls للتصعيد/إلغاء/طلب معلومات؛ financial action عبر WLT command فقط.

## العقود والبيانات

- request/proposal/decision schemas/versioning.
- attachment refs مع owner/order/request binding.
- text length/content validation وredaction.
- idempotency لكل submit/decision/confirm.
- audit/outbox/notifications.

## الاختبارات الآلية

- malicious/oversized file.
- unsupported/unsafe content.
- cross-order/actor IDOR.
- duplicate submit/accept.
- quote expiry/double confirmation.
- WLT timeout/unknown result.
- attachment orphan cleanup.

## التجريب اليدوي

1. قدم طلبًا نصيًا ومرفقًا صالحًا.
2. اختبر الحدود والأنواع المحظورة والملف الضار.
3. اطلب معلومات إضافية ورد من العميل.
4. اقبل/ارفض واقترح quote.
5. اترك quote تنتهي ثم حاول التأكيد.
6. افصل الشبكة بعد submit/confirm.
7. تحقق من Partner/Control Panel/WLT/Media/audit.

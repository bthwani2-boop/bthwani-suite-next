## النتيجة التشغيلية النهائية

يدير الكابتن رحلة التنفيذ من pickup إلى الوصول ومحاولة التسليم عبر allowedActions صادرة من DSH. كل action يتحقق من assignment/custody/state/version والموقع عند الحاجة، ويدعم offline queue محكومة. العميل والمشغل يريان projection متزامنة دون كشف PII زائد.

## تشخيص الحالة الحالية

### الموجود
- Captain execution/route renderers وdispatch/order handlers.
- live tracking من J064 وحيازة من J065.

### الناقص
- execution state machine وallowedActions contract.
- offline action ordering/dedupe/rejection UX.
- contact attempt/proxy policy.
- arrival/geofence tolerance.
- reassignment/cancellation conflict rules.
- privacy matrix لكل مرحلة.

### الخاطئ أو الممنوع
- أزرار تعمل بناءً على local state.
- queue offline تطبق بعد تغير assignment أو cancellation.
- كشف هاتف العميل الخام أو العنوان بعد الحاجة.
- transition مباشر من picked_up إلى completed دون proof.
- arrival من موقع غير منطقي بلا review.

### التصحيح المطلوب
- commands: depart، arrive، contact attempt، begin delivery attempt، report issue.
- server-driven actions/reasons/version.
- bounded encrypted offline queue.
- geofence/integrity checks مع exception flow.
- إزالة aliases/buttons غير المرتبطة.

### الإضافات المطلوبة
- stale assignment banner.
- contact audit دون محتوى حساس.
- operator live intervention link.

## منطق التشغيل

الحالات: `PICKED_UP | EN_ROUTE | ARRIVED | CONTACTING | DELIVERY_ATTEMPT`. كل command idempotent ويحمل base version. offline commands يعاد تقييمها بالترتيب؛ غير الصالح يرفض مع reason ولا يعاد تفسيره. cancellation/reassignment يبطل queue القديمة.

## App Captain

- route map، next action card، customer instructions الضرورية، status timeline.
- controls: start route، arrived، contact، delivery attempt، report exception، support.
- كل زر disabled/hidden وفق allowedActions ويعرض pending/confirmed/rejected.
- حالات GPS weak، offline، stale assignment، route unavailable، customer unavailable.

## App Client

- tracking/status/last update، safe contact options، support.
- لا يعرض تفاصيل داخلية أو actions للكابتن.
- stale/degraded states واضحة.

## Control Panel

- live execution timeline، location integrity، attempts، allowedActions، assignment/custody refs.
- controls للتدخل عبر commands محكومة أو rescue، لا status editing.

## العقود والبيانات

- execution command schemas/version/idempotency.
- action audit with device/location references.
- contact attempt metadata masked.
- offline replay dedupe.
- privacy projection حسب state.

## الاختبارات الآلية

- invalid transition/double tap.
- offline queue after cancellation/reassign.
- geofence mismatch/spoof.
- stale version.
- PII overexposure.
- provider map down.
- concurrent operator action.

## التجريب اليدوي

1. نفّذ المسار الكامل على App Captain.
2. اضغط كل action مرتين.
3. افصل الشبكة ونفّذ actions ثم غيّر الحالة من Control Panel.
4. اختبر arrival خارج geofence.
5. ألغِ أو أعد الإسناد أثناء offline.
6. راقب Client وControl Panel والـtimeline.
7. افحص PII والlogs.

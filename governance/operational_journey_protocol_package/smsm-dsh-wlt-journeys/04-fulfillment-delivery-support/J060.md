## النتيجة التشغيلية النهائية

ينفذ طلب Pickup دون دخول Dispatch أو Captain. بعد جاهزية الطلب يصدر DSH verification mechanism قصير العمر ويربطه بالعميل والطلب والمتجر، ويثبت handoff مرة واحدة. كل Surface يرى الحالة نفسها، ولا يستطيع الشريك إكمال الطلب دون proof معتمد.

## تشخيص الحالة الحالية

### الموجود
- Pickup handlers وfulfillment mode من J051.
- Partner preparation/order surfaces.

### الناقص
- pickup state machine وverification contract.
- code/QR policy: hashing، expiry، attempts، single-use.
- customer arrival/ready notifications.
- wrong-recipient handling.
- cancellation/expiry race.
- proof retention وsupport override workflow.

### الخاطئ أو الممنوع
- إنشاء assignment أو Captain route لطلب Pickup.
- code ثابت/ظاهر في logs أو قابل لإعادة الاستخدام.
- Partner يضغط complete دون تحقق.
- العميل يرى ready قبل transition الفعلية.
- override شفهي غير مدقق.

### التصحيح المطلوب
- mode-specific lifecycle `PICKUP_SELECTED | READY_FOR_PICKUP | CODE_ISSUED | VERIFICATION_PENDING | VERIFIED | COMPLETED | EXPIRED | FAILED`.
- verification atomically consumes proof and completes handoff.
- dispatch guards تمنع Pickup.
- generated UI states/actions.

### الإضافات المطلوبة
- arrival instruction/store location/contact-safe details.
- support recovery/identity verification وفق policy.
- Control Panel pickup monitor.

## App Client

- pickup status، store address/map، opening window، instructions، code/QR masked حسب policy.
- controls: `عرض الرمز`، `تحديث`، `أنا في الموقع` إن معتمد، `طلب مساعدة`.
- حالات not ready/ready/code expired/attempt locked/completed/cancelled.
- الرمز لا يظهر قبل eligibility ولا يبقى بعد completion.

## App Partner

- pickup queue، ready action، scan/enter code، verify، handoff complete.
- يمنع manual completion دون proof.
- يوضح wrong/expired/used code وattempt limits.

## Control Panel

- pickup workboard، code status masked، attempts، proof/audit، SLA.
- controls: revoke/reissue وفق permission، support override بموافقة/evidence؛ لا كشف raw code.

## العقود والبيانات

- hashed verification secret، expiry/attempts/consumed_at.
- unique active code per order حسب policy.
- atomic verify+handoff transition.
- no dispatch assignment constraint.
- audit/outbox/notification correlation.

## الاختبارات الآلية

- code replay/wrong customer/wrong store.
- expired/locked code.
- partner complete without proof.
- concurrent verify.
- cancellation vs verification race.
- dispatch creation blocked.
- raw code log scan.

## التجريب اليدوي

1. أنشئ Pickup Order وجهزه.
2. تحقق من عدم ظهوره للكابتن أو dispatch.
3. اعرض/امسح الرمز الصحيح.
4. اختبر wrong/expired/replay ومحاولات متعددة.
5. ألغِ الطلب أثناء verification.
6. اختبر support reissue/override.
7. قارن Client/Partner/Control Panel والتدقيق.

## النتيجة التشغيلية النهائية

يكمل DSH الطلب مرة واحدة فقط بعد استيفاء proof policy والتحقق من recipient والحالة والحيازة والassignment. ينتج completion snapshot وtimeline وoutbox موثوقًا إلى WLT للآثار المالية اللاحقة. لا يعتمد الإكمال على UI success أو رفع ملف منفرد غير مربوط.

## تشخيص الحالة الحالية

### الموجود
- delivery proof completion handlers وPoD surfaces.
- WLT delivery collection/settlement boundaries.

### الناقص
- proof requirements matrix حسب order/mode/value/risk.
- recipient verification alternatives.
- atomic completion + outbox.
- rejected proof/review workflow.
- unknown-result recovery.
- cancellation/exception race rules.

### الخاطئ أو الممنوع
- complete بدون required proof.
- duplicate completion ينتج أثرًا ماليًا مكررًا.
- client/captain local success قبل readback.
- wrong recipient أو reused code.
- WLT call داخل transaction غير قابل للتعافي.

### التصحيح المطلوب
- command `SubmitDeliveryProof` ثم `CompleteDelivery` أو command مركب محكوم حسب التصميم.
- proof policy evaluation server-side.
- idempotent completion transaction + outbox.
- WLT consumes event/reference idempotently.
- إزالة completion shortcuts.

### الإضافات المطلوبة
- proof review queue للحالات عالية المخاطر.
- recipient exception/support workflow.
- receipt/readback للمستخدم.

## منطق التشغيل

الحالات: `PROOF_PENDING | SUBMITTED | UNDER_REVIEW | VERIFIED | COMPLETED | REJECTED`. completion يثبت proof set version وrecipient method وtime/location. إذا commit نجح وفقدت الاستجابة، GET order/proof يعيد completed. WLT effect مستقل idempotent بعد outbox.

## App Captain

- proof checklist ديناميكية، recipient selector/method، submit، verify status.
- يمنع complete إذا missing/invalid.
- unknown result screen لا يسمح إعادة عمياء.
- بعد completion تختفي actions والبيانات الحساسة.

## App Client

- completed status، receipt، proof summary المسموح، report issue window.
- لا يرى وسائط حساسة غير معتمدة.

## Control Panel

- proof review، requirements، evidence refs، location/time، decision audit.
- controls: approve/reject/request more info وفق permission؛ no force complete بلا evidence.
- WLT outbox/delivery status.

## العقود والبيانات

- proof set/version/requirements/result.
- completion unique order constraint.
- atomic order/custody/assignment completion + outbox.
- recipient verification secrets hashed/single-use.
- WLT event dedupe key.

## الاختبارات الآلية

- missing proof/wrong recipient.
- duplicate submit/complete.
- offline unknown result.
- cancellation/exception race.
- proof rejected/retry.
- outbox replay وWLT dedupe.
- post-completion access.

## التجريب اليدوي

2. اختبر missing/wrong/reused recipient proof.
3. افصل الشبكة بعد submit/commit.
4. اضغط complete من جهازين.
5. افتح high-risk review في Control Panel.
6. اختبر cancellation race.
7. تحقق من Client receipt وWLT event مرة واحدة.

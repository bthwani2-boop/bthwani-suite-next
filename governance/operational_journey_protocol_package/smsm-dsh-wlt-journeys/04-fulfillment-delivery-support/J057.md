## النتيجة التشغيلية النهائية

يتخذ الشريك قرارًا نهائيًا واحدًا قبل deadline خادمية: قبول أو رفض بسبب معتمد. أول transition صحيحة تفوز، وتظهر النتيجة نفسها للعميل والمشغل، ولا يقرر countdown محلي أو optimistic UI الحقيقة.

## التشخيص الجذري

- **الموجود:** Partner decision UI وOrder lifecycle.
- **الناقص:** transition contract، rejection taxonomy، server deadline، idempotency، timeout worker، unknown-result readback.
- **الخاطئ:** قبول/رفض بلا version، reason حر فقط، عضو خارج Store scope، local timer، قراران نهائيان.
- **التصحيح:** `DecidePartnerOrder` command واحد، DB time/version، unique final decision، timeout job idempotent.
- **الإضافة:** customer-safe reason، decision audit، operator monitoring، notification reconciliation.

## الأسطح

- App Partner: summary/deadline/Accept/Reject/reason/note/confirm، disabled أثناء command وبعد deadline، Verify Result عند timeout.
- App Client: `بانتظار المتجر` ثم accepted/rejected/timed-out مع خيارات تالية آمنة.

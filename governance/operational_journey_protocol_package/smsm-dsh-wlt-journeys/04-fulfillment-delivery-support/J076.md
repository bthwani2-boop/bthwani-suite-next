## النتيجة التشغيلية النهائية

تستهلك Notifications أحداثًا committed من المجالات المالكة، تطبق template/version/locale/channel/preferences والسياسة، ثم تسجل محاولة التسليم والنتيجة. لا تنشئ حقيقة تشغيلية أو مالية ولا تعتمد أي Surface على push payload كسلطة. كل رسالة قابلة للربط بالحدث والActor والنسخة دون تسريب PII.

## تشخيص الحالة الحالية

### الموجود
- notification routes/push endpoints/delivery audit وdevice tokens.
- producers متعددة في DSH/WLT/Identity/Workforce.

### الناقص
- event→template registry مركزي.
- template versioning/localization/RTL/fallback.
- channel eligibility/preferences/mandatory notices.
- dedupe/retry/dead-letter/provider failover.
- in-app inbox readback والcorrelation.
- redaction/secret/PII rules.

### الخاطئ أو الممنوع
- business state يتغير عند فتح/وصول notification.
- push payload يحمل بيانات كاملة أو secrets.
- template strings hardcoded في services/apps.
- duplicate event يرسل رسائل مكررة بلا policy.
- preference تعطل إشعارًا إلزاميًا أو تُتجاهل بلا سبب.

### التصحيح المطلوب
- notification registry وعقود event payload الحد الأدنى.
- render service بقوالب versioned.
- delivery state machine `QUEUED | SENT | DELIVERED | FAILED | RETRYING | DEAD_LETTERED | SUPPRESSED`.
- preference evaluation وmandatory classification.
- إزالة direct provider calls/templates الموزعة.

### الإضافات المطلوبة
- Control Panel template preview/test ضمن بيئة آمنة.
- provider health/retry dashboards.
- in-app notification center لكل Surface حيث معتمد.

## كل تطبيقات الموبايل

- notification center/list/detail/read/unread/delete local presentation إن كانت السياسة تسمح.
- deep link يتحقق من auth/object access والحالة الحالية، لا يثق بالpayload.
- badges من server counts.
- حالات notification expired/entity unavailable/permission revoked.
- إعدادات preferences واضحة مع mandatory notices غير قابلة للإيقاف ومفسرة.

## Control Panel

- template registry/version/locale/channel، delivery search، provider status، retry/dead letter.
- controls: preview، send test لجهة اختبار، retry safe، suppress policy، open source event.
- لا تعديل event أو business outcome.

## العقود والبيانات

- notification intent/event reference/dedupe key.
- template version وrendered payload hash.
- recipient/device/channel/preferences snapshot.
- delivery attempts/provider refs masked.
- retention/redaction/audit.

## الاختبارات الآلية

- duplicate event/dedupe.
- provider timeout/429/invalid token/failover.
- locale/RTL/template variable missing.
- preference mandatory/optional.
- revoked actor/device rotation.
- deep-link IDOR/entity deleted.
- PII/log payload scan.
- delayed notification after state change.

## التجريب اليدوي

1. ولّد أحداثًا من الرحلات الرئيسية لكل Actor.
2. تحقق من القالب واللغة والdeep link على كل تطبيق.
3. عطّل provider وجرّب retry/dead letter/failover.
4. غيّر preferences وmandatory classification.
5. أعد إرسال event نفسه.
6. ألغِ صلاحية Actor أو احذف entity قبل فتح notification.
7. راجع delivery audit/PII والcounts في Control Panel.

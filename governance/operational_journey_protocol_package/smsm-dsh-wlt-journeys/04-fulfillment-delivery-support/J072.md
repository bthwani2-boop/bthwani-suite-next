## النتيجة التشغيلية النهائية

يدير DSH Return/Refund Operational Case واحدة مرتبطة بالOrder/items والأدلة والمهل والقرارات، ثم يطلب من WLT تنفيذ Refund المعتمد. أي return logistics تمر workflow واضحة. لا يملك Surface أو DSH حقيقة المبلغ المسترد ولا ينشئ refund مباشرًا.

## تشخيص الحالة الحالية

### الموجود
- refunds handlers/controllers وWLT refund contracts.
- support/media/order evidence capabilities.

### الناقص
- eligibility window/item-level rules.
- case lifecycle وdecision roles.
- evidence requirements وreturn logistics.
- partial/multiple item policy.
- WLT financial readback/reconciliation.
- duplicate case/refund prevention.

### الخاطئ أو الممنوع
- App Client يستدعي WLT مباشرة.
- Operator يدخل refund amount بلا WLT policy.
- أكثر من active case لنفس scope.
- قبول evidence غير مربوط أو بعد expiry.
- case resolved قبل WLT result أو return completion حيث required.

### التصحيح المطلوب
- lifecycle `SUBMITTED | REVIEWING | NEEDS_INFO | APPROVED | REJECTED | RETURN_IN_PROGRESS | FINANCIAL_PENDING | RESOLVED`.
- item/order snapshot وeligibility decision version.
- Media refs وWLT request idempotency.
- generated UI actions/reasons.
- إزالة direct refund paths/types الموازية.

### الإضافات المطلوبة
- return pickup/drop-off flow عند الانطباق.
- decision explanation/customer status.
- reconciliation queue وSLA.

## App Client

- اختيار Order/items/reason، quantity، description، attachments، submit، reply، cancel request، track status.
- يعرض eligibility window والحدود قبل submit.
- حالات needs info/rejected/return required/financial pending/refunded/failed.
- amount النهائي من WLT readback فقط.

## App Partner

- يرى case الخاصة بمتجره، يقدم response/evidence، accepts return handoff إذا مطلوب.
- لا يقرر مبلغًا ماليًا.

## App Captain

- يظهر return logistics assignment منفصل فقط إذا أنشأته policy، مع custody/proof.

## Control Panel

- case review، evidence، item/order snapshots، partner response، WLT refs.
- controls request info/approve/reject/start return/reconcile/escalate.
- no raw bank/payment details.

## العقود والبيانات

- return case/items/decisions/version.
- unique active case scope وidempotency.
- evidence bindings/retention.
- WLT refund request/result references.
- return custody/logistics records عند الانطباق.

## الاختبارات الآلية

- duplicate request/refund.
- expired window/wrong item/quantity.
- evidence abuse/IDOR.
- approval race/stale version.
- WLT timeout/partial refund/readback.
- return required but skipped.
- partner/customer scope.

## التجريب اليدوي

1. قدم طلبًا كاملًا وجزئيًا.
2. اختبر window منتهية/item غير مؤهل.
3. أرفق أدلة صحيحة وخاطئة.
4. اطلب معلومات ورد من Client/Partner.
5. نفّذ return logistics عند الحاجة.
6. عطّل WLT وكرر approval.
7. راجع status/refs/audit على كل Surface.

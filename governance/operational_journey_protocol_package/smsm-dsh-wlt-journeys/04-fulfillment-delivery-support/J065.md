## النتيجة التشغيلية النهائية

ينقل DSH الحيازة من المتجر إلى الكابتن مرة واحدة بعد تحقق جاهزية الطلب وهوية الكابتن والمتجر والassignment وproof المطلوب. تنتقل Order وAssignment وcustody state ذرّيًا، وتظهر النتيجة فورًا في Partner/Captain/Control Panel.

## تشخيص الحالة الحالية

### الموجود
- store-captain handoff contract وpickup handlers/SLA alerts.
- Partner handoff وCaptain pickup contexts.

### الناقص
- custody state machine وproof policy.
- code/QR/device binding وexpiry.
- arrived/ready prerequisites.
- exception flow عند mismatch/damage/wait.
- atomic order/assignment/custody transition.
- evidence retention وsupport override.

### الخاطئ أو الممنوع
- pickup قبل `READY` أو من متجر خاطئ.
- Captain غير معين أو قديم يثبت الاستلام.
- code replay أو screenshot دائم.
- Partner يضغط handoff دون acknowledgement من Captain حسب policy.
- تحديث order وassignment في معاملات منفصلة غير قابلة للتعافي.

### التصحيح المطلوب
- custody command واحد مع locks/versions.
- proof generated/scanned/verified بشكل محكوم.
- strict actor/store/assignment binding.
- exception commands لا bypass.
- إزالة manual status buttons المتوازية.

### الإضافات المطلوبة
- arrival/wait timer وSLA.
- item/package count/condition acknowledgement.
- Control Panel handoff workbench وaudit.

## منطق التشغيل

الحالات: `READY | CAPTAIN_ARRIVED | VERIFICATION_PENDING | PICKED_UP | HANDOFF_EXCEPTION`. verify consumes proof، confirms both contexts، changes custody وorder/assignment versions، emits outbox. أي retry يعيد نفس result.

## App Partner

- ready queue، captain identity/vehicle masked المناسب، verification scanner/input، package checklist.
- controls: verify، report mismatch، not ready، request support.
- no completion بدون proof وassignment match.

## App Captain

- pickup context، store navigation، arrival، code/QR/acknowledge package، report issue.
- يظهر result/unknown recovery؛ actions disabled بعد pickup.

## Control Panel

- handoff queue، timers، proof status، mismatches، custody timeline.
- controls: investigate/override وفق approval/evidence، no raw secret display.

## العقود والبيانات

- custody record unique order/current holder/version.
- proof hash/expiry/consumed/attempts.
- transaction joins order/assignment/custody/outbox.
- store/captain object auth.
- audit/evidence/media refs.

## الاختبارات الآلية

- wrong captain/store/order.
- pickup before ready.
- proof replay/expiry/concurrent verify.
- reassign before verify.
- transaction fault injection.
- partner/captain unknown result.
- exception race/cancellation.

## التجريب اليدوي

1. جهز Order ووصل Captain الصحيح.
2. اختبر arrival والانتظار والproof الصحيح.
3. جرّب Captain/Store/Code خاطئًا.
4. أعد استخدام proof واضغط من الطرفين بالتزامن.
5. أعد الإسناد قبل handoff.
6. افصل الشبكة بعد commit.
7. راجع custody/order/assignment/audit على Control Panel.

## النتيجة التشغيلية النهائية

يظهر كل Order مؤهلة للشريك والمتجر الصحيح مرة واحدة في Inbox مرتبة ترتيبًا ثابتًا وقابلة للقراءة بعد reconnect. التنبيه وسيلة تسليم فقط ولا يخلق الطلب أو يغير حالته. كل عنصر يرتبط بـOrder version وstore scope ويعرض urgency/SLA والnext action الحقيقية.

## تشخيص الحالة الحالية

### الموجود
- Partner order inbox وalerts panels وruntime hooks في DSH frontend.
- Notifications routes/audit موجودة.
- Control Panel يملك live order workboards.

### الناقص
- query contract موحد للـInbox مع cursor ثابت وfilters server-side.
- dedupe بين event/inbox/push/in-app bell.
- read/unread/ack policy منفصلة عن Order state.
- multi-store/team scope وrevocation behavior.
- offline cache freshness وreconciliation.
- mapping لكل badge/action إلى حقول Runtime.

### الخاطئ أو الممنوع
- الاعتماد على push payload كحقيقة الطلب.
- تكرار card بسبب duplicate event.
- إخفاء Order عند فشل notification.
- إظهار طلب لموظف سُحبت صلاحيته أو لمتجر آخر.
- ترتيب client-side على صفحة ناقصة أو أرقام counts محلية.

### التصحيح المطلوب
- inbox projection في DSH قابلة لإعادة البناء.
- cursor/version/dedupe keys ثابتة.
- generated client واحد وcontroller واحد.
- فصل notification delivery status عن order lifecycle.
- إزالة inbox fixtures والـmock orders والمسارات المتوازية.

### الإضافات المطلوبة
- reconnect readback وstale indicator.
- diagnostics للـmissing/duplicate/delayed items.
- delivery correlation بين outbox وpush وin-app وreadback.

## منطق التشغيل

- Order event بعد commit ينشئ/يحدث inbox projection idempotently.
- الاستعلام يتحقق من partner/store/team scopes عند كل طلب.
- read/unread metadata شخصية ولا تغير حالة الطلب.
- تنبيه متأخر لا يعيد card قديمة أو يغير ترتيب الحقيقة.
- revoked member يفقد الوصول فورًا حتى لو cache محلية موجودة.

## App Partner

- تبويبات: `جديدة`، `قيد التنفيذ`، `تحتاج إجراء`، `مكتملة` حسب Product Truth.
- controls: search، filters، refresh، open order، mark notification read، retry.
- card: Order ID masked المناسب، store، created time، SLA countdown server-derived، status، payment/fulfillment readiness المسموحة.
- حالات: loading، empty، stale، offline cached، permission revoked، partial error.
- Bell badge من server count؛ الضغط يفتح العنصر الصحيح أو يعرض أنه لم يعد متاحًا.

## Control Panel

- partner/store inbox diagnostics وcounts وprojection lag.
- مقارنة order truth مع partner projection والتنبيهات.
- controls: replay safe projection event أو open incident؛ لا create order/card يدويًا.
- search by order/partner/store/correlation.

## العقود والبيانات

- GET inbox مع cursor/filters/sort/version.
- projection unique `(order_id, partner_id, store_id)`.
- notification delivery audit منفصل.
- team scopes من Identity/DSH owner context.
- indexes للـstatus/store/created_at دون cross-scope leakage.

## الاختبارات الآلية

- duplicate/out-of-order event.
- notification failure مع inbox success.
- revoked team member.
- multi-store scope.
- reconnect after offline.
- stable pagination/no duplicates.
- read/unread لا يغير order.
- projection rebuild parity.

## التجريب اليدوي

1. أنشئ Orders لمتجرين وشريكين.
2. تحقق من الظهور والترتيب والcounts.
3. أعد إرسال event وعطّل notification provider.
4. افصل App Partner ثم أعد الاتصال.
5. اسحب صلاحية عضو أثناء فتح Inbox.
6. اختبر كل filter/search/tab والpagination.
7. قارن Control Panel diagnostics مع order truth.

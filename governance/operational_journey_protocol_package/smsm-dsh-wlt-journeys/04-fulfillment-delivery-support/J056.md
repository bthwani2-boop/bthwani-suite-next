## النتيجة التشغيلية النهائية

تظهر كل Order مؤهلة للشريك والمتجر الصحيح مرة واحدة في Inbox، بترتيب ثابت وSLA و`allowedActions` من DSH. التنبيه وسيلة تسليم لا مصدر حقيقة؛ فشل Push لا يخفي Order، وإعادة الحدث لا تنشئ بطاقة أو تنبيهًا مكررًا.

## التشخيص: الموجود والناقص والخاطئ والتصحيح والإضافة

- **الموجود:** Partner order inbox، alerts، order events، notification delivery.
- **الناقص:** projection contract، stable cursor، dedupe، read/unread policy، team/store scope، reconnect reconciliation.
- **الخاطئ الممنوع:** الاعتماد على Push payload، counts محلية، duplicate cards، ظهور Order بعد revoke أو لمتجر آخر.
- **التصحيح:** projection فريدة `(order, partner, store)`، cursor/version، generated client، server filters، event/inbox dedupe.
- **الإضافات:** delivery correlation، stale indicator، projection rebuild، missing/duplicate diagnostics.

## المنطق التشغيلي والأسطح

- Order committed → outbox → inbox projection idempotent → notification intent → App Partner readback.
- App Partner يعرض tabs الجديدة/تحتاج إجراء/قيد التنفيذ/المكتملة وفق Product Truth، مع search/filter/refresh/open Order وread state منفصلة.
- permission أو team membership تعاد عند كل query؛ cache لا تمنح وصولًا بعد revoke.

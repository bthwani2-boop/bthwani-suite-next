## النتيجة التشغيلية النهائية

يستطيع Operator مخول assign/reassign ضمن حالات مسموحة مع سبب ومراجعة الأهلية، دون overwrite صامت. الكابتن القديم يفقد assignment فورًا ويُخطر، والجديد يرى الحقيقة نفسها. العميل والشريك يريان أثرًا تشغيليًا مناسبًا دون كشف تفاصيل داخلية.

## تشخيص الحالة الحالية

### الموجود
- dispatch assignment governance وControl Panel command center.
- Captain current assignment وclient tracking.

### الناقص
- manual assignment permission/reason taxonomy.
- transition rules قبل/بعد pickup.
- concurrency مع auto-dispatch.
- partial notification failure compensation.
- old captain revocation/readback.
- approval requirements للحالات الحساسة.

### الخاطئ أو الممنوع
- اختيار Captain من قائمة غير معاد التحقق منها.
- overwrite assignment row دون timeline.
- reassign بعد custody transition بلا rescue workflow.
- old Captain يحتفظ بالبيانات/actions.
- operator stale screen يفوز دون version check.

### التصحيح المطلوب
- command `ManualAssign/Reassign` مع order/assignment version.
- eligibility recheck transactionally.
- revoke old assignment + create new + timeline/outbox.
- state restrictions وربط post-pickup بـJ070 rescue.
- إزالة direct DB/admin shortcuts.

### الإضافات المطلوبة
- candidate comparison/why excluded.
- confirmation يعرض الأثر على ETA/custody.
- notification reconciliation.

## منطق التشغيل

- قبل pickup: reassign مسموح وفق policy والسبب.
- بعد pickup: لا reassign عادي؛ يتطلب rescue/custody transfer.
- auto/manual races تحسم بقفل/version وsingle active assignment.
- notification failures لا تعيد transaction لكن تسجل retry/incident.
- old token/actions تفشل فورًا.

## Control Panel

- candidate list مع eligibility freshness/reasons.
- controls: assign، reassign، cancel offer، open rescue.
- reason required، confirmation، approval عند policy.
- displays old/new captain، versions، notification status، audit.

## App Captain

- old captain: assignment removed banner، actions disabled، sensitive data cleared.
- new captain: assignment appears مع acknowledgement.
- unknown/reconnect readback.

## App Client

- tracking قد يعرض `تم تحديث المندوب` دون تفاصيل داخلية.
- ETA refresh وstale indicator.

## App Partner

- assignment summary updated؛ no candidate details.

## العقود والبيانات

- assignment version/active uniqueness.
- reassignment event يحمل old/new/reason/operator.
- scoped tokens/reads invalidate old captain.
- notification outbox/retry.
- audit append-only.

## الاختبارات الآلية

- stale operator view.
- manual vs auto assign race.
- two operators reassign.
- ineligible candidate.
- after-pickup reassign blocked.
- old captain action after revocation.
- notification partial failure.
- cross-surface readback.

## التجريب اليدوي

1. عيّن Captain يدويًا قبل auto assignment.
2. اختبر race مع auto-dispatch ومشغل ثانٍ.
3. أعد الإسناد قبل pickup.
4. حاول بعد pickup وتحقق من توجيه Rescue.
5. افصل أحد التطبيقات أثناء reassign.
6. تحقق من مسح بيانات الكابتن القديم.
7. راجع audit/notifications/ETA على الأسطح.

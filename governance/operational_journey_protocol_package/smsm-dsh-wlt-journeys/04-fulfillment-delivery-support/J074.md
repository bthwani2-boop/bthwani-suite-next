## النتيجة التشغيلية النهائية

يوفر دعمًا scoped للشريك حول store/team/orders/catalog/operations والمرجع المالي عبر DSH facade فقط. لا يستطيع Operator انتحال الشريك أو الوصول لشريك آخر، ولا تظهر بيانات بنكية أو Ledger كاملة. كل إجراء دعم command محكوم ومدقق.

## تشخيص الحالة الحالية

### الموجود
- Partner support routes/runbook وPartner Hub.
- WLT finance references وmasking boundaries.

### الناقص
- partner support categories/routing.
- scope enforcement partner/store/team per ticket.
- governed support session/impersonation alternative.
- financial reference masking matrix.
- escalation to catalog/finance/identity owners.
- audit لكل sensitive access/action.

### الخاطئ أو الممنوع
- Operator يستخدم token الشريك أو يغيّر context يدويًا.
- raw bank/payment/ledger data في DSH support.
- cross-partner search/ticket.
- support action يعدل catalog/order/finance مباشرة.
- duplicate escalation/cases.

### التصحيح المطلوب
- partner support aggregate scoped بالoperator context.
- links/commands للdomains المالكة بدل direct writes.
- read-only masked WLT references.
- support session policy مع banner/audit إن كانت مطلوبة.
- remove raw-finance fields/legacy support routes.

### الإضافات المطلوبة

- Control Panel partner context header ثابت.
- escalation lifecycle/status readback.

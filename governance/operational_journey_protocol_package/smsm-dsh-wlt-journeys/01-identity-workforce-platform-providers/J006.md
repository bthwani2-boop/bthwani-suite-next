```yaml
owner: Identity
actors: [OPERATOR, CUSTOMER, PARTNER, CAPTAIN, FIELD]
surfaces: [control-panel, app-client, app-partner, app-captain, app-field]
dependencies: [FOUNDATION-00, J005]
assessment_status: NOT_ASSESSED
closure_status: OPEN
```

## النتيجة التشغيلية

جلسة آمنة قابلة للتحديث والدوران والإبطال، مع اكتشاف reuse، وخروج من الجهاز الحالي أو كل الأجهزة، واستمرار صحيح عند انقطاع الشبكة دون إبقاء صلاحية منتهية.

## الحالة الحالية

| التصنيف | الحكم |
|---|---|
| الموجود | access/refresh/logout ومخازن جلسة متوقعة في الأسطح |
| غير المثبت | token-family model، rotation atomicity، reuse detection، all-device revoke، CSRF/cookie flags، SecureStore cleanup |
| الخاطئ المحتمل | refresh متكرر يصدر عدة tokens، logout UI فقط، token في AsyncStorage أو logs، session تبقى بعد Actor suspension |
| التصحيح | عائلة refresh واحدة، rotate-and-revoke ذرية، middleware يربط Actor/device/session version |
| الإضافات | session management UI، device labels، security alerts، status lookup |

## الأسطح

### Control Panel

- صفحة جلسات Actor: الجهاز، السطح، وقت الإنشاء، آخر استخدام، الحالة، IP/metadata المسموح.
- أزرار `إبطال جلسة` و`إبطال جميع الجلسات` مع reason وconfirmation.
- لا يعرض raw tokens.
- بعد الإبطال يعاد readback وتظهر revoked status.

### التطبيقات الأربعة

- bootstrap يقرأ session بشكل آمن.
- refresh يحدث في interceptor/controller واحد، لا من كل شاشة.
- concurrent 401s تشترك في refresh واحد.
- logout يمسح التخزين بعد نجاح/قبول الإبطال وفق السياسة، ويمنع mutations queued القديمة.
- عند reuse/compromise تظهر شاشة session revoked وتطلب login جديدًا.

## الحالات والتحكمات

| الحالة | ما يظهر | الفعل المتاح |
|---|---|---|
| ACTIVE | التطبيق الطبيعي | logout/manage devices |
| REFRESHING | progress غير حاجب | لا نقرات مكررة |
| EXPIRED | login required | إعادة المصادقة |
| REVOKED | سبب واضح | login جديد |
| COMPROMISED | تنبيه أمني | revoke all/login |
| OFFLINE_VALID_CACHE | بيانات cached محدودة | لا mutation حساسة بلا تحقق |

## التقنية

- refresh token hash أو rotation records، لا raw persistence server-side.
- unique token-family/version وreuse marker.
- access TTL قصير وrefresh TTL وسياسة device binding.
- cookies: HttpOnly/Secure/SameSite وCSRF عند الانطباق.
- mobile: SecureStore فقط.
- audit لكل login/refresh/revoke/reuse.
- session revocation ينسجم مع J003 وJ007.

## الاختبارات

- concurrent refresh من عدة requests.
- reuse token قديم.
- logout current/all مع جهازين.
- Actor suspend أثناء refresh.
- offline expiry/reconnect.
- cookie flags/CSRF وmobile storage scan.
- app kill أثناء rotation.

## التجريب اليدوي

1. سجّل الدخول بجهازين لكل نوع تطبيق.
2. اترك access token ينتهي وشغّل requests متزامنة.
3. أعد استخدام refresh قديم عمدًا.
4. نفّذ logout current ثم all من Control Panel.
5. جرّب reconnect بعد offline طويل.
6. افحص التخزين المحلي والlogs وNetwork.

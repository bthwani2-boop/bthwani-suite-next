# J010 — الأشخاص والملف المهني

```yaml
owner: Workforce
identity_reference: actor_id
actors: [OPERATOR, PARTNER, CAPTAIN, FIELD]
surfaces: [control-panel, app-partner, app-captain, app-field]
control_panel_sections: [hr, administration, partners, operations]
dependencies: [FOUNDATION-00, J009]
assessment_status: NOT_ASSESSED
closure_status: OPEN
```

## النتيجة التشغيلية

ملف مهني واحد لكل Actor يملك بيانات العمل والجاهزية والوثائق والتكليفات المرجعية، بينما تبقى المصادقة والهاتف والأدوار والجلسات في Identity.

## الحالة الحالية

| التصنيف | الحكم |
| --- | --- |
| الموجود | Workforce service ومفاهيم profiles/readiness موجودة |
| غير المثبت | جداول profile الفعلية لكل دور، uniqueness، self-edit allowlist، media linkage، readiness enforcement |
| الخاطئ المحتمل | نسخ phone/roles في Workforce أو DSH، profile داخل التطبيق، login بلا profile gate، PII مكشوفة |
| التصحيح | actor_id FK/reference واحد، role-specific extensions، state machine، API موحد |
| الإضافات | documents status، supervisor/shift/city/hire date، audit وretention |

## Control Panel

- قائمة الأشخاص مع employee code/name/role/employment/profile status/supervisor/city.
- create/edit/suspend/terminate وفق الصلاحية.
- tabs: overview، employment، assignments، documents، audit.
- Identity fields تظهر read-only ومقنعة عند الحاجة.
- لا يمكن إنشاء profile بلا Actor أو إنشاء Actor ضمنيًا خارج J011.

## أقسام لوحة التحكم المرتبطة — التحديد التنفيذي الإلزامي

| القسم والمسار | الصفحة/التبويب | ما يظهر | التحكمات | الحالات والصلاحيات | الربط والتجريب |
| --- | --- | --- | --- | --- | --- |
| **الموارد البشرية** `/dsh/hr` | People list وPerson/Captain/Field Detail: `نظرة عامة`، `التوظيف`، `التكليفات`، `المستندات`، `التدقيق` | employee code/name/type/status/supervisor/shift/city/hire date/profile readiness/document refs/version | create/edit allowed fields، suspend/terminate، request document، assign supervisor؛ reason/confirmation/readback | HR permissions field-level؛ missing/incomplete/review/active/suspended/terminated/conflict/unknown | Workforce generated APIs؛ أنشئ كل profile، جرّب duplicate code/self-edit/termination/concurrency |
| **الإدارة** `/dsh/administration` | Actor Detail → `Workforce reference` | actor status/ID والlink إلى person؛ auth fields فقط في الإدارة | `فتح ملف الموظف`؛ لا تعديل employment أو نسخ HR fields | Identity read permission وHR link permission؛ missing/orphan reference | قارن Actor/Profile وتأكد من عدم duplication أو implicit creation |
| **الشركاء** `/dsh/partners/[partnerId]` | Partner team/member detail → `الملف المهني` | Workforce reference وحالة الجاهزية للعضو فقط | open profile/request provisioning؛ لا HR mutation عام من Partner Detail | partner scope + HR limited permission | اختبر عضو من Partner آخر وprofile ناقص/موقوف |
| **العمليات** `/dsh/operations` | Assignment/Order detail → `جاهزية العامل` | profile/employment/readiness blocker masked، الوثائق المطلوبة status فقط | actions التشغيلية disabled من allowedActions؛ link إلى HR للمخول | operations لا تعدل HR؛ active/incomplete/suspended/terminated/stale | أنهِ employment أثناء assignment وتحقق من رفض الأفعال والreadback |

Finance لا يقرأ الملف المهني إلا Actor reference المصرح؛ Dashboard يعرض counts مشتقة فقط ولا ينشئ حقول HR موازية.

## App Partner/Captain/Field

- صفحة الملف تعرض البيانات المسموحة فقط.
- self-completion للحقول المعتمدة مثل photo/emergency contact/language.
- حقول employment/supervisor/status read-only.
- حالات missing/incomplete/review/active/suspended/terminated واضحة.
- لا وصول للعمليات قبل gate المناسب.

## البيانات والمنطق

- unique profile per actor/type وفق model.
- employee_code uniqueness ونطاقه محدد.
- effective employment status وtermination reason.
- document refs إلى Media، لا file blobs.
- PII encryption/retention/audit.
- update versioning وfield-level authorization.

## الاختبارات

- duplicate actor profile/employee code.
- missing actor.
- self-edit لحقل محظور.
- support/operator masking.
- terminate أثناء active session/assignment.
- document expiry/readiness effect.
- concurrent profile update.
- كل تبويب وزر وحقل في HR مربوط بحقل مالكه واختبار سلبي.

## التجريب اليدوي

1. أنشئ profile لكل Partner/Captain/Field من `/dsh/hr`.
2. جرّب duplicate employee code وActor غير موجود.
3. عدّل self-service fields من التطبيق.
4. حاول تعديل employment status من التطبيق.
5. علّق/أنه العمل وتحقق من الإدارة والشركاء والعمليات وكل تطبيق.
6. افحص Identity وWorkforce للتأكد من عدم تكرار الحقائق.

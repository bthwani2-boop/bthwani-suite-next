# J010 — الأشخاص والملف المهني

```yaml
owner: Workforce
identity_reference: actor_id
actors: [OPERATOR, PARTNER, CAPTAIN, FIELD]
surfaces: [control-panel, app-partner, app-captain, app-field]
dependencies: [FOUNDATION-00, J009]
assessment_status: NOT_ASSESSED
closure_status: OPEN
```

## النتيجة التشغيلية

ملف مهني واحد لكل Actor يملك بيانات العمل والجاهزية والوثائق والتكليفات المرجعية، بينما تبقى المصادقة والهاتف والأدوار والجلسات في Identity.

## الحالة الحالية

| التصنيف | الحكم |
|---|---|
| الموجود | Workforce service ومفاهيم profiles/readiness موجودة |
| غير المثبت | جداول profile الفعلية لكل دور، uniqueness، self-edit allowlist، media linkage، readiness enforcement |
| الخاطئ المحتمل | نسخ phone/roles في Workforce أو DSH، profile داخل التطبيق، login بلا profile gate، PII مكشوفة |
| التصحيح | actor_id FK/reference واحد، role-specific extensions، state machine، API موحد |
| الإضافات | documents status، supervisor/shift/city/hire date، audit وretention |

## Control Panel

- قائمة الأشخاص مع employee code/name/role/employment/profile status/supervisor/city.
- create/edit/suspend/terminate وفق الصلاحية.
- tabs: overview، employment، assignments، documents، audit.
- Identity fields تظهر read-only ومقنعة عند الحاجة.
- لا يمكن إنشاء profile بلا Actor أو إنشاء Actor ضمنيًا خارج J011.

## App Partner/Captain/Field

- صفحة الملف تعرض البيانات المسموحة فقط.
- self-completion للحقول المعتمدة مثل photo/emergency contact/language.
- حقول employment/supervisor/status read-only.
- حالات missing/incomplete/review/active/suspended/terminated واضحة.
- لا وصول للعمليات قبل gate المناسب.

## البيانات والمنطق

- unique profile per actor/type وفق model.
- employee_code uniqueness ونطاقه محدد.
- effective employment status وtermination reason.
- document refs إلى Media، لا file blobs.
- PII encryption/retention/audit.
- update versioning وfield-level authorization.

## الاختبارات

- duplicate actor profile/employee code.
- missing actor.
- self-edit لحقل محظور.
- support/operator masking.
- terminate أثناء active session/assignment.
- document expiry/readiness effect.
- concurrent profile update.

## التجريب اليدوي

1. أنشئ profile لكل Partner/Captain/Field.
2. جرّب duplicate employee code وActor غير موجود.
3. عدّل self-service fields من التطبيق.
4. حاول تعديل employment status من التطبيق.
5. علّق/أنه العمل وتحقق من كل Surface.
6. افحص Identity وWorkforce للتأكد من عدم تكرار الحقائق.

## الإغلاق

`professional_profiles_per_actor=1; duplicated_identity_fields=0; unauthorized_self_edits=0; pii_exposure=0; readiness_profile_gate=PASS; evidence_sha=CURRENT_SHA`.

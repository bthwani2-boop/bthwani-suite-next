## النتيجة التشغيلية

Orchestration موثوق ينشئ Workforce person ثم Identity Actor ثم role/assignment المطلوب، أو يتعافى/يعوض دون ترك orphan في أي خدمة. لا يجوز أن ينفذ Control Panel سلسلة طلبات مستقلة بلا correlation وحالة قابلة للاستئناف.

## الحالة الحالية

- **الموجود:** Identity وWorkforce endpoints ومفاهيم activation/profile.
- **غير المثبت:** orchestrator واحد، durable provisioning case، compensation، idempotency عبر الخدمات.
- **الخاطئ المحتمل:** profile بلا Actor، Actor بلا profile، duplicate عند retry، UI يعتبر النجاح بعد أول خدمة فقط.
- **التصحيح:** provisioning case/state machine وservice identities وصلاحيات محددة وresult lookup.
- **الإضافات:** correlation، step status، retry/compensate controls، orphan reconciliation job.

## Control Panel

- Wizard واضح: نوع الشخص → البيانات المهنية → Actor identity → الدور → assignments → مراجعة → تنفيذ.
- كل خطوة تعرض validation ومصدر الحقيقة.
- شاشة progress تعرض `Workforce created`, `Actor created`, `Role assigned`, `Scope assigned`, `Activation ready`.
- إذا فشلت خطوة: لا يعرض نجاحًا كاملاً؛ يقدم `استئناف` أو `تعويض` حسب السياسة.
- زر submit واحد مع idempotency وunknown-result lookup.

## التطبيقات

- لا تنشئ الشخص أو Actor.
- بعد التفعيل تقرأ نتيجة provisioning؛ تعرض `PROFILE_INCOMPLETE` أو `ASSIGNMENT_MISSING` بدل إنشاء بيانات محلية.
- App Partner/Captain/Field لا تتجاوز حالة partial provisioning.

## نموذج الحالات

`DRAFT → VALIDATED → WORKFORCE_CREATED → ACTOR_CREATED → ROLE_ASSIGNED → SCOPE_ASSIGNED → READY_FOR_ACTIVATION → COMPLETED`، مع `FAILED_RETRYABLE`, `FAILED_COMPENSATION_REQUIRED`, `COMPENSATED`.

## التقنية

- service-to-service auth منفصلة.
- idempotency key على provisioning case.
- كل خطوة تحفظ external reference/version.
- compensation لا تحذف تاريخًا ماليًا/تشغيليًا؛ تستخدم deactivation/rollback مع audit.
- reconciliation job يكتشف orphans.
- UI لا ينسق الحقيقة بنفسه.

## الاختبارات

- Identity failure بعد Workforce commit والعكس.
- duplicate submit/response loss.
- compensation failure.
- stale case resume.
- permission/scope escalation.
- conflicting employee code/phone.

## التجريب اليدوي

1. زوّد Field وCaptain وPartner employee.
2. عطّل Identity في منتصف التنفيذ.
3. أعد تشغيل الصفحة واضغط استئناف.
4. كرر submit وفقد الرد بعد commit.
5. افحص كلا الخدمتين وreconciliation queue.
6. سجّل الدخول وتحقق من gate الصحيح.

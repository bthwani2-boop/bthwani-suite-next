# J012 — جاهزية الكابتن

```yaml
owners: [Workforce, DSH, WLT]
actors: [OPERATOR, CAPTAIN]
surfaces: [control-panel, app-captain]
dependencies: [FOUNDATION-00, J011]
assessment_status: NOT_ASSESSED
closure_status: OPEN
```

## النتيجة التشغيلية

لا يدخل الكابتن إلى التوفر أو العروض أو التنفيذ قبل اكتمال Actor/profile/documents/assignment/employment status، مع فصل الأهلية المهنية عن الأهلية المالية القادمة من WLT.

## الحالة الحالية

| الطبقة | المطلوب إثباته |
|---|---|
| Workforce | profile/document/employment readiness rules |
| DSH | assignment/affiliation/area readiness |
| WLT | eligibility decision/reasons وTTL |
| App Captain | reason-coded gate بلا حساب محلي |
| Control Panel | checklist موحد وreadback |

الخطر: flag محلي `isReady`, خلط debt مع document expiry، أو السماح بعد revoke/offline.

## Control Panel

- صفحة Captain تعرض checklist مستقلة: Identity active، profile complete، employment active، documents valid، assignment active، affiliation، area، financial eligibility.
- كل بند يعرض owner وreason وeffective time.
- أزرار المعالجة تذهب إلى owner الصحيح؛ لا يعدل Control Panel حالة مجمعة يدويًا.
- history للتغييرات والحظر.

## App Captain

- عند الدخول تعرض شاشة readiness قبل tabs التشغيلية.
- كل سبب له نص وخطوة تالية: إكمال profile، تجديد وثيقة، انتظار assignment، التواصل مع الإدارة، تسوية مالية.
- لا يظهر Toggle availability أو Offers إذا أي شرط حرج غير متحقق.
- عند revoke أثناء الجلسة يتحول فورًا إلى blocked ويحذف queued privileged actions.
- عند WLT unavailable يظهر `ELIGIBILITY_UNAVAILABLE` لا eligible افتراضيًا.

## التقنية

- readiness response مركب من مصادر حاكمة مع reason codes وsource/version/freshness.
- لا يخزن DSH balance/threshold؛ projection decision قصيرة العمر فقط.
- كل dispatch mutation تعيد التحقق، لا تعتمد على شاشة الدخول.
- events تبطل cache عند document/assignment/employment/financial change.

## الاختبارات

- profile incomplete/document expired/no assignment.
- Actor suspended/employment terminated.
- financial blocked وWLT unavailable/stale decision.
- revoke أثناء active offer.
- offline reconnect بعد تغيير readiness.
- forged local ready state.

## التجريب اليدوي

1. اختبر كل سبب حظر منفردًا ومجتمعًا.
2. تحقق مما يظهر في Control Panel وApp Captain.
3. أصلح كل بند من owner الصحيح وراقب الانتقال.
4. عطل WLT ثم أعده.
5. ألغِ assignment أثناء offline.
6. حاول استدعاء offer/availability API مباشرة.

## الإغلاق

`captain_readiness_bypasses=0; local_readiness_or_financial_calculations=0; reason_ownership=PASS; revoke_propagation=PASS; all_gate_states_visible=PASS; evidence_sha=CURRENT_SHA`.

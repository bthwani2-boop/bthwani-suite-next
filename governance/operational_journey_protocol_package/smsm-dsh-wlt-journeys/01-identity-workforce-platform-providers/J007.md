## النتيجة التشغيلية

ربط device installation وPush token بالActor والسطح والجلسة بصورة قابلة للدوران والإبطال، مع إزالة token غير الصالح ومنع انتقاله إلى Actor آخر.

## الحالة الحالية

- **الموجود:** تسجيل Push متوقع في تطبيقات Expo، ومفاهيم devices/sessions.
- **غير المثبت:** مصدر device identity، token rotation، logout cleanup، provider invalid-token handling، retention.
- **الخاطئ المحتمل:** token واحد مربوط بأكثر من Actor، إرسال بعد logout، orphan tokens، device ID مولد بطريقة غير مستقرة أو متتبعة بلا حاجة.
- **التصحيح:** unique active binding، versioned token replacement، session ownership، provider feedback loop.
- **الإضافات:** صفحة إدارة الأجهزة، security notification، cleanup job، metrics.

## الأسطح

### التطبيقات

- تطلب permission في سياق مفهوم، لا عند أول frame بلا شرح.
- تعرض enabled/denied/permanently-denied/provider-unavailable states.
- بعد login تسجل token للActor الحالي والسطح.
- بعد logout أو تبديل Actor تلغي binding القديم قبل إنشاء الجديد.
- عند token rotation أو reinstall تحدّث السجل idempotently.

### Control Panel

- قائمة أجهزة Actor مع surface/platform/app version/last seen/status.
- revoke device action بصلاحية واضحة.
- لا يعرض push token الخام.
- يمكن رؤية سبب invalidation ووقت آخر تسليم دون تفاصيل حساسة.

## التقنية

- device installation ID منفصل عن hardware fingerprint غير الضروري.
- token مشفر/محجوب في logs والواجهات.
- unique `(provider, token)` وactive binding واحد.
- notifications consumer يعالج `invalid/unregistered` ويعطل السجل.
- logout/revoke event يزيل eligibility للتسليم.
- retry لا يعيد إرسال رسالة حساسة لجهاز revoked.

## الاختبارات

- same token مع Actorين.
- logout/login Actor آخر.
- reinstall وrotation.
- provider invalid-token response.
- duplicate registration.
- revoked session/device delivery.
- permission denied ثم enabled من settings.
- Control Panel masking/action/route binding.

## التجريب اليدوي

1. سجّل جهازين للActor نفسه وتحقق من التسليم لكليهما.
2. نفّذ logout من جهاز واحد، ثم أرسل إشعارًا.
3. بدّل الحساب وأعد تسجيل token.
4. أعد تثبيت التطبيق أو حاكي rotation.
5. ألغِ الجهاز من `/dsh/administration`.
6. راقب provider/cleanup في `/dsh/platform` والتنبيه في Dashboard.
7. تحقق من عدم التسليم للأجهزة الملغاة وعدم وجود token خام.

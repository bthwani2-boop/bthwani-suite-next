## النتيجة التشغيلية

اشتقاق platform/operator/partner/store/area/actor/object scope من هوية وتكليفات موثوقة، ثم تطبيقه داخل query وtransaction وcache. لا تثق الخدمات في `partnerId`, `storeId`, `actorId` أو headers يرسلها العميل كسلطة.

## الحالة الحالية

- **الموجود:** trusted context ومفاهيم scopes متفرقة في Identity/Workforce/DSH/WLT.
- **الناقص:** مصفوفة كل operation إلى scope/object predicate، وفحوص cache/search/event consumers.
- **الخاطئ المحتمل:** generic tenant context، header authority، query بلا owner predicate، service identity واسعة، cache key غير scoped.
- **التصحيح:** context resolver مركزي لكل خدمة، repository predicates، transaction recheck، service auth.
- **الإضافات:** IDOR suite، scope-change events، diagnostics correlation.

## الأسطح

### Control Panel

- يظهر scope الفعال في أعلى الصفحة: platform/partner/store/area.
- selectors لا تمنح صلاحية؛ تعرض فقط scopes المسموحة من الخادم.
- deep link إلى object خارج scope يعرض forbidden لا not-found مضللًا حسب سياسة الخصوصية.

### التطبيقات

- لا تحفظ authority IDs كحقائق دائمة؛ ترسل object reference فقط.
- عند تبدل assignment أو membership، caches وnavigation تتحدث.
- queued offline mutation يعاد تفويضها عند reconnect.
- لا يوجد header يدوي مثل `x-tenant-id` أو fallback scope.

## التقنية

- subject/service identity موثوق من token/mTLS/service credential.
- context resolver يجلب assignments الفعالة ويثبت version.
- كل repository query حساس يضم ownership predicate.
- mutations تعيد التحقق داخل transaction لمنع TOCTOU.
- cache/search keys تشمل scope/version.
- events تحمل canonical refs لا authority قابلة للتزوير.
- WLT يستقبل DSH service identity + actor/object context الموثوق.

## الاختبارات

- تبديل IDs في path/query/body.
- forged headers.
- assignment ينتهي بين check/write.
- cache bleed بين partner/store.
- service identity زائدة الصلاحية.
- offline action after revoke.
- search/export cross-scope.
- route/tab/filter/export/action isolation لكل قسم مذكور.

## التجريب اليدوي

1. أنشئ Actors في partner/store/area مختلفة.
2. افتح كل قسم مذكور وdeep links وبدّل IDs يدويًا.
3. ألغِ assignment أثناء صفحة مفتوحة وأثناء offline.
4. راقب API/DB/cache للتأكد من predicates.
5. جرّب service-to-service call بscope ناقص وزائد.
6. تحقق من الرسالة المرئية وعدم تسريب object data.

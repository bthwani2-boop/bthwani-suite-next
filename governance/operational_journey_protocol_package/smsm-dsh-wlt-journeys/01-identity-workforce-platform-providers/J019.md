## النتيجة التشغيلية

كل اتصال خارجي يستخدم TLS وtimeout budget وretry classification وcircuit breaker وتوقيع webhook وresult reconciliation، دون retry storm أو نجاح كاذب.

## الحالة الحالية

- يلزم جرد كل HTTP/provider clients وwebhooks وtimeouts/retries.
- الخطر: calls بلا timeout، retry لكل 4xx/5xx، unsigned webhook، duplicate late result، breaker محلي غير مرئي.
- المطلوب: adapter policies موحدة، idempotency/provider reference، signature rotation، metrics.

## Control Panel

- provider connection status وbreaker state `CLOSED/OPEN/HALF_OPEN`.
- last success/failure/latency/error class.
- controls محدودة: test، maintenance، authorized retry/reconcile.
- لا زر يعيد financial/provider mutation عمياء؛ يبدأ lookup/reconcile أولًا.

## التطبيقات

- تعرض degraded/unavailable/pending/unknown states حسب feature.
- retry UI يلتزم classification وbackoff.
- لا تعرض provider raw errors أو IDs الحساسة.
- unknown financial result لا يعاد submit قبل lookup.

## التقنية

- connect/read/overall timeouts.
- retry فقط للأخطاء المؤقتة والعمليات الآمنة/idempotent.
- breaker thresholds وhalf-open probes.
- webhook signature/timestamp/replay protection.
- inbox deduplication وlate/out-of-order handling.
- correlation من Surface إلى provider.

## الاختبارات

- DNS/TLS/timeout/429/5xx/4xx.
- retry exhaustion وstorm prevention.
- breaker open/half-open/recovery.
- invalid/replayed/rotated webhook signatures.
- provider success بعد local timeout.
- duplicate webhook.

## التجريب اليدوي

1. حاكي كل فئة فشل عبر simulator.
2. راقب breaker في Control Panel.
3. نفّذ retry من Surface وتأكد من عدم storm.
4. أرسل webhook مكررًا وخاطئ التوقيع ومتأخرًا.
5. اختبر unknown result ثم reconcile.
6. تحقق من logs/metrics والتعافي.

## الإغلاق

`unbounded_provider_calls=0; unsafe_retries=0; unsigned_or_replayed_webhooks=0; duplicate_provider_effects=0; breaker_recovery=PASS; evidence_sha=CURRENT_SHA`.

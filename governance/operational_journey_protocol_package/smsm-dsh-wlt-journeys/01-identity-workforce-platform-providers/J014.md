## النتيجة التشغيلية

مصدر واحد لتكليف supervisor/shift/area/partner/store/department بمدد فعالة وتاريخ كامل، مع منع overlaps غير المعتمدة واستهلاك موحد من كل الخدمات والأسطح.

## الحالة الحالية

- الجداول/واجهات assignments موجودة جزئيًا أو مفهوميًا؛ يلزم جرد فعلي.
- الخطر: assignment في Workforce وآخر في DSH، ranges متداخلة، timezone غير محدد، UI يعرض current من local clock.
- المطلوب: canonical assignment model، range constraints، query `effective-at`, events، negative guard ضد نسخ موازية.

## Control Panel

- calendar/list/history مع filter actor/type/scope/status/date.
- create/edit/end وليس delete للتاريخ الحي.
- conflict preview قبل الحفظ.
- confirmation عند إنهاء assignment نشط يوضح العمليات المتأثرة.
- readback يعرض effective range والنسخة.

## أقسام لوحة التحكم المرتبطة — التحديد التنفيذي الإلزامي

| القسم والمسار | الصفحة/التبويب | البيانات | التحكمات | الحالات والصلاحيات | الاختبار |
|---|---|---|---|---|---|
| **الموارد البشرية** `/dsh/hr` | `التكليفات` Calendar/List وPerson Detail | type، actor، supervisor، shift، area/partner/store/department، start/end/timezone/version/history | create/edit future/end active، conflict preview، filter/sort/page؛ لا delete history | assignment permissions؛ current/upcoming/expired/conflict/stale/unknown | overlap، boundary، concurrent create/end، timezone واختبار readback |
| **الشركاء** `/dsh/partners/[partnerId]` و`/stores` | Team/Store assignments | assignments المتعلقة بالشريك والمتجر فقط، effective status وsource HR | request/assign/end إذا مخول عبر نفس Workforce command؛ لا جدول موازٍ | partner/store scope؛ cross-partner denied | أنشئ من HR ثم Partner page، جرّب overlap ومتجر آخر |
| **العمليات** `/dsh/operations` | Assignment/Order/Task detail | effective assignment snapshot/version وblocker عند انتهاء النطاق | لا تعديل assignment؛ actions تعيد التحقق، link إلى HR | operations object auth؛ expired/stale/revoked/conflict | أنهِ assignment أثناء operation ثم استدع action من stale page |

Dashboard/Analytics تعرض counts وSLA مشتقة مع freshness فقط؛ لا Calendar أو write path آخر.

## App Partner/Captain/Field

- تعرض assignments الفعالة فقط مع تاريخ/وقت محلي واضح.
- future assignment يظهر upcoming دون منح صلاحية مبكرًا.
- expired يظهر history لا current.
- عند overlap المسموح توضح الأولوية؛ عند غير المسموح يجب ألا يصل إلى Runtime.

## البيانات والمنطق

- type taxonomy حاكمة.
- start/end timestamps وtimezone policy.
- exclusion/range constraints أو transaction validation.
- unique active primary supervisor/shift حسب السياسة.
- events `assignment.started/ended/changed`.
- consumers تستخدم actor_id وcanonical refs.

## الاختبارات

- overlapping ranges.
- boundary second/timezone/DST إن انطبق.
- concurrent create/end.
- retroactive correction.
- active mutation وقت الانتهاء.
- cross-partner/store scope.
- عدم وجود assignment write path خارج Workforce.

## التجريب اليدوي

1. أنشئ future/current assignments من HR.
2. حاول overlap محظورًا من HR وPartner page.
3. افتح كل تطبيق قبل/عند/بعد effective time.
4. أنهِ assignment أثناء عملية مفتوحة في Operations.
5. اختبر timezone مختلفة في Control Panel والجهاز.
6. راجع history/audit/events والأقسام الأربعة.

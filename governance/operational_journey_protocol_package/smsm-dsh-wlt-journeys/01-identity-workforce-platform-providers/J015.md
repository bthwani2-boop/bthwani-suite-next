```yaml
owner: Platform Control
actors: [OPERATOR, SERVICE_IDENTITY]
surfaces: [control-panel, app-client, app-partner, app-captain, app-field]
control_panel_sections: [platform, administration, operations, finance]
dependencies: [FOUNDATION-00, J014]
assessment_status: NOT_ASSESSED
closure_status: OPEN
```

## النتيجة التشغيلية

تغيير السياسات السيادية عبر draft/review/approval/schedule/apply/rollback، مع نسخة فعالة واحدة وdiff كامل وفصل صلاحيات وعدم تعديل مباشر من المستهلكين.

## الحالة الحالية

| البند | التشخيص المطلوب |
| --- | --- |
| Change-set model | الجداول والعقود والحالات |
| Approval separation | منع self-approval وrole overlap |
| Apply engine | atomic/partial/rollback behavior |
| Consumer adoption | version/freshness/readback في DSH والأسطح |
| Parallel configs | env/constants/local flags الواجب حذفها |

الخطر: UI يكتب policy مباشرة، apply جزئي بلا حالة، rollback يعيد نسخة غير متوافقة.

## Control Panel

- قائمة change sets مع owner/status/target/effective time.
- editor يعرض base version وdiff validated.
- أزرار submit/review/approve/reject/schedule/apply/rollback حسب الدور والحالة.
- stale base يمنع approval ويطلب rebase/review جديد.
- apply progress لكل consumer وحالة partial واضحة.

بقية الأقسام تعرض النسخة الفعالة وتأثيرها فقط، وتفتح change set المالك بدل direct save.

## التطبيقات

- لا تدير change sets.
- تقرأ policy/feature decision المطبق مع version.
- عند تطبيق/rollback تحدث view models دون hardcoded fallback.
- في partial outage تعرض behavior محدد لا خليط نسخ صامت.

## التقنية

- immutable versions وone-effective constraint.
- separation of duties.
- apply jobs idempotent وcorrelated.
- consumer acknowledgements/readback.
- rollback forward-compatible ولا يعدل history.
- audit كامل.

## الاختبارات

- self-approval.
- stale base/concurrent approval.
- apply failure في مستهلك واحد.
- duplicate job/retry.
- scheduled boundary.
- rollback after schema change.
- all listed section controls bound to change-set lifecycle.

## التجريب اليدوي

1. أنشئ draft وراجع diff في Platform.
2. حاول self-approval وapproval stale من Administration roles.
3. جدول التطبيق ثم عطّل مستهلكًا.
4. راقب partial state في Operations/Finance والأسطح.
5. استأنف أو rollback.
6. تحقق من نسخة فعالة واحدة وAudit.

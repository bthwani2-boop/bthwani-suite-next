## النتيجة التشغيلية

إنشاء Partner واحد داخل DSH وربطه بـActor وWorkforce person وMedia evidence، ثم فتح Onboarding Case قابلة للاستئناف. لا ينشأ Tenant أو instance أو catalog محلي أو wallet محلي.

## الحالة الحالية

| التصنيف | الحكم |
| --- | --- |
| الموجود | مفاهيم Partner/onboarding والأسطح الثلاثة موجودة |
| غير المثبت | write path الحاكم، duplicate detection، orchestration references، case state، media ownership |
| الخاطئ المحتمل | إنشاء Partner من أكثر من Surface بمنطق مختلف، free-text owner، tenant remnants، success قبل اكتمال case |
| التصحيح | operation واحدة idempotent، actor/workforce refs، onboarding state machine، audit/outbox |
| الإضافات | resume/unknown-result، duplicate review، field draft/offline policy |

## Control Panel

- زر `إضافة شريك` من قسم الشركاء.
- Wizard: اختيار/إنشاء Actor عبر J011 → legal/basic data → contacts → evidence → review → submit.
- يعرض duplicate suggestions قبل الإنشاء.
- بعد submit يظهر Partner ID وCase status وnext required action.
- حالات: draft، duplicate suspected، validation failed، evidence pending، unknown result، submitted.

## App Field

- قائمة مهام onboarding ضمن assignment فقط.
- يمكن حفظ draft محلي مشفر وإرفاق evidence، لكن الإنشاء النهائي يمر بنفس operation.
- يجب عرض scope الحالي والPartner candidate وعدم السماح خارج المنطقة/assignment.
- عند reconnect يعاد التحقق من duplicate/version قبل الإرسال.

## App Partner

- لا ينشئ Partner بنفسه.
- بعد activation يقرأ onboarding case ويعرض checklist/status/needs-info.
- لا يدخل Dashboard التشغيلي قبل الحالة المسموحة.

## التقنية

- Partner canonical ID من DSH.
- actor_id/workforce_person_id/media_refs فقط، لا نسخ auth/HR/media blobs.
- unique legal identity/phone/email وفق Product Truth.
- idempotency/result lookup.
- transaction + outbox لبدء case.
- no tenant_id/platform instance semantics.

## الاختبارات

- duplicate legal identity/phone بصيغ متعددة.
- same request من Control Panel وField.
- missing Actor/Workforce profile.
- response loss after commit.
- media upload incomplete.
- cross-area Field.
- grep/guard لبقايا tenant provisioning.
- كل قسم مذكور يستخدم نفس case وcanonical refs.

## التجريب اليدوي

1. أنشئ Partner من `/dsh/partners` ثم حاول نفسه من Field.
2. ابدأ draft offline وأكمله بعد reconnect.
3. افقد الرد بعد submit وافتح status.
4. راقب HR/Administration/Operations references والحالات.
5. جرّب Field خارج assignment.
6. سجّل دخول Partner وتحقق من checklist.
7. افحص DSH/Identity/Workforce/Media والعلاقات.

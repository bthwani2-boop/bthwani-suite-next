## النتيجة التشغيلية

نشر Store فقط بعد اكتمال الملف والموقع والساعات والمنطقة والتغطية وassortment والسياسات والقدرات المطلوبة، ثم pause/suspend/close مع أثر فوري على discovery/checkout دون حذف التاريخ.

## الحالة الحالية

- readiness/publication موجودة مفهوميًا؛ يلزم إثبات rules engine وclient visibility.
- الخطر: published flag يدوي، متجر بلا catalog/area يظهر للعميل، pause لا يبطل cache، order race.
- المطلوب: reason-coded checklist ومصدر قرار واحد وevents/cache invalidation.

## Control Panel

- Store detail يعرض checklist owner/source/status لكل شرط.
- controls: request review، publish، pause، resume، suspend، close.
- publish لا يظهر/يتفعل إلا عند readiness، لكن Backend يعيد التحقق.
- confirmation يوضح أثر pause/suspend على الطلبات الجديدة والقائمة.

## App Partner

- checklist قابلة للإصلاح وروابط لكل قسم.
- publish/pause controls حسب permission.
- حالات partial dependency وunknown result.
- لا يسمح toggle local أو optimistic published قبل readback.

## App Field

- يعرض verification tasks/evidence المطلوبة.
- لا يملك publish النهائي إلا بصلاحية صريحة.
- offline evidence يحدث checklist بعد server processing.

## App Client

- لا يظهر Store غير منشور/موقوف/غير قابل للخدمة.
- إذا أوقف أثناء شاشة مفتوحة: banner وحظر add/checkout مع refresh.
- orders السابقة تبقى قابلة للقراءة.

## التقنية

- readiness engine من canonical sources.
- state machine `DRAFT→READY→PUBLISHED↔PAUSED→SUSPENDED/CLOSED`.
- publication transaction + outbox.
- search/cache/home invalidation.
- checkout يعيد التحقق.

## الاختبارات

- missing each prerequisite.
- publish/pause/order race.
- stale search cache.
- direct status mutation.
- unauthorized Partner/Field.
- resume after prerequisite invalidated.
- section-by-section owner/control mapping.

## التجريب اليدوي

1. حاول نشر Store ناقصًا لكل شرط من Store Detail.
2. أصلح Catalog/Discovery blockers في أقسامها وانشره.
3. تحقق من Home/Search/Store detail.
4. أوقفه أثناء Cart/Checkout وراقب Operations.
5. ألغِ prerequisite بعد النشر.
6. راجع Analytics/timeline/audit/events.

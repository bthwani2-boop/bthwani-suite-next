## النتيجة التشغيلية

إنشاء Store واحد تابع لشريك فعال مع code/name/address/location/hours baseline، وتطبيق ownership داخل Backend وDB. لا يقبل `partnerId` العميل كسلطة ولا ينشئ Store orphan.

## الحالة الحالية

- **الموجود:** store APIs/UI/runtime catalog مفاهيم.
- **غير المثبت:** canonical create path، partner FK، uniqueness، geolocation validation، idempotency.
- **الخاطئ المحتمل:** إنشاء مختلف بين surfaces، store بدون active partner، cross-partner write، duplicate code/location.
- **التصحيح:** operation واحدة وtrusted context/explicit operator target authorization.
- **الإضافات:** draft/resume، unknown-result lookup، readiness initialization.

## Control Panel

- من Partner detail زر `إضافة متجر`.
- Wizard: basic data، map/location، address، hours، review.
- يعرض owner Partner ثابتًا ولا يسمح تبديله بلا permission.
- بعد النجاح يفتح Store detail بحالة `DRAFT/INCOMPLETE` وchecklist J025.

## App Partner

- زر add store فقط لعضو مخول.
- partner context مشتق من session؛ لا selector لشريك آخر.
- forms ودعم draft، validation، map/provider degraded.
- readback بعد submit.

## App Field

- add store ضمن assigned partner/area task.
- يتطلب geo/time evidence حسب السياسة.
- offline draft لا ينشئ local Store ID حاكمًا؛ يستخدم client correlation مؤقتًا.

## التقنية

- FK partner_id مع active-state validation في transaction.
- unique store code ضمن نطاق محدد.
- normalized address/geo وSRID.
- idempotency/result lookup.
- outbox for readiness/search projections.
- no store ownership update مباشر.

## الاختبارات

- forged partnerId/cross-partner.
- inactive/suspended partner.
- duplicate code/concurrent create.
- invalid coordinates/provider down.
- offline duplicate Field submit.
- response loss.
- no alternate Store write in sections.

## التجريب اليدوي

1. أنشئ Store من Partner section/App Partner/App Field.
2. بدّل partnerId في Network request.
3. جرّب Partner معلقًا وcode مكررًا.
4. اقطع map provider/network وراقب Platform.
5. افقد الرد ثم تحقق من القائمة وOperations work item.
6. افحص FK/outbox/audit/readiness.

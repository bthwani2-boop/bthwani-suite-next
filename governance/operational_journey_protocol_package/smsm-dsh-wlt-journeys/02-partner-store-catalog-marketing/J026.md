## النتيجة التشغيلية

Geometry مركزية وversioned لمناطق الخدمة مع validation وSRID وسياسة overlap وspatial indexes، وقرار Serviceability خادمي لا يعتمد polygon عميلية.

## الحالة الحالية

- map/areas/serviceability مفاهيم موجودة؛ يلزم جرد العقود والجداول والفهارس.
- الخطر: GeoJSON بلا validation، SRID mismatch، polygon invalid، client point-in-polygon، overlap غير محسوم، provider fallback صامت.
- المطلوب: geometry schema وDB spatial constraints وversioned publication وdecision engine.

## Control Panel

- map editor/list/history.
- controls: draw، edit vertices، validate، compare overlap، save draft، publish، retire.
- يعرض area version وaffected stores/policies.
- invalid geometry تمنع save/publish مع سبب مرئي.

## App Partner

- يعرض مناطق Store الحالية ويمكن request/edit ضمن scope والسياسة.
- لا يحسب serviceability محليًا.
- يرى overlap/conflict/review states.

## App Field

- map/geo capture للتحقق الميداني ضمن assignment.
- accuracy/time/provider status ظاهر.
- offline draft يخزن evidence لا قرار نهائي.

## App Client

- يرسل address/location reference إلى serviceability endpoint.
- يعرض serviceable/unserviceable/temporary unavailable/unknown-provider مع next action.
- boundary decision يأتي من server.

## التقنية

- PostGIS geometry/geography type وGIST/SP-GIST index حسب التصميم.
- valid polygon/multipolygon، ring/coordinate/SRID validation.
- effective versions وoverlap policy.
- provider geocode منفصل عن DSH geometry truth.
- cache key includes area version.

## الاختبارات

- self-intersection/empty/huge polygon.
- SRID mismatch.
- boundary points/holes.
- overlap concurrency.
- provider unavailable.
- forged client decision.

## التجريب اليدوي

1. ارسم polygons صحيحة وغير صحيحة ومتداخلة.
2. اختبر points داخل/خارج/on-boundary.
3. عطّل maps/geocoder.
4. جرّب App Field offline evidence.
5. راقب App Client قبل/بعد نشر version.
6. افحص spatial query plan والفهرس.

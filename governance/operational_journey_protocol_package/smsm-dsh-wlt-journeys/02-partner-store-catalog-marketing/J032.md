## النتيجة التشغيلية

Proposal workflow لإضافة Product أو تصحيح canonical fields دون direct write إلى Master Catalog، مع base version وevidence وduplicate candidates وحالة قابلة للاستئناف.

## الحالة الحالية

- proposal concepts موجودة أو مطلوبة؛ mapping الفعلي غير مثبت.
- الخطر: App Partner/Field يكتب product مباشرة، proposal بلا base version، duplicate proposals، evidence خارج Media، silent approval.
- المطلوب: proposal state machine وreview queue وoptimistic conflict.

## App Partner

- من catalog search زر `اقتراح منتج جديد` أو `اقتراح تصحيح`.
- form يوضح canonical fields مقابل Store overrides.
- controls: save draft، add evidence، submit، edit before review، withdraw.
- statuses: draft/submitted/in-review/needs-info/approved/rejected/conflict/withdrawn.

## App Field

- barcode lookup ثم proposal عند no match.
- offline draft/scan/evidence مع scope وversion.
- عند reconnect يعاد duplicate search قبل submit.

## Control Panel

- review queue وcomparison مع canonical/duplicate candidates.
- request info/approve/reject/merge في J033.
- لا تعديل proposal الأصلي دون audit.

## التقنية

- proposal table/changeset JSON validated أو normalized rows.
- base product/version refs.
- unique open proposal policy عند الحاجة.
- media refs، actor/scope، idempotency.
- outbox notifications.

## الاختبارات

- duplicate open proposal.
- stale base.
- wrong Partner/Store scope.
- direct master API denial.
- offline duplicate submit.
- evidence invalid.

## التجريب اليدوي

1. اقترح منتجًا جديدًا وتصحيحًا.
2. كرر proposal من Partner وField.
3. غيّر Master قبل submit/review.
4. اطلب معلومات ثم أعد الإرسال.
5. withdraw أثناء review.
6. تحقق من عدم تغير Master قبل approval.

## الإغلاق

`direct_partner_field_master_writes=0; duplicate_open_proposals=0; stale_base_conflicts=PASS; proposal_status_readback=PASS; evidence_sha=CURRENT_SHA`.

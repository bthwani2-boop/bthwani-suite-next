## النتيجة التشغيلية

مراجعة proposals وحل conflicts/duplicates واعتماد أو دمج مع canonical lineage وحفظ كل references، دون lost update أو orphan assortment.

## الحالة الحالية

- يلزم إثبات review operations/merge engine/search reindex/reference migration.
- الخطر: approve مرتين، merge يغير IDs بلا redirects، barcode conflict، reviewer يعدل proposal صامتًا، stale approval.
- المطلوب: version lock وsingle final decision وmerge transaction/jobs وrebuild.

## Control Panel

- queue بpriority/age/type/duplicate risk.
- compare view: proposal، base version، current canonical، diff، evidence، affected assortments.
- controls: claim، request info، approve، reject، choose canonical، merge، resolve field conflict.
- confirmation للmerge يعرض reference impact.
- stale view يمنع القرار ويطلب refresh.

## App Partner/App Field

- يعرض decision/reasons/merged canonical ID وnext action.
- لا يرى internal reviewer notes الحساسة.
- approved proposal يمكن ربطها بالassortment بعد readback.

## البيانات والمنطق

- one terminal decision.
- approval creates/updates canonical product with version.
- merge lineage source→canonical.
- reassignment of media/barcodes/assortment refs.
- outbox/search reindex idempotent.
- rollback عبر forward corrective action، لا حذف history.

## الاختبارات

- simultaneous approvals.
- stale base/current product.
- barcode conflict.
- merge target deprecated.
- job failure halfway/retry.
- reference and search rebuild.

## التجريب اليدوي

1. افتح Proposal في جلستين.
2. عدّل Master ثم حاول approve stale.
3. نفّذ merge مع assortments/media.
4. عطّل reindex job ثم أعده.
5. تحقق من Partner/Field status وClient catalog.
6. افحص lineage وكل references.

## الإغلاق

`multiple_terminal_decisions=0; orphan_references_after_merge=0; unresolved_committed_conflicts=0; lineage_and_rebuild=PASS; stale_approval=0; evidence_sha=CURRENT_SHA`.

## النتيجة التشغيلية النهائية

Checkout هو orchestration محكوم يجمع snapshot السلة والعنوان وserviceability والfulfillment والquote والتفضيلات والمتطلبات الخاصة ويعيد preview قابلة للتأكيد. لا ينشئ Order أو Payment effect أثناء المعاينة، ولا تعتمد قابلية التأكيد على flags محلية.

## تشخيص الحالة الحالية

### الموجود

- `dsh.checkout.openapi.yaml` وgenerated checkout types.
- GovernedCheckoutScreen وcheckout view-model.
- cart/serviceability/finance bridges موجودة.

### الناقص

- checkout intent lifecycle وexpiry.
- validation issue model يربط المشكلة بالعنصر والتحكم القابل للإصلاح.
- preview hash/version.
- distinction بين validate/preview/confirm.
- unknown-result UX لكل step.
- runtime end-to-end proof من Cart إلى Order.

### الخاطئ أو الممنوع

- عقد Checkout يدوي موازٍ أو `CONTRACT_ONLY`.
- إنشاء payment/order في preview.
- زر تأكيد enabled رغم issue غير محلول.
- رسائل عامة تخفي field أو line المسبب.
- الاحتفاظ preview قديمة بعد تعديل Cart/Address/Mode.

### التصحيح المطلوب

- checkout aggregate contract generated فقط.
- server state machine `DRAFT | VALIDATING | READY | BLOCKED | EXPIRED | CONFIRMING | CONFIRMED`.
- deterministic invalidation عند تغير dependencies.
- UI controller واحد مع mapping لكل issue إلى control.

### الإضافات المطلوبة

- review sections قابلة للانتقال للتحرير.
- validation summary أعلى الشاشة.
- Control Panel inspector لقراءة intent دون mutation.
- telemetry للdrop-off حسب reason دون PII.

## منطق التشغيل

- Create/refresh intent يثبت cart version/address snapshot/quote version/mode candidate.
- validate يعيد issues ولا يخلق آثارًا نهائية.
- preview يتضمن hash وexpires_at.
- confirm في J053 يقبل intent READY غير منتهية فقط.
- تعديل أي dependency يبطل preview ويعيد التحقق.

## App Client

- أقسام: العنوان، المتجر/items، fulfillment، الوقت إن وجد، payment choice placeholder، instructions، price breakdown، policies/consent.
- controls: edit لكل قسم، refresh، resolve issue، confirm، back، cancel intent.
- confirm disabled مع reason نصي؛ loading يمنع double-submit.
- حالات: validating، ready، multiple issues، price changed، address invalid، store closed، session expired، offline، unknown result.
- focus ينتقل لأول issue مع accessibility announcement.

Administration can locate Customer Actor but does not inspect Checkout. Platform provides runtime/job diagnostics without business mutation.

## العقود والباك إند والبيانات

- endpoints create/get/refresh/cancel/validate preview.
- intent DB مع expiry/version/hash وimmutable snapshots/references.
- validation issue vocabulary ثابتة.
- no side-effect adapters في preview path عدا reads/reservations إذا Product Truth صريح ومع compensations.
- idempotency للcreate/refresh/cancel.

## الاختبارات الآلية

- cart version changes بعد preview.
- quote expiry/price change.
- address/serviceability invalidation.
- store close أثناء checkout.
- duplicate create/refresh.
- preview no order/payment side effects.
- issue-to-control mapping completeness.
- accessibility focus/error summary.
- section inspector/action permissions.

## التجريب اليدوي

1. افتح Checkout من Cart صالحة.
2. عدّل كل قسم وراقب invalidation/revalidation في Operations.
3. أغلق المتجر أو غيّر السعر أثناء المعاينة وراقب Partners/Finance.
4. اترك intent تنتهي ثم حاول التأكيد.
5. افصل الشبكة أثناء refresh وارجع.
6. تحقق من كل issue ومكان إصلاحه ودعم العميل.
7. قارن Analytics وhashes/versions دون أي Payment/Order side effect.

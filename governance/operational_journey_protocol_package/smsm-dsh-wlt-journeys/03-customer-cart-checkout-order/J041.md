## النتيجة التشغيلية النهائية

يمتلك العميل ملف تجارة واحدًا في DSH مرتبطًا بـ`identity_actor_id` دون نسخ حقيقة الهاتف أو الأدوار أو الجلسات. يحتوي الملف على الاسم التجاري المسموح، اللغة، تفضيلات التواصل، تفضيلات الاكتشاف، إعدادات الوصول، والموافقات القانونية المرقمة بالإصدار. كل تعديل قابل للتدقيق، وكل قراءة دعم تخضع لإخفاء PII وصلاحية غرضية.

## تشخيص الحالة الحالية المطلوب قبل التنفيذ

### الموجود المثبت
- Identity هو مالك الهاتف والجلسة والدور.
- DSH يملك الأسطح التجارية للعميل.
- App Client وControl Panel هما السطحان المباشران لهذه الرحلة.

### غير المثبت أو الناقص
- جدول حقول موثق يحدد مالك كل حقل بين Identity وDSH.
- عقد OpenAPI موحد للقراءة والتعديل والموافقات.
- version/ETag لمنع الكتابة فوق تعديل أحدث.
- سجل موافقات يثبت النص والإصدار والوقت والمصدر والجهاز.
- مصفوفة إخفاء PII في Control Panel.
- سياسة حذف/تصدير/احتفاظ وربطها بالرحلات العرضية.

### الخاطئ أو الممنوع
- تخزين الهاتف أو الدور أو حالة الجلسة كحقيقة ثانية داخل DSH.
- حقول Profile محلية داخل التطبيق لا تقرأ من Runtime.
- زر حفظ ينجح بصريًا دون readback من الخادم.
- تعديل الدعم للعميل دون سبب وصلاحية وتدقيق.
- تحويل سحب الموافقة إلى حذف صامت أو فقد تفضيلات غير مرتبطة.

### التصحيح المطلوب
1. إنشاء ownership matrix لكل حقل.
2. تثبيت schema وعقد أخطاء موحد.
3. تطبيق optimistic concurrency وidempotency.
4. فصل self-service عن support mutation.
5. إزالة الأنواع والـfixtures والـdefaults التي تعمل كمصدر حقيقة موازٍ.
6. إضافة audit event لكل تغيير حساس.

### الإضافات المطلوبة
- شاشة سجل الموافقات.
- إعدادات وصول ولغة واتجاه نص قابلة للاستعادة.
- read-only support view مع masking افتراضي.
- export/delete request entry points دون تنفيذ مالي أو هوياتي محلي.

## منطق التشغيل والحالات

الحالات: `LOADING | READY | SAVING | CONFLICT | PARTIAL_REDACTION | CONSENT_REQUIRED | BLOCKED | DELETED | ERROR`.

القواعد:
- لا يُنشأ أكثر من ملف DSH فعال لكل Actor.
- التعديل يرسل `version` أو `If-Match`؛ التعارض يعيد البيانات الأحدث ولا يطغى عليها.
- سحب موافقة يغيّر capability المرتبطة فقط ويصدر event.
- حذف Actor في Identity يمنع mutations فورًا ويطلق مسار retention وليس حذفًا ارتجاليًا.
- أي ملخص مالي يظهر عبر DSH facade من WLT ولا يكتب في الملف.

## App Client — ما يجب أن يظهر ويعمل

### الصفحات والعناصر
- صفحة **ملفي**: الاسم، اللغة، تفضيلات التواصل، إمكانية الوصول، الموافقات.
- زر `تعديل`، `حفظ`، `إلغاء`، `إعادة المحاولة`، `عرض نص الموافقة`، `سحب الموافقة`، `طلب نسخة بياناتي`، `طلب حذف الحساب`.
- أيقونات اللغة والإشعارات والخصوصية مع label نصي وaccessibility hint.

### سلوك التحكمات
- `حفظ`: disabled عند عدم وجود تغيير أو أثناء الطلب؛ يمنع double-submit.
- `سحب الموافقة`: confirmation يوضح الأثر، ثم readback للحالة الجديدة.
- `إعادة المحاولة`: يعيد آخر command بنفس idempotency key عند نتيجة مجهولة.
- `إلغاء`: يعيد snapshot الأخير من الخادم لا defaults محلية.

### الحالات المرئية
- Skeleton للتحميل، Empty غير مسموح لملف Actor صالح، Conflict مع مقارنة، Offline مع pending غير مزعوم نجاحه، Blocked بسبب Actor state، Error برمز مفهوم دون PII.

## Control Panel — ما يجب أن يظهر ويعمل

- بحث Actor ثم بطاقة Profile masked.
- تبويبات: `الملف`، `التفضيلات`، `الموافقات`، `التدقيق`، `طلبات الخصوصية`.
- أزرار: `تحديث مسموح`، `كشف مؤقت` بصلاحية وسبب، `نسخ معرف مرجعي`، `فتح طلب خصوصية`.
- لا يظهر raw phone أو token أو بيانات مالية كاملة.
- كل support mutation يتطلب permission وreason ويعرض before/after diff.
- حالة Actor المحذوف أو الموقوف تظهر بوضوح وتمنع الكتابة.

## العقود والباك إند والبيانات

- OpenAPI: GET/PATCH profile، GET/PATCH preferences، GET/POST consent decisions، GET audit summary.
- أخطاء ثابتة: `PROFILE_NOT_FOUND`, `VERSION_CONFLICT`, `CONSENT_VERSION_REQUIRED`, `ACTOR_INACTIVE`, `FORBIDDEN_FIELD`, `PII_ACCESS_DENIED`.
- DB: unique active profile per actor، version، timestamps، consent ledger append-only، indexes للبحث المصرح.
- AuthZ: self actor ownership؛ support permissions منفصلة للقراءة والكشف والتعديل.
- Events: profile.updated، consent.changed، privacy.requested مع outbox وcorrelation id.

## الاختبارات الآلية الإلزامية

- duplicate profile race.
- stale version conflict.
- IDOR بين عميلين.
- support masking وpermission negative.
- consent version/replay.
- Actor deactivation أثناء الحفظ.
- offline/unknown-result recovery.
- scan لحقول Identity المكررة والأنواع المحلية.
- generated client provenance وcontract binding.

## التجريب اليدوي الكامل

1. افتح الملف في App Client وتحقق من loading ثم البيانات الحية.
2. عدّل اللغة وإعداد وصول واحفظ؛ أعد فتح التطبيق وتحقق من الاستعادة.
3. افتح جهازًا ثانيًا، نفّذ تعديلين متعارضين، وتحقق من شاشة Conflict دون فقد بيانات.
4. اسحب موافقة، تحقق من تعطيل feature المرتبطة فقط ومن سجل الموافقة في Control Panel.
5. افصل الشبكة بعد الضغط على حفظ، ثم أعد الاتصال وتحقق من readback دون duplicate.
6. استخدم Operator بلا صلاحية ثم بصلاحية؛ تحقق من masking وreason/audit.
7. أوقف Actor من Identity وحاول mutation؛ يجب الرفض وعرض Blocked.
8. افحص DB/audit/outbox والـlogs للتأكد من عدم تسريب PII.

## أدلة الإغلاق

- صور/فيديو لكل حالة Surface.
- request/response redacted وعقد OpenAPI المولد.
- DB invariant وaudit rows.
- نتائج الاختبارات السلبية وruntime readback على SHA نفسه.

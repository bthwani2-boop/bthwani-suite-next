## النتيجة التشغيلية النهائية

تعرض صفحة المتجر snapshot متسقة من حقيقة المتجر والكتالوج المنشور والتوفر والأسعار التشغيلية والصور والسياسات. App Client يقرأ فقط؛ App Partner يدير عبر رحلات الحوكمة السابقة؛ Control Panel يشخص النسخة والاختلافات. لا توجد عقود كتالوج محلية موازية أو محتوى phantom.

## تشخيص الحالة الحالية

### الموجود

- كتالوج مركزي وgenerated clients ومسارات catalog/store في DSH.
- أسطح Partner وControl Panel لإدارة ومراجعة الكتالوج.

### الناقص

- storefront read contract واحد يجمع store header/categories/items/options/availability.
- publication/version token يربط كل response.
- قواعد image fallback وmedia readiness.
- consistency بين list/detail/cart validation.
- reason codes للعناصر المخفية أو غير المتاحة.
- runtime proof من seed حتى App Client.

### الخاطئ أو الممنوع

- إعادة تعريف Product/Category/Option في frontend كعقد سلطة.
- أسعار أو availability hardcoded.
- فتح تفاصيل item قديم من cache دون revalidation.
- عرض صورة placeholder كأنها أصلية بلا حالة.
- Partner preview يكتب مباشرة في published view.

### التصحيح والإضافات

- Storefront aggregate API أو composition محكومة.
- versioned ETag وcache invalidation.
- media resolver مركزي.
- item detail/options schema generated.
- diagnostics للفرق بين draft/published/runtime projection.

## منطق التشغيل

- القراءة تستخدم published catalog version المسموح للمتجر والسياق.
- availability وschedule تطبق عند القراءة وعند الإضافة للسلة.
- option groups تحترم min/max/required/compatibility.
- item غير متاح يبقى قابلًا للعرض فقط إذا Product Truth يسمح مع state واضحة.
- cache stale يعرض timestamp ويمنع add-to-cart حتى revalidation إذا تغيرت النسخة.

## App Client

- Header: الاسم، الصور، الحالة، ETA، الرسوم، minimum، badges.
- Tabs/categories، search داخل المتجر، item cards، item detail modal/screen.
- controls: favorite إن كانت رحلة مستقلة، add، quantity، options، notes، retry، share/deep link.
- states: loading، empty catalog، category empty، item unavailable، option invalid، media failed، store closed، version refreshed.
- كل زر Add يعرض السعر والخيارات من response الحية ولا يحسب locally.

## App Partner

- preview للنسخة draft والمنشورة مع banner واضح.
- diff وتاريخ النشر وروابط لرحلات إدارة الكتالوج.
- لا توجد mutation سرية من شاشة preview.
- يرى media/availability errors الخاصة بمتجره.

## التقنية والبيانات

- generated OpenAPI types فقط للطلبات والاستجابات.
- immutable published versions ومراجع item/option مستقرة.
- ETag/cache-control وevent invalidation.
- media URLs موقعة أو public governed مع expiry/fallback.
- observability للـ404 phantom، version mismatch، media failures.

## الاختبارات

- draft not visible، unpublished item، store closed.
- option min/max وinvalid combination.
- stale cache/version update.
- item deep link بعد حذف/أرشفة.
- media unavailable/fallback.
- list/detail/cart price consistency.
- scan للعقود اليدوية والfixtures.
- all section preview/diagnostic/action bindings.

## التجريب اليدوي

1. انشر catalog version وتحقق من App Client وCatalog Inspector.
2. عدّل draft دون نشر وتحقق من عدم تسربه.
3. انشر نسخة جديدة أثناء فتح العميل ثم اختبر refresh/add وOperations.
4. اختبر item options والحدود والملاحظات.
5. عطّل media object من Platform وتحقق من fallback.
6. أغلق المتجر أو عطّل item وتحقق من Partner/Marketing states.
7. قارن Partner preview وpublished/runtime inspector.

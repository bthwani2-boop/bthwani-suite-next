## النتيجة التشغيلية النهائية

يمتلك العميل سلة DSH فعالة ومحكومة للسياق المعتمد، تتضمن عناصر الكتالوج بمراجع versions وخياراتها وكمياتها وملاحظاتها. كل mutation idempotent ومتحقق من publication/availability/serviceability، ولا تعتمد totals أو صلاحية العناصر على state محلي.

## تشخيص الحالة الحالية

### الموجود

- Cart HTTP handlers وشاشة Cart وGoverned Cart في DSH frontend.
- أنواع Checkout مولدة من OpenAPI بعد إزالة العقد اليدوي الموازي.

### الناقص

- تعريف صريح لسياسة single-store/multi-store.
- cart version وoptimistic concurrency.
- line identity ثابتة تشمل item/options/configuration.
- validation reason per line.
- limits للكميات والملاحظات وحجم السلة.
- support read-only view وaudit mutations.

### الخاطئ أو الممنوع

- الاعتماد على local cart كحقيقة نهائية.
- دمج أسطر غير متطابقة في options.
- قبول item/version غير منشور أو سعر محلي.
- زر `+` يرسل طلبات متوازية تسبب فقد تحديث.
- إزالة line بصريًا قبل تأكيد أو recovery لنتيجة مجهولة دون حالة واضحة.

### التصحيح المطلوب

- central cart domain/state machine.
- version/ETag لكل mutation.
- idempotency key لكل add/update/remove/clear.
- server authoritative line validation وderived presentation model فقط في frontend.
- إزالة reducers/types التي تعيد تعريف authority.

### الإضافات المطلوبة

- unavailable/changed line remediation.
- restore last removal إن كان Product Truth يسمح كأمر جديد لا rollback محلي.
- support diagnostics مع masked actor.

## منطق التشغيل

الحالات: `ACTIVE | REVALIDATION_REQUIRED | BLOCKED | CONVERTING_TO_ORDER | CONVERTED | EXPIRED`. كل line: `VALID | PRICE_CHANGED | UNAVAILABLE | OPTION_INVALID | LIMIT_EXCEEDED | STORE_MISMATCH`. لا تتحول السلة إلى order إلا من version مثبتة. أي تغيير address/store/mode يطلق revalidation.

## App Client

- Cart badge من Runtime، قائمة lines، quantity stepper، remove، clear، notes، edit options، continue shopping، checkout.
- كل control له loading خاص، disabled rules، double-submit protection، error recovery.
- totals تعرض quote مرجعية فقط وتوسم stale إذا انتهت.
- حالات empty، partial invalid، whole cart blocked، offline snapshot، conflict، unknown mutation result.
- Checkout disabled مع سبب قابل للإصلاح، لا بسبب boolean مجهول.

## العقود والبيانات

- OpenAPI cart create/get/add/update/remove/clear/revalidate.
- DB unique active cart وفق policy، cart_version، line_version، item/catalog refs.
- transaction boundaries تمنع partial line mutation.
- audit/outbox للأحداث المؤثرة.
- limits enforced backend وcontract errors ثابتة.

## الاختبارات الآلية

- concurrent `+/-` وstale version.
- duplicate add idempotency.
- different options line identity.
- unpublished/unavailable item.
- store mismatch والسياسة المتعددة.
- oversized note/quantity/cart.
- Actor IDOR/support permission.
- unknown result after commit.
- section query/action binding.

## التجريب اليدوي

1. أضف نفس item بنفس الخيارات ثم بخيارات مختلفة.
2. اضغط `+` سريعًا ومن جهازين.
3. غيّر publication أو availability أثناء فتح السلة وراقب Catalogs/Operations.
4. افصل الشبكة بعد remove/add ثم أعد الاتصال.
5. اختبر clear والعودة للمتجر وbadge.
6. افتح Cart في Operations/Support وتحقق من versions/idempotency/audit.
7. حاول الوصول بسلة عميل آخر وقارن Analytics.

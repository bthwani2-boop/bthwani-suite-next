## النتيجة التشغيلية النهائية

يعرض الاكتشاف متاجر منشورة وصالحة للسياق فقط، وفق عنوان العميل والوقت وحالة المتجر والخدمة والكتالوج وسياسات الاستهداف. البحث والترشيح projection قابلة لإعادة البناء وليسا مصدر حقيقة موازياً. لا تظهر متاجر phantom أو غير قابلة للطلب.

## تشخيص الحالة الحالية

### الموجود
- Home discovery وstore publication ومفاهيم targeting موجودة ضمن DSH.
- App Client يحتاج search/filter/sort؛ Control Panel يحتاج diagnostics؛ Partner يحتاج preview محدود.

### الناقص
- eligibility pipeline موثق بالترتيب.
- سبب إخفاء/ظهور قابل للتفسير.
- freshness/version للindex.
- parity بين home/search/category/deep link.
- zero-result recovery وspell/Arabic normalization.
- اختبارات publication-to-discovery runtime.

### الخاطئ أو الممنوع
- قوائم متاجر محلية أو fixtures في التطبيق.
- إظهار متجر غير منشور بسبب index stale.
- ترتيب يعتمد على قيم مالية أو sponsored placement بلا policy معلنة.
- اختلاف نتائج البحث والصفحة الرئيسية لنفس السياق دون سبب.
- filters شكلية لا تغير query الفعلية.

### التصحيح والإضافات
- central discovery query model وgenerated client.
- decision trace داخلي لكل store candidate.
- index invalidation/outbox/readback.
- diagnostics صفحة وpreview بسياق العميل.
- إزالة hardcoded categories/store cards.

## منطق التشغيل

التسلسل: validate context → resolve address/service area → publication state → store schedule/capacity → catalog availability → targeting/policy → ranking → pagination. كل خطوة تعيد reason code قابلًا للتشخيص داخليًا. النتائج مستقرة مع cursor ولا تعيد عناصر مكررة.

## App Client

- Home sections، search box، recent searches محلية غير سلطوية، filters، sort، category chips، clear filters، retry.
- كل بطاقة: صورة، اسم، حالة فتح، ETA تقديري، رسوم/حد أدنى من quote حية، badges governed.
- حالات: loading، zero results، no address، outside area، stale refresh، offline cached مع timestamp، error.
- الضغط على بطاقة يتحقق من eligibility مجددًا قبل تفاصيل المتجر.

## Control Panel

- Discovery diagnostics: أدخل actor/address/time ثم اعرض candidates وreason لكل استبعاد.
- index status، lag، last rebuild، publication mismatch، provider health.
- controls: rebuild projection أو replay event عبر workflow، لا تعديل نتيجة مفردة يدويًا.
- تقارير phantom/missing stores مع links لمالك الحقيقة.

## App Partner

- preview للمتجر كما سيظهر في سياقات تجريبية مع disclaimer.
- يرى أسباب عدم الظهور المرتبطة بمتجره فقط: publication، schedule، catalog readiness.
- لا يرى ranking منافسين أو targeting سري.

## التقنية والبيانات

- read model مشتق من store/catalog/service area/schedule.
- cursor pagination ثابتة، normalized Arabic search، typo policy محددة.
- event-driven invalidation مع reconciliation job.
- cache key يشمل context المؤثر ولا يتسرب بين العملاء.
- observability: zero-result rate، stale index، eligibility reasons.

## الاختبارات

- unpublished/closed/outside-area/no-catalog stores.
- index lag ثم reconciliation.
- home/search/deep-link parity.
- Arabic normalization وfilters effectiveness.
- pagination duplicates/missing.
- cross-context cache leakage.
- sponsored/ranking policy boundary.

## التجريب اليدوي

1. انشر متجرًا صالحًا وتحقق من ظهوره في Home/Search/Category.
2. أوقف النشر أو أغلق الجدول وتحقق من اختفائه وسبب diagnostics.
3. غيّر العنوان إلى خارج النطاق.
4. اختبر كل filter وsort وتحقق من الطلب الشبكي والنتيجة.
5. افصل event consumer ثم شغّل reconciliation.
6. افتح Partner preview وقارن App Client.
7. اختبر zero results وoffline cache وdeep link.

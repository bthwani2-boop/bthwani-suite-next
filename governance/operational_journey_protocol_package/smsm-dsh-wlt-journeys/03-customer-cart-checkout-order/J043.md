## النتيجة التشغيلية النهائية

يوفر DSH واجهة خرائط موحدة ويعامل مزودي geocoding/routing كاعتماد قابل للاستبدال. نقطة المستخدم الأصلية وقرارات serviceability تبقى في DSH، بينما أسماء الأماكن والمسارات وETA هي نتائج مزود ذات provenance وTTL ولا تتحول إلى حقيقة دائمة صامتة.

## تشخيص الحالة الحالية

### الموجود

- أسطح العميل والكابتن والميدان تحتاج خريطة ووظائف موقع مختلفة.
- Provider registry والحالة التشغيلية جزء من المنصة.

### الناقص

- contract موحد للـforward/reverse geocode وroute وsnap-to-road.
- provider selection/fallback/circuit breaker وquota handling.
- precision/privacy rules لكل Actor.
- cache key وTTL وprovenance.
- manual pin override ومسار تصحيح البيانات.
- خرائط RTL/a11y وoffline degradation.

### الخاطئ أو الممنوع

- استدعاء SDK provider مباشرة من كل Surface بمنطق مختلف.
- اعتبار ETA provider قيمة تعاقدية ثابتة.
- إرسال الموقع الدقيق في telemetry أو crash reports.
- fallback إلى provider آخر دون توضيح اختلاف الجودة أو حفظ provenance.
- حجب كامل للتجربة عند فشل geocoding رغم توفر pin.

### التصحيح والإضافات

- DSH Maps Facade بعقود generated clients.
- provider adapters مستقلة وسياسة fallback مركزية.
- confidence/precision/TTL في response.
- diagnostics في Control Panel وmanual override محكوم.
- اختبارات provider simulators وquota/timeout.

## منطق التشغيل

- pin الأصلية هي إدخال المستخدم؛ geocode enrichment لا يستبدلها دون تأكيد.
- routing يستخدم نقطة بداية/نهاية مصرح بها ويعيد route reference لا أسرار provider.
- cache لا يتجاوز TTL ولا يشارك نتائج دقيقة بين Actors.
- عند الفشل: الخريطة تظل قابلة لاختيار pin، ويظهر ETA غير متاح بدل رقم مختلق.
- التبديل بين providers change-set أو policy مسجلة.

## App Client

- map picker، search place، current location، recenter، confirm pin.
- عرض confidence منخفض وطلب تأكيد يدوي.
- حالات GPS off، permission denied، provider timeout، offline، outside bounds.
- لا يرسل search كاملًا إلى analytics.

## App Captain

- route preview، open navigation، recenter، refresh route، report map issue.
- يوضح أن ETA تقديري وتاريخ آخر تحديث.
- عند فقد الشبكة يعرض آخر route مع stale badge ولا يزعم live.
- لا يكشف مواقع طلبات أخرى.

## App Field

- خرائط الزيارات والنطاقات، التقاط evidence location حسب permission.
- عرض accuracy وتحذير spoof/low accuracy.
- زر report geofence mismatch مع reason/evidence.

## التقنية

- typed coordinates، CRS موحد، precision rules.
- timeouts/retries/circuit breakers ومحددات rate.
- correlation id وprovider request id masked.
- cache partitioning وnegative cache قصير.
- no direct provider SDK خارج adapter boundaries.

## الاختبارات

- provider timeout/429/5xx/invalid payload.
- fallback consistency وprovenance.
- low confidence/manual pin.
- location privacy/IDOR.
- stale route/offline.
- RTL gestures/a11y labels.
- quota exhaustion وعدم cascading failure.
- section action and precision mapping.

## التجريب اليدوي

1. اختر pin وابحث عن مكان وغيّر النتيجة يدويًا.
2. اختبر permission denied وGPS off.
3. عطّل provider الأساسي من Platform وراقب fallback.
4. نفد quota وتحقق من circuit breaker وDashboard/Analytics.
5. شغّل رحلة Captain ثم افصل الشبكة وتحقق من Operations stale indicator.
6. نفّذ geofence mismatch من Field وافتح Store diagnostics.
7. افحص telemetry والـlogs لعدم وجود إحداثيات خام غير لازمة.

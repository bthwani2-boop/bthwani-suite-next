## النتيجة التشغيلية النهائية

DSH يركب quote التشغيلية من catalog price والسياسات والserviceability والخصومات المسموحة، بينما WLT يملك أي حقيقة مالية أو التزام أو funding أو rounding policy مالية. كل amount يحمل currency وminor-unit semantics وsource/version، ولا تحسب الواجهات الرسوم أو الضرائب أو الإجمالي.

## تشخيص الحالة الحالية

### الموجود
- WLT financial sovereignty وformatter موحد `wlt-money`.
- Checkout وdelivery pricing وcoupon/loyalty capabilities ضمن المستودع.

### الناقص
- quote schema جامع: lines، subtotal، delivery، service، tax، discount، rounding، total، funding refs، expires_at.
- ownership matrix لكل amount.
- rounding/order-of-operations policy مثبتة.
- quote version pinned للسلة والCheckout والOrder.
- partner/client/operator presentation parity.
- reconciliation بين quote والledger/payment session.

### الخاطئ أو الممنوع
- `/100` أو digits ثابتة في UI.
- حساب total من line amounts داخل frontend.
- ضريبة أو رسم hardcoded في DSH إذا كان WLT مالكها.
- اختلاف currency/rounding بين surfaces.
- تعديل quote بعد إنشاء Order دون transition/adjustment محكوم.

### التصحيح المطلوب
- central pricing orchestration بحدود DSH/WLT صريحة.
- استخدام generated money types وformatter واحد.
- إزالة جميع financial constants/calculations المحلية.
- quote hash/version وexpiry وإعادة حساب ذرية.
- reason/source لكل adjustment.

### الإضافات المطلوبة
- Control Panel quote inspector.
- Partner breakdown المسموح دون كشف funding سري.
- test vectors متعددة العملات والحدود.

## منطق التشغيل

- DSH يجمع inputs غير المالية ويطلب من WLT القرارات المالية اللازمة.
- quote immutable بعد الإصدار حتى expiry؛ reprice ينتج version جديدة وdiff.
- Checkout يتطلب قبول explicit إذا تغير total بما يتجاوز السياسة.
- Order يحفظ snapshot ومراجع WLT؛ لا يعاد حساب التاريخ من السياسات الحالية.
- cancellation/refund تستخدم snapshot والمراجع لا UI totals.

## App Client

- breakdown واضح: items، fees، discounts، tax، total، currency، expiry/price changed.
- controls: `عرض التفاصيل`، `تطبيق/إزالة قسيمة`، `قبول السعر الجديد`، `إعادة المحاولة`.
- لا يمكن Edit amount.
- states: calculating، quote expired، price changed، funding unavailable، unsupported currency، unknown result.

## App Partner

- يرى item/partner-relevant breakdown وnet implication عبر facade المسموح.
- لا يرى customer wallet أو funding source.
- disputes تفتح workflow ولا تغير quote.

## العقود والبيانات

- Money type: integer minor units + ISO currency.
- quote rows/version/hash، adjustment rows، source refs.
- WLT request id/idempotency/correlation.
- contract errors: `QUOTE_EXPIRED`, `PRICE_CHANGED`, `CURRENCY_MISMATCH`, `FUNDING_UNAVAILABLE`, `ROUNDING_POLICY_ERROR`.
- no floating-point persistence.

## الاختبارات الآلية

- currency fraction digits including YER and zero/three-decimal currencies if supported.
- negative/overflow/floating input rejection.
- rounding order vectors.
- coupon/loyalty/funding combinations.
- quote expiry/reprice/acceptance.
- WLT timeout/unknown result/idempotency.
- surface parity snapshots.
- scan for hardcoded rates/division.
- section owner/control parity.

## التجريب اليدوي

1. أنشئ Cart بعدة items/options.
2. طبق قسيمة وميزة ولاء حسب السياسات.
3. غيّر سعر item أو fee بعد quote.
4. تحقق من price-change confirmation في Operations/App Client.
5. عطّل WLT بعد commit لمحاكاة unknown result.
6. قارن Finance/Partners/Marketing/Analytics وWLT refs.
7. اختبر currencies والحدود المعتمدة.

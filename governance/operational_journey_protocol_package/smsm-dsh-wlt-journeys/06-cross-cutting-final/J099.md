## النتيجة التشغيلية النهائية

Cache وSearch وRead Models مشتقة وقابلة لإعادة البناء، ومفاتيحها تشمل actor/scope/version/context المؤثر. كل تغيير حاكم يطلق invalidation أو reconciliation، ويظهر stale state بوضوح. لا تتحول cache أو index إلى مصدر حقيقة أو قناة تسريب بين النطاقات.

## التشخيص

### الموجود
- caches وsearch projections وHome/catalog/order workboards في عدة أسطح.

### الناقص
- registry لكل cache/index: source، key، TTL، invalidation، rebuild، sensitivity.
- قياس lag وparity واختبارات cross-scope leakage.

### الخاطئ
- key بلا actor/partner/store/version، fallback دائم، stale financial state، index لا يحذف المنشور المتوقف، local cache تمنح authorization.

### التصحيح
- typed cache registry، versioned keys، event invalidation + reconciliation، stale envelopes، rebuild runbooks.

## متطلبات التطبيقات

- cache محلية partitioned by actor وتُمسح عند logout/account switch.
- Offline data تحمل version/timestamp ولا تمنح mutation حساسة.
- App Client لا يعرض phantom stores/items؛ Partner/Field لا يرسلان stale privileged commands؛ Captain لا يرى offer منتهية.

## التقنية والاختبارات

- cache key contract وTTL/invalidation/rebuild لكل entry.
- search indexes لا تحتوي PII غير لازمة.
- tests: cross-actor/partner bleed، stale authorization، event loss، duplicate invalidation، rebuild parity، pagination بعد reindex، WLT projection freshness.
- manual: تغيير مصدر الحقيقة لكل قسم، التحقق من كل Surface، تعطيل event ثم reconciliation وإثبات parity.

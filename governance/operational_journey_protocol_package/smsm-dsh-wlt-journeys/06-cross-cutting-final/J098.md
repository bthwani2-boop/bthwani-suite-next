## النتيجة التشغيلية النهائية

كل Job لها owner وpayload contract وdedupe key وschedule/trigger وretry classification وtimeout وlease وdead-letter policy وrecovery runbook. لا Retry بلا حدود، ولا زر إعادة تشغيل يتجاوز idempotency أو الحالة الحالية.

## تشخيص الحالة الحالية

- **الموجود:** jobs للمهاجرات والإشعارات والمصالحة والإسقاطات والتنظيف.
- **الناقص:** registry موحد، budgets، lease semantics، poison policy، visibility لكل domain.
- **الخاطئ:** cron مكرر، retry لكل خطأ، payload حساس، DLQ بلا owner، manual run بلا dry-run.
- **التصحيح:** Job Registry وworker contracts وbackoff/jitter وdead-letter case وauthorized replay.

## قواعد التنفيذ

- payload references لا snapshots حساسة إلا عند الضرورة.
- lease/heartbeat يمنع عاملين من تنفيذ الأثر نفسه.
- retries فقط للأخطاء المؤقتة وبحدود.
- DLQ لها owner وSLA وتصنيف وإجراء إصلاح قبل replay.
- replay يستخدم original dedupe/correlation ويعيد التحقق من current state.

## الاختبارات

- crash before/after effect، duplicate scheduler، lease expiry، poison payload، retry exhaustion، clock skew، queue outage، DLQ replay بعد تغير الحالة.
- التجريب اليدوي لكل قسم: تعطيل العامل، مراقبة الحالة، إصلاح السبب، replay محكوم، إثبات عدم تكرار الأثر.

## النتيجة التشغيلية النهائية

كل حدث مطلوب يُكتب في Outbox داخل transaction نفسها مع حقيقة المجال، ويستهلك عبر Inbox/idempotency مع schema/version/ordering/lineage. replay يعيد projections دون duplicate effects، والpoison events مملوكة وقابلة للتشخيص، ولا توجد أحداث بلا مالك أو consumer effect غير مدقق.

## تشخيص الحالة الحالية

### الموجود
- outbox patterns في DSH/WLT وnotification/event consumers.
- projections متعددة للـorders/catalog/analytics/finance.

### الناقص
- event registry producer/owner/schema/version/consumers/ordering key.
- inbox standard وdedupe retention.
- replay ranges/checkpoints/compatibility.
- poison/dead-letter ownership.
- gap detection وprojection rebuild proof.

### الخاطئ أو الممنوع
- DB write ثم event خارج transaction.
- consumer side effect غير idempotent.
- schema change يكسر replay التاريخي.
- event order غير محدد لنفس aggregate.
- Control Panel replay بدون scope/confirmation/audit.

### التصحيح المطلوب
- event registry وعقود versioned.
- transactional outbox لكل producer.
- consumer inbox/dedupe/checkpoint.
- replay tooling with dry-run/limits.
- poison quarantine/DLQ owner.

### الإضافات المطلوبة
- lineage explorer.
- projection lag/gap dashboards.
- compatibility tests لكل event version.

## Control Panel

- Operations: event/outbox/inbox health وlag.
- Platform: registry/schema versions/owners.
- Analytics: projection checkpoints/rebuild state.
- Finance: WLT event lineage دون تعديل مالي.
- Support: incident link للpoison/gaps.
- Audit: replay actor/range/result.

## الاختبارات الآلية

- duplicate/out-of-order/missing event.
- crash before/after ack.
- schema evolution old/new consumer.
- replay range twice.
- poison payload.
- DB commit without outbox guard.
- projection rebuild parity.

## التجريب اليدوي

1. نفّذ mutations تنتج أحداثًا بكل المجالات.
2. أوقف consumer ثم أعده.
3. أعد إرسال event وغيّر ترتيبها.
4. أدخل poison event في بيئة اختبار.
5. نفّذ dry-run/replay من Control Panel.
6. راقب projections وAudit.

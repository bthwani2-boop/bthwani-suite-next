## النتيجة التشغيلية النهائية

كل رحلة وطلب وcommand وevent وjob لها trace/correlation وmetrics/logs/audit قابلة للربط، مع redaction وretention وfreshness. لوحة التحكم تعرض تشخيصًا موجّهًا للمالك ولا تتحول إلى مصدر حقيقة أو واجهة لعرض أسرار وPII.

## تشخيص الحالة الحالية

### الموجود

- health/readiness/logging/audit/metrics متفرقة وControl Panel diagnostics جزئية.

### الناقص

- telemetry contract موحد، SLO/SLI definitions، trace propagation، audit taxonomy، dashboard ownership، alert runbooks.

### الخاطئ

- raw tokens/PII في logs، metrics بلا scope، dashboards بلا freshness، audit mutable، correlation مفقود، alert بلا owner.

### التصحيح

- OpenTelemetry-compatible context، structured logs، metrics registry، append-only audit، redaction tests، runbooks وروابط source evidence.

## معايير التدقيق

- audit append-only: actor/service/action/object/before-after refs/reason/result/time/correlation.
- الكشف الحساس يسجل purpose ومدة وصلاحية.
- logs لا تحمل payloads مالية أو عناوين/هواتف خام إلا ضرورة مع masking.
- alerts لها owner/severity/runbook/dedupe/silence policy.

## الاختبارات الآلية

- trace propagation HTTP/event/job/provider، redaction scans، audit tamper attempts، metric cardinality، alert dedupe، clock skew، dashboard stale source.
- correlation completeness وappend-only audit وretention وfreshness contracts.

4. أسقط اعتمادًا ثم أعده وتحقق من Alert وRunbook وRecovery.

## النتيجة التشغيلية النهائية

كل Mutation حساسة تُنفذ مرة واحدة منطقيًا، وتملك `idempotency_key` و`payload_hash` و`operation_scope` ونتيجة محفوظة و`correlation_id` ووسيلة استعلام عند فقد الاستجابة. لا يعيد أي Surface الإرسال عميانيًا، ولا ينتج timeout بعد commit أثرًا مكررًا أو حالة مجهولة بلا recovery.

## تشخيص الحالة الحالية

### الموجود
- أنماط idempotency في Checkout/Orders/Partner/Field/WLT mutations.
- correlation وoutbox concepts ضمن الخدمات.

### الناقص
- registry شامل لكل mutation الحساسة.
- شكل موحد للمفتاح والـpayload hash والتعارض والretention.
- status lookup لكل operation.
- UI state موحد `PENDING | UNKNOWN | RESOLVED | CONFLICT`.
- قياس correlation gaps عبر الخدمات.

### الخاطئ أو الممنوع
- نفس المفتاح مع payload مختلف يُنفذ.
- retry من UI ينشئ key جديدًا دون lookup.
- operation حساسة بلا result store.
- correlation يتغير بين DSH/WLT/Provider.
- Control Panel يعرض زر Replay بلا معرفة هل العملية committed.

### التصحيح المطلوب
- mutation registry يحدد operation/owner/scope/key/hash/lookup/retention.
- middleware/domain support لا يحل محل uniqueness في DB.
- conflict ثابت عند different payload.
- readback endpoint أو lookup by source reference.
- frontend controller موحد للنتيجة المجهولة.

### الإضافات المطلوبة
- diagnostics للkeys/attempts/results.
- retention cleanup دون حذف evidence قبل المدة.
- fault-injection بعد commit.

## كل الأسطح

- زر mutation disabled أثناء الطلب.
- عند timeout تظهر `جارٍ التحقق من النتيجة` لا نجاح/فشل كاذب.
- `إعادة المحاولة` تعيد نفس key أو تنفذ lookup أولًا حسب العقد.
- conflict يعرض سببًا قابلًا للإصلاح.

## Control Panel — جميع الأقسام

- كل زر Create/Update/Delete/Approve/Reject/Replay/Retry/Confirm يملك operation ID مسجلًا.
- Operations/Support/Finance تعرض correlation وresult lookup.
- Audit يعرض key/hash/attempt/result دون payload حساس.
- لا قسم يملك mutation غير مدرجة في registry.

## العقود والبيانات

- idempotency records unique scoped key.
- payload hash canonicalization/version.
- stored status/result/error/reference.
- correlation/causation propagation.
- expiry/retention وcleanup auditable.

## الاختبارات الآلية

- same key same payload.
- same key different payload conflict.
- concurrent duplicate.
- timeout after commit.
- expired key policy.
- cross-service correlation propagation.
- every registered UI mutation has lookup/recovery.

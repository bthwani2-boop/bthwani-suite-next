## النتيجة التشغيلية النهائية

كل Mutation حساسة تُنفذ مرة واحدة منطقيًا، وتملك `operation_id` و`idempotency_key` و`payload_hash` و`scope` و`correlation_id` ونتيجة محفوظة ووسيلة Readback. فقد الاستجابة بعد Commit لا ينتج إعادة تنفيذ عمياء، ولا يسمح لأي Surface بعرض نجاح أو فشل غير مثبت.

## تشخيص الحالة الحالية

### الموجود المثبت
- توجد أنماط idempotency وcorrelation في أجزاء من Checkout وOrders وWLT وعمليات التزويد.
- توجد Outbox ومراجع source/correlation في عدد من الخدمات.

### الناقص أو غير المثبت
- سجل مركزي لكل Mutation حساسة في التطبيقات ولوحة التحكم.
- سياسة موحدة لبناء المفتاح، canonical payload hash، retention، conflict، وstatus lookup.
- تطابق كل زر مع `operation_id` وعقد recovery.
- إثبات استمرار correlation عبر DSH → WLT → Provider → webhook/reconciliation.

### الخاطئ أو الممنوع
- إنشاء مفتاح جديد عند Retry لعملية قد تكون committed.
- قبول المفتاح نفسه مع payload مختلف.
- زر Replay أو Retry بلا Lookup أولًا.
- نجاح Optimistic في الواجهة قبل readback النهائي.
- فقد correlation عند الانتقال بين الخدمات أو jobs.

### التصحيح المطلوب
1. إنشاء Mutation Registry يربط كل عملية بمالكها ومسارها ومفتاحها ونتيجتها ومدة الاحتفاظ.
2. فرض uniqueness وpayload conflict في قاعدة البيانات، لا في middleware فقط.
3. توحيد حالات الواجهة: `PENDING | UNKNOWN_RESULT | RESOLVED | CONFLICT | FAILED_RETRYABLE | FAILED_FINAL`.
4. توفير GET/lookup لكل عملية حرجة.
5. إضافة fault injection بعد commit وقبل response.

### الإضافات المطلوبة
- شاشة تشخيص correlation/idempotency redacted.
- عدادات duplicate attempts وunknown-result age.
- cleanup jobs مدققة لا تحذف evidence قبل المدة.

## منطق التشغيل

`SUBMIT → PENDING → COMMITTED|REJECTED`; إذا فُقد الرد تنتقل الواجهة إلى `UNKNOWN_RESULT` ثم تستعلم بالمفتاح أو المرجع. `same key + same canonical payload` يعيد النتيجة نفسها؛ `same key + different payload` يعيد conflict ثابتًا. لا تُعاد العمليات غير الآمنة إلا وفق عقد العملية نفسه.

## متطلبات كل Surface

- كل زر Mutation يملك loading محليًا ويمنع double tap.
- عند timeout يظهر `نتحقق من النتيجة` مع action lookup، لا رسالة فشل نهائية.
- App Client/Partner/Captain/Field تحتفظ بالمفتاح الآمن فقط حتى resolution.
- queued offline commands لا تُعاد بعد انتهاء الصلاحية أو تغير version دون conflict.

## العقود والبيانات

- unique `(operation_id, scope, idempotency_key)`.
- canonical payload hash versioned.
- status/result/reference/error class وcreated/committed/expires timestamps.
- correlation/causation propagated في HTTP، events، jobs، providers.
- redaction يمنع payload أو secrets في لوحة التحكم والlogs.

## الاختبارات الآلية والتجريب اليدوي

- same key/same payload؛ same key/different payload؛ concurrent duplicate؛ response loss after commit؛ retry after expiry.
- E2E correlation عبر DSH/WLT/provider.
- تشغيل كل زر حرج في الأقسام الإحدى عشرة بنقر مزدوج وانقطاع شبكة وreadback.
- إثبات `duplicate_persisted_effects=0` من DB وevents وواجهات الأسطح.

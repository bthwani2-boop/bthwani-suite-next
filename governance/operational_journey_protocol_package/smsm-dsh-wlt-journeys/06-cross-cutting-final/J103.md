## النتيجة التشغيلية النهائية

كل رحلة تملك threat model واختبارات سلبية تغطي authn/authz/IDOR/injection/SSRF/file abuse/replay/rate limits/secrets/PII/encryption/retention/consent/deletion. لا P0/P1 مفتوحة ولا secret في repo/log/response، وكل طلب خصوصية قابل للتنفيذ والتدقيق.

## تشخيص الحالة الحالية

### الموجود
- CodeQL/guards/operator context/privacy/media tests.

### الناقص
- threat model لكل journey/control.
- negative matrix موحدة.
- rate-limit/brute-force policies.
- secret inventory/rotation.
- retention/consent/delete/export mapping.
- network boundary/SSRF controls.

### الخاطئ أو الممنوع
- الاعتماد على UI hiding.
- raw errors/stack/secrets.
- cross-scope object access.
- unvalidated URL/file/template/command input.
- privacy deletion يكسر ledger/audit أو يحذف أكثر من اللازم.

### التصحيح المطلوب
- threat/negative-test registry.
- centralized validation and secure defaults.
- network allowlists/egress policy.
- secret management/rotation.
- privacy workflows مع retention/legal obligations.

### الإضافات المطلوبة
- abuse monitoring وincident links.
- security headers/mobile storage checks.
- privacy request dashboard.

## جميع الأسطح

- secure storage/session، no secrets in bundle.
- object access revalidated.
- rate-limit/error messages آمنة.
- privacy controls واضحة.

## Control Panel

- كل section يختبر role/object/operator context.
- Platform يملك security/privacy policies عبر workflow.
- Audit وPrivacy dashboards منفصلة وصلاحياتها دقيقة.
- لا raw secret أو PII غير ضروري.

## الاختبارات الآلية

- auth bypass/IDOR.
- SQL/command/template injection.
- SSRF/path traversal/file abuse.
- replay/brute force/rate limits.
- secrets scan.
- privacy export/delete/retention/legal hold.
- headers/CORS/network boundaries.

## التجريب اليدوي

1. اختبر أدوارًا وسياقات مختلفة في كل Surface وقسم.
2. أرسل inputs هجومية وروابط وملفات.
3. اختبر brute force/replay.
4. نفّذ privacy export/delete/consent withdrawal.
5. راقب logs/responses/bundles.
6. نفّذ secret rotation في بيئة اختبار.
7. راجع threat evidence.

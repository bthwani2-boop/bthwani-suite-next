## النتيجة التشغيلية النهائية

يُعرّف لكل capability ما يمكن قراءته offline وما يمكن صفّه وما يجب رفضه. كل queue مشفرة ومحدودة ومرتبة وidempotent ولها expiry/base version. عند reconnect يعيد الخادم التفويض والتحقق ويعرض conflict/unknown-result بوضوح؛ لا تطبق privileged action قديمة.

## تشخيص الحالة الحالية

### الموجود
- mobile apps وoffline use cases للسلة والتنفيذ والزيارات وCOD.

### الناقص
- offline capability matrix.
- queue schemas/encryption/retention.
- conflict resolution per journey.
- permission/assignment/state revocation behavior.
- device clock skew handling.
- diagnostics للpending/rejected commands.

### الخاطئ أو الممنوع
- optimistic success دائم.
- replay بعد إلغاء assignment أو سحب permission.
- queue غير مشفرة أو تحتوي PII زائد.
- ترتيب commands غير محدد.
- تطبيق command بعد expiry أو base version قديمة.

### التصحيح المطلوب
- registry لكل offline operation.
- common queue envelope وidempotency.
- reconnect protocol/readback/conflict UI.
- bounded retries وmanual resolution.
- إزالة unsupported offline writes.

### الإضافات المطلوبة
- sync diagnostics في Control Panel.
- user-visible pending/conflict center.
- lost-device queue revocation.

## التطبيقات

- Client: cart/preferences/support drafts فقط وفق matrix.
- Partner: inventory/order actions حسب المخاطر.
- Captain: execution/location/PoD/COD وفق قواعد صارمة.
- Field: visits/evidence/tasks.
- كل تطبيق يعرض pending/rejected/conflict/expired/readback.

## Control Panel

- Operations: pending/rejected execution actions.
- Support: failed message/attachment queues.
- HR: Field/Captain sync readiness.
- Partners/Stores: partner inventory/order sync.
- Audit: replay/resolve decisions.

## الاختبارات الآلية

- long offline وqueue expiry.
- permission revoked/assignment changed.
- duplicate reconnect.
- device clock skew.
- wrong Actor login بعد queue.
- lost device/revocation.
- unknown result after commit.
- unsupported operation rejected.

## التجريب اليدوي

1. نفّذ offline scenarios لكل تطبيق.
2. غيّر state/permission من Control Panel قبل reconnect.
3. بدّل الحساب على الجهاز.
4. اترك queue تنتهي.
5. افصل الشبكة بعد commit.
6. حل conflicts يدويًا.
7. راجع diagnostics/audit.

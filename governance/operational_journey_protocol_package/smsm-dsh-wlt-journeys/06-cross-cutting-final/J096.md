## النتيجة التشغيلية النهائية

كل قراءة أو Mutation تطبق Authentication وPermission وObject Scope وcurrent-state preconditions داخل transaction أو query الحاكمة. لا تصبح IDs أو selectors أو headers القادمة من الواجهة مصدر سلطة، ولا تسمح نافذة TOCTOU بتغيير object/assignment/state بين الفحص والكتابة. هويات الخدمات محددة الغرض وأقل صلاحية.

## تشخيص الحالة الحالية

### الموجود المثبت

- Identity وpermission vocabulary وoperator context وservice identities موجودة.
- توجد object authorization وscope concepts في DSH وWLT وWorkforce.

### الناقص

- مصفوفة operation → permission → object predicate → transaction recheck.
- جرد كل service credential وaudience والعمليات المسموحة.
- negative matrix لكل Route وزر وdeep link/export/search.
- cache invalidation عند revoke أو scope change.

### الخاطئ أو الممنوع

- الثقة في `partnerId/storeId/actorId` أو role من request/local storage.
- فحص permission قبل transaction ثم الكتابة بعد تغير الحالة.
- إخفاء الزر فقط مع endpoint قابل للاستدعاء.
- service token عام أو wildcard.
- export/search بلا scope predicate.

### التصحيح والإضافات

- Trusted Context Resolver لكل خدمة.
- repository predicates إلزامية وإعادة فحص داخل transaction.
- service identity registry مع owner/audience/operations/rotation.
- IDOR/TOCTOU suite وcache versioning.

## متطلبات التطبيقات

- selectors تعرض scopes القادمة من الخادم ولا تمنحها.
- queued offline commands يعاد تفويضها عند reconnect.
- عند revoke أثناء session تزال controls وتُرفض API مباشرة.
- لا يوجد fallback header أو local role map.

## التقنية والبيانات

- subject/audience/service identity من token أو credential موثوق.
- object authorization داخل SQL/repository، لا filtering بعد القراءة.
- optimistic version أو row lock مع recheck.
- caches/search keys تشمل scope/version.
- audit يسجل subject/service/purpose/permission/object/result.

## الاختبارات الآلية

- IDOR عبر path/query/body، forged headers، stale assignment، revoke أثناء transaction، service credential زائد، export leakage.
- TOCTOU بين permission check وtransaction write، مع row lock أو version conflict.
- فحص كل operation مسجلة ضد permission وobject predicate وservice audience.

## التجريب اليدوي

1. اختبر كل زر حساس في الأقسام الإحدى عشرة بحساب بلا صلاحية، وبصلاحية عامة دون Object Scope، وبصلاحية صحيحة.
2. غيّر assignment أو state بعد فتح Dialog وقبل Confirm وتحقق من الرفض وعدم الكتابة.
3. بدّل IDs في Route وQuery وBody وExport وتحقق من عدم تسريب بيانات أو counts.
4. ألغِ permission أثناء جلسة مفتوحة وتحقق من اختفاء التحكم ورفض Backend فورًا.

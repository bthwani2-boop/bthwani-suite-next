## النتيجة التشغيلية النهائية

يُفحص Actor/Role/Permission/Object ownership/Operator Context/Service Identity ثم تُنفذ الكتابة في نفس boundary الذرية عندما يمكن أن تتغير الحقيقة بين الفحص والكتابة. لا يمنح client identifier سلطة، ولا service identity مفرطة الصلاحيات، ولا delegation قابلة لإعادة الاستخدام خارج الغرض والمدة.

## تشخيص الحالة الحالية

### الموجود
- Identity permissions/scope vocabulary وoperator context isolation.
- object authorization tests في DSH/WLT/Workforce.

### الناقص
- authorization matrix لكل command/object/state.
- TOCTOU threat list للownership/role/state/balance/assignment.
- service identity inventory/minimal scopes/rotation.
- delegation schema/purpose/expiry/replay protection.
- atomic negative tests تحت concurrency.

### الخاطئ أو الممنوع
- check permission ثم write في transaction منفصلة مع stale state.
- الثقة في actor/store/order IDs من client.
- service account شامل لكل scopes.
- headers قابلة للتزوير من public boundary.
- تغيير ownership أو revocation لا يؤثر على command الجاري.

### التصحيح المطلوب
- policy enforcement داخل domain transaction/lock/version predicate.
- trusted service-auth boundary مع audience/issuer/scope.
- object predicates server-derived.
- delegation single-purpose/single-use أو bounded.
- إزالة fallback auth/legacy headers.

### الإضافات المطلوبة
- service identity registry وowner/rotation.
- authorization decision audit.
- TOCTOU concurrency test harness.

## جميع الأسطح

- لا تحمل service credentials.
- hidden/disabled controls لا تعتبر حماية؛ backend يرفض دائمًا.
- permission revoked أثناء الشاشة ينتج reauthorization/readback.

## Control Panel — جميع الأقسام

- كل section/action يربط permission + object predicate + operator context.
- Partners/HR/Operations/Finance تمنع cross-context reads/writes.
- Platform يغير policies عبر workflow لا bypass.
- Audit يعرض القرار والسبب دون secrets.

## الاختبارات الآلية

- concurrent revoke أثناء write.
- ownership/store transfer أثناء command.
- stale object version.
- forged service headers/audience/scope.
- replayed delegation.
- cross-operator-context access.
- overprivileged service identity scan.

## التجريب اليدوي

1. افتح mutation ثم اسحب role قبل التأكيد.
2. انقل store/assignment/ownership بالتزامن.
3. استخدم IDs من Actor آخر.
4. حاول استدعاء internal route من تطبيق.
5. اختبر كل قسم Control Panel بدور ناقص وبسياق آخر.
6. راجع authorization audit.

## النتيجة التشغيلية النهائية

Media يملك upload/storage/hash/scan/quarantine/derivatives/URL/retention/deletion، بينما كل Domain يملك رابط الأصل وغرضه وترتيبه وحالته التشغيلية. لا Blob داخل DSH/WLT، ولا URL دائم غير محكوم، ولا ملف نشط قبل الفحص، ولا orphan أو كشف خارج الغرض والصلاحية.

## تشخيص الحالة الحالية

### الموجود
- Media runtime وobject storage ومسارات رفع وعرض في الكتالوجات والملفات والدعم والإثباتات.

### الناقص
- lifecycle موحد، ownership/link registry، scan policy، signed URL policy، cleanup/reconciliation، purpose-based authorization.

### الخاطئ أو الممنوع
- Base64 أو paths محلية في العقود، MIME موثوق من العميل، public permanent URL، active-before-scan، حذف ملف يكسر evidence، reuse بين Actors بلا تفويض.

### التصحيح والإضافات
- upload intent/complete/scan/link/unlink/expire/delete contracts.
- content sniffing وsize limits وmalware scan وhash/dedup.
- link constraints وretention holds وderivative provenance.
- manual recovery للuploads المعلقة وorphan reports.

## متطلبات التطبيقات

- Progress/resume/cancel واضح؛ النجاح بعد `complete + scan` فقط.
- Offline draft يحمل local handle مؤقتًا ولا يصبح authoritative link.
- broken/expired URL يعاد طلبها ولا تُخزن دائمًا.
- alt text/captions/accessibility لكل وسائط العرض.

## التقنية والبيانات

- upload intents قصيرة العمر ومحددة owner/purpose/type/size.
- asset lifecycle: `PENDING_UPLOAD → UPLOADED → SCANNING → ACTIVE|QUARANTINED|REJECTED → EXPIRED|DELETED`.
- domain links unique ومؤرخة؛ retention hold يمنع الحذف غير الآمن.
- signed delivery، redacted logs، orphan cleanup/reconciliation.

## الاختبارات والتجريب

- MIME spoof، zip bomb، oversized، interrupted/duplicate upload، cross-owner link، scan timeout، delete while referenced، expired URL، provider outage.
- اختبار كل تبويب وزر في الأقسام المذكورة مع حالات loading/empty/error/forbidden/stale/unknown-result.

# SMSM DSH/WLT Multi-Surface Journey Package

هذه الحزمة هي نقطة التخطيط والتنفيذ التشخيصي الوحيدة لرحلات DSH وما يرتبط بها في WLT على فرع `smsm`.

## الفرق الحاكم

- **الرحلة Journey:** نتيجة تشغيلية كاملة تبدأ من حاجة Actor، وتمر بالهوية والصلاحيات والعقد والباك إند والبيانات والتكاملات والأسطح والتعافي، وتنتهي بحقيقة محفوظة وقراءة راجعة.
- **الشريحة Slice:** جزء رأسي داخل الرحلة يثبت طبقة أو خطرًا محددًا؛ لا تمثل رحلة مستقلة ولا تغلق الرحلة منفردة.
- **التحكم Control:** زر أو أيقونة أو تبويب أو نموذج أو رابط أو فلتر أو Pagination؛ يجب ربطه برحلة وشريحة وأثر حقيقي.
- **الدليل Evidence:** نتيجة قابلة لإعادة التشغيل من SHA واحد؛ وجود ملف أو شاشة ليس دليل إغلاق.

## ما يجب أن يحتويه كل ملف رحلة

1. النتيجة والمنطق التشغيلي من البداية للنهاية.
2. الموجود المثبت مع المسارات والرموز والأدلة.
3. الناقص والخاطئ والمتعارض والسبب الجذري.
4. ما يجب تصحيحه وحذفه ونقله وإضافته.
5. مصفوفة مستقلة لكل Surface من الصفحات والتبويبات والأزرار والأيقونات والنماذج والحالات.
6. العقود والعملاء والباك إند وقاعدة البيانات والأحداث والتكاملات.
7. state machine والانتقالات الصحيحة والممنوعة.
8. اختبارات آلية وسلبية وconcurrency/idempotency/offline/recovery.
9. Runbook تجريب يدوي يوضح ماذا ينقر وما يجب أن يظهر في كل Surface.
10. ترحيل وتنظيف ودليل Same-SHA وقرار صريح.

## قواعد التنفيذ

1. `FOUNDATION-00` و`COVERAGE-00` قبل الرحلات.
2. التنفيذ متدرج ومتسلسل حسب السجل.
3. داخل كل رحلة تنفذ `SL-01..SL-24` بقدر الانطباق؛ ولا يسجل عدم الانطباق بلا سبب ودليل.
4. لا تفتح رحلة لاحقة قبل إغلاق تبعياتها أو إثبات مانع خارجي.
5. كل Surface وتحكم وحالة مرئية يجب أن تكون مصنفة ومربوطة.
6. كل رحلة تتضمن تجربة يدوية، اختبارات سلبية، Offline/Unknown Result، Runtime Readback، وتنظيف البقايا.
7. الحالة الافتراضية `NOT_ASSESSED`; وجود الملف لا يساوي تنفيذ الرحلة.
8. الحقول الفارغة أو `UNPROVEN` تمنع الإغلاق؛ لا تتحول تلقائيًا إلى PASS.
9. ملفات الرؤية النهائية للأسطح بوابة تجميعية بعد إغلاق الرحلات الفردية.

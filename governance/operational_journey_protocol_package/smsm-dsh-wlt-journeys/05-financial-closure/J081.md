## النتيجة التشغيلية النهائية

تمتلك WLT accounts/wallets، ويُشتق الرصيد من Ledger المصدق لا من عمود قابل للتعديل أو cache. كل Actor يرى الحسابات المسموحة فقط عبر DSH facade بقيم masked/freshness واضحة. لا توجد `set balance` أو local aggregation كحقيقة.

## تشخيص الحالة الحالية

### الموجود
- actor-wallet panels/APIs وfinance summaries.
- Ledger/account domain في WLT.

### الناقص
- account ownership/currency/type lifecycle.
- available/pending/held definitions.
- balance snapshot/checkpoint/rebuild rules.
- closed/suspended account behavior.
- cache TTL/freshness/read consistency.
- masking/reporting لكل Surface.

### الخاطئ أو الممنوع
- direct balance update.
- DSH يخزن raw balance كسلطة.
- frontend يجمع entries ويعرض total authoritative.
- cross-actor/account access.
- unsupported currency أو negative unexplained balance.

### التصحيح المطلوب
- account aggregate وimmutable currency/owner.
- balance query من ledger/checkpoint verified.
- DSH reference/cache قصيرة العمر مع stale marker فقط.
- remove balance columns/mutations/types المتوازية.
- object authorization لكل read.

### الإضافات المطلوبة
- account status/restriction reasons الآمنة.
- balance reconciliation diagnostics.
- multi-currency presentation policy.

## الأسطح

- App Client: wallet summary/transactions link وفق Product Truth.
- App Partner: commercial balance/available/pending/settlement refs.
- App Captain/Field: custody/commission/payout summaries المحدودة.
- Control Panel: masked account lookup، status، checkpoints، no set-balance control.
- كل سطح يعرض `as_of` وstale/unavailable.

## العقود والبيانات

- account owner/type/currency/status immutable or versioned.
- balance derives from posted entries; optional checkpoints verified.
- no mutable balance authority.
- scoped query and pagination.
- closed/suspended policies.

## الاختبارات الآلية

- cross-actor/account IDOR.
- concurrent entries/read consistency.
- stale cache 표시.
- closed/suspended account.
- unsupported currency.
- checkpoint rebuild vs ledger.
- direct mutation endpoint/SQL scan.

## التجريب اليدوي

1. أنشئ entries عبر رحلات مالية صحيحة.
2. قارن summaries على الأسطح مع Ledger.
3. افتح حساب Actor آخر.
4. أوقف/أغلق الحساب واختبر reads/mutations.
5. عطّل WLT واختبر stale marker.
6. أعد بناء checkpoint.
7. تحقق من عدم وجود set balance أو raw copies في DSH.

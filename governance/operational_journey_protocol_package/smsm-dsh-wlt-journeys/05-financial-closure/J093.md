## النتيجة التشغيلية النهائية

تقارن WLT Ledger مع provider records ومع operational evidence من DSH، وتفتح Reconciliation Case واحدة لكل فرق قابل للتعريف. الحل يتم بالمطابقة أو journaled adjustment أو accepted risk مع approval؛ لا حذف record أو تعديل التاريخ لإخفاء الفرق.

## تشخيص الحالة الحالية

### الموجود
- WLT reconciliation/operator context tests وDSH reconciliation panels.
- provider events وLedger وoperational refs.

### الناقص
- reconciliation source registry/frequencies/checkpoints.
- match keys/tolerances/timezone/currency rules.
- case lifecycle/ownership/SLA.
- adjustment approval/linkage.
- external blocker classification.
- partner-safe status/readback.

### الخاطئ أو الممنوع
- delete/update-to-match.
- فرق يختفي بسبب retry دون lineage.
- auto-adjustment بلا policy/approval.
- DSH يمتلك case المالية أو يغير Ledger.
- case unresolved بلا owner/SLA.

### التصحيح المطلوب
- reconciliation jobs idempotent/checkpointed.
- case `DETECTED | INVESTIGATING | MATCHED | ADJUSTMENT_REQUIRED | RESOLVED | ACCEPTED_RISK | BLOCKED_EXTERNAL`.
- evidence snapshots and lineage.
- adjustment via J082 journal command.
- no-delete guard/audit.

### الإضافات المطلوبة
- dashboards حسب source/provider/age/severity.
- external evidence request/workflow.
- automated safe matching مع explainability.

## Control Panel — جميع الأقسام المتأثرة

### المالية
- queue للفروقات، مقارنة Ledger/Provider/DSH evidence، adjustment workflow.

### التحليلات
- counts/age/severity/freshness دون اعتبارها truth بديلة.

### الشركاء
- masked case status داخل Partner Detail عند تأثيره عليه.

### العمليات
- روابط order/delivery/COD evidence فقط، دون تعديل مالي.

### الدعم
- طلب أدلة ومراسلات case مع فصل internal/public.

### التدقيق
- كل match/adjustment/accepted risk/resolve مسجل وغير قابل للحذف.

## الاختبارات الآلية

- missing/duplicate provider record.
- amount/currency/date mismatch.
- stale operational evidence.
- duplicate job/run/case.
- unauthorized resolve/adjustment.
- delete-to-resolve attempt.
- blocked external/late evidence.
- rebuild/replay.
- كل قسم Control Panel يعرض subset الصحيح ولا ينفذ action خارج ملكيته.

## التجريب اليدوي

1. ولّد missing/duplicate/mismatched provider records.
2. شغّل reconciliation أكثر من مرة.
3. طالب evidence من DSH/Partner.
4. طابق حالة سليمة وأنشئ adjustment لحالة أخرى.
5. حاول الحذف/التعديل أو resolve بلا approval.
6. افتح Finance/Analytics/Partners/Operations/Support/Audit وتحقق من كل tab/action.
7. اختبر external blocker وlate record.
8. راجع lineage/Ledger/status.

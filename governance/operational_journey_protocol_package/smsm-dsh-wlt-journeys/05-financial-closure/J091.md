## النتيجة التشغيلية النهائية

تملك WLT بيانات Payout Destination الحساسة ودورة تحققها وتشفيرها وإخفاءها. يحتفظ DSH فقط بـdestination ID والقيمة masked والحالة اللازمة للعرض. لا raw bank/IBAN/mobile wallet details في DSH أو frontend state أو logs، ولا يُصرف إلى وجهة غير verified.

## تشخيص الحالة الحالية

### الموجود
- WLT payout destination contracts/panels.
- DSH facade وmasking policy.
- migration أسقطت raw bank columns من DSH.

### الناقص
- destination type schemas/validation/provider verification.
- lifecycle `DRAFT | PENDING_VERIFICATION | VERIFIED | REJECTED | SUSPENDED | DELETED`.
- change/reverify/cooldown/security notifications.
- duplicate detection دون كشف raw data.
- access audit وsecret rotation.
- fallback عند provider unavailable.

### الخاطئ أو الممنوع
- raw destination persistence أو request logging في DSH.
- masked value تستخدم للتحويل.
- تغيير verified destination دون reverify/step-up auth.
- verification replay.
- Operator يكشف أو ينسخ raw value.

### التصحيح المطلوب
- WLT secure destination aggregate/encryption.
- tokenized/provider reference إن أمكن.
- step-up auth/approval حسب actor/risk.
- DSH facade returns masked/status only.
- scan/remove raw fields/types/fixtures/logs.

### الإضافات المطلوبة
- security notification عند create/change/delete.
- verification attempt/lockout.
- Control Panel review مع separation of duties.

## App Partner / Captain / Field

- list masked destinations، add/edit/delete، initiate verify، set default حسب policy.
- sensitive entry ينتقل إلى WLT-secured flow عبر DSH facade contract دون تخزين محلي غير آمن.
- states pending/rejected/suspended/verified، reason آمن.
- لا copy raw value بعد save.

## Control Panel — جميع الأقسام المتأثرة

### المالية
- قائمة الوجهات، النوع، المالك، masked value، verification state، آخر تغيير، audit.
- أزرار `مراجعة`، `طلب إعادة تحقق`، `تعليق`، `حذف منطقي`، وكلها بصلاحيات منفصلة.

### الشركاء
- داخل Partner Detail يظهر summary masked وروابط مالية فقط، دون raw fields.

### الموارد البشرية
- للكابتن/الميداني يظهر وجود وجهة verified أو missing كحالة جاهزية فقط، دون البيانات الحساسة.

### العمليات
- يظهر blocker إذا payout متوقف بسبب destination، دون إتاحة تعديلها من العمليات.

### التدقيق
- كل كشف أو تعديل أو تحقق أو رفض مسجل مع actor/سبب/وقت.

## العقود والبيانات

- encrypted fields/provider token داخل WLT.
- hash/fingerprint للduplicate detection.
- verification challenges single-use/expiry.
- owner/context/object auth.
- DSH stores reference/masked/status only.

## الاختبارات الآلية

- raw data in DSH DB/logs/env/frontend cache.
- duplicate destination.
- unauthorized create/change/read.
- verification replay/expiry/brute force.
- destination change during payout.
- encryption/key rotation.
- cross-actor IDOR.
- كل أقسام Control Panel تستخدم masked facade فقط.

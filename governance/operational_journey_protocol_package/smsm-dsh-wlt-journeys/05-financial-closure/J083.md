## النتيجة التشغيلية النهائية

ينشئ WLT سجل COD ماليًا واحدًا لكل obligation مستحقة اعتمادًا على Order/Delivery evidence مثبتة من DSH. يملك WLT amount/currency/status، بينما يحتفظ DSH بمراجع الحالة التشغيلية فقط. لا duplicate COD record أو amount محلي أو record بلا دليل.

## تشخيص الحالة الحالية

### الموجود
- WLT COD domain/routes وDSH COD finance handlers.
- delivery completion evidence من J067.

### الناقص
- trigger/evidence contract لإنشاء COD.
- uniqueness/order/currency/amount pinning.
- lifecycle `EXPECTED | COLLECTED | IN_CUSTODY | HANDED_OVER | RECONCILED | SHORT | OVER | DISPUTED`.
- late/duplicate/cancelled delivery event handling.
- DSH readback/projection freshness.

### الخاطئ أو الممنوع
- amount يأتي من App Captain أو Partner.
- record مكرر عند event replay.
- COD created لPayment method غير COD أو Order ملغاة.
- DSH يخزن amount/status كحقيقة ثانية.
- تغيير amount الأصلي بعد الإنشاء بلا adjustment.

### التصحيح المطلوب
- WLT command idempotent من immutable order evidence.
- unique source/order obligation constraint.
- pinned amount/currency/quote/order refs.
- state machine وLedger linkage.
- facade readback فقط في DSH.

### الإضافات المطلوبة
- COD record inspector/reconciliation links.
- mismatch/dispute workflow.
- event replay diagnostics.

## App Captain

- يرى expected amount/status عبر facade فقط وفي الوقت المسموح.
- لا يستطيع تعديل amount؛ controls للتحصيل/التسليم في J084.
- stale/unavailable واضح.

## App Partner / App Field

- يرى obligations ضمن scope والحيازة فقط.
- لا raw ledger أو actor آخر.

## Control Panel

- search by order/record/actor، evidence، amount/currency، lifecycle، ledger refs.
- controls open custody/reconciliation/dispute؛ no edit amount.

## العقود والبيانات

- COD record unique source reference.
- immutable principal amount/currency.
- status transitions versioned.
- ledger journal refs.
- DSH projection reference/expiry.

## الاختبارات الآلية

- duplicate delivery event.
- wrong payment method/order/currency.
- amount mismatch/tampering.
- late event after cancellation.
- concurrent creation.
- DSH projection stale/rebuild.
- cross-actor read.

## التجريب اليدوي

1. أكمل COD Order وأنشئ record.
2. أعد event عدة مرات.
3. جرّب Order إلكترونية/ملغاة/amount معدلًا.
4. افصل WLT ثم أعد event.
5. تحقق من الأسطح وControl Panel.
6. قارن record مع Order snapshot وLedger.
7. اختبر scope والـmasking.

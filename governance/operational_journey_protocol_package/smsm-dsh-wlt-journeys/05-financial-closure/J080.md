## النتيجة التشغيلية النهائية

تملك WLT Payment Session وحقيقة provider من الإنشاء حتى authorization/capture/failure/cancel/expiry/reconciliation. DSH يحتفظ بالreference والحالة المقروءة فقط ويربطها بالCheckout/Order. لا duplicate charge ولا ثقة بcallback من العميل ولا أسرار provider خارج WLT.

## تشخيص الحالة الحالية

### الموجود
- payment session capabilities وproviders simulators/contracts.
- DSH checkout handoff وControl Panel payment operations.

### الناقص
- lifecycle/transition table كاملة وprovider mapping.
- amount/currency/order binding immutable.
- webhook signature/replay/order handling.
- late success بعد timeout وunknown reconciliation.
- authorization/capture split policy.
- masking/retention/PCI boundary.

### الخاطئ أو الممنوع
- تعديل amount من client أو DSH بعد session.
- capture مكرر.
- success من redirect/callback client وحده.
- raw token/card/provider credential في DSH/logs.
- provider status يكتب مباشرة في Order دون WLT validation.

### التصحيح المطلوب
- WLT payment aggregate/state machine.
- provider adapter registry وsigned callbacks.
- idempotent authorize/capture/cancel/refund references.
- reconciliation worker وstatus lookup.
- generated facade presentation.

### الإضافات المطلوبة
- provider event timeline.
- operations queue للunknown/pending long-running.
- simulator cases لكل provider outcome.

## App Client

- next action/redirect/SDK وفق session response.
- states created/requires action/processing/succeeded/failed/expired/unknown.
- controls continue/cancel/verify/retry with new session فقط حسب policy.
- لا يعرض success قبل WLT readback.

## App Partner

- payment readiness/status masked على Order.
- لا method details أو provider identifiers حساسة.

## Control Panel

- session search، amount/currency/order ref، provider events masked، attempts، reconciliation.
- controls verify/cancel/capture إذا policy وصلاحية، no force success.

## العقود والبيانات

- session immutable amount/currency/source.
- provider event unique IDs/signatures/timestamps.
- transition version وidempotency keys.
- encrypted secrets داخل WLT فقط.
- ledger posting links من J082.

## الاختبارات الآلية

- tampered amount/currency/order.
- duplicate capture/authorize.
- webhook replay/invalid signature/out-of-order.
- timeout ثم late success.
- client callback spoof.
- provider duplicate event.
- raw secret scan.
- DSH order readback parity.

## التجريب اليدوي

1. نفّذ success/failure/cancel/expiry عبر simulator.
2. غيّر payload amount أو order ref.
3. أعد webhook وغيّر ترتيبه وتوقيعه.
4. اقطع الاتصال قبل provider success ثم أرسل late event.
5. اضغط capture مرتين.
6. راقب Client/Partner/Control Panel وWLT timeline.
7. افحص logs/DB/DSH references فقط.

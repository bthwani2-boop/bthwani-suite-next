## النتيجة التشغيلية النهائية

تملك WLT Payment Session وحقيقة Provider من create إلى authorize/capture/fail/cancel/expire/reconcile. DSH يحتفظ بالمرجع والقراءة فقط. لا duplicate charge أو client callback authority أو secrets خارج WLT.

## التشخيص

- **الموجود:** payment sessions/provider simulators/checkout handoff.
- **الناقص:** full lifecycle mapping، immutable amount/order binding، signed webhooks، late result reconciliation، auth/capture policy، PCI boundary.
- **الخاطئ:** tampered amount، double capture، redirect success كحقيقة، raw provider token، direct Order status write.
- **التصحيح:** WLT aggregate، provider adapter registry، idempotent commands، signed/replay-safe events، reconciliation worker.
- **الإضافة:** provider timeline، unknown queue، simulator vectors.
